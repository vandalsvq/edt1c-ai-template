# План: документация форм PrintWizard для ассистента

> Рабочий документ для нарезки задач в продолжение pw-210/pw-225/pw-226.
> После согласования из этого плана выделяются отдельные GitHub-issues и
> спеки `specs/pw-XXX/`.

## Контекст

В pw-225 принята методология (8-секционный шаблон документа формы для LLM, инструменты `PW_GetDocs` / `PW_SearchDocs`). В pw-226 пилот доведён до кондиции на главной форме `pw_Макеты/ФормаЭлемента` (Редактор макетов).

Осталось 53 формы. Цель — покрыть формы, реально влияющие на пользовательский опыт, не пытаясь объять всё подряд.

## Принципы группировки

- Один markdown-документ может покрывать **несколько мелких форм**, если они являются звеньями одного сценария или однотипны (например, диалоги «Конструктор *»). В bundle такой документ разбивается на отдельные topics по H2-заголовкам, каждая форма получит свой topic.
- **Главные формы** (Редактор макетов, Конструктор форм, Пакетная печать) описываются отдельным документом каждая.
- **Служебные формы** (P5) — допустимо описывать одной строкой в общем документе или вообще пропустить.

## Зависимости

- Задачи 1–4 должны идти после pw-226 (методология устоялась, базовый документ опубликован).
- Задачи 2–4 разумно делать после или параллельно с задачей 1, поскольку часть конструкторов вызывается также из формы конструктора кнопки печати.
- Задача 4 («Алгоритмы и доступные поля») пересекается с упомянутой в pw-226 «отдельной задачей по подсказкам в полях алгоритмов» — стоит объединить или явно связать.
- Задачи 5–8 независимы между собой и могут идти в произвольном порядке.

## Шаблон процесса (зафиксирован в pw-225/226)

Для каждой задачи:

1. Создать issue, ветку `feature/pw-XXX` от `develop`.
2. Спека: `specs/pw-XXX/spec.md` + `plan.md` по шаблонам.
3. **Инвентаризация форм без участия владельца** (страницы, элементы, команды, обработчики из `Form.form` + `Module.bsl`).
4. **Батчи интервью** с владельцем — по группам элементов (4–6 батчей на форму, в зависимости от размера).
5. **Сборка документа** в `pw_public/docs/llm/<имя>.md` по 8-секционному шаблону.
6. **Синонимы**: внутренние имена формы — из `<title>` элементов; значения перечислений — из `pw_Перечисления`. Стратегия — «синоним | внутреннее имя | назначение» (А по pw-226).
7. **Регенерация bundle**: `python3 tools/docs-llm/build.py` из корня `pw_public`.
8. **Метрика**: 8–10 контрольных вопросов через ассистента.
9. Коммит в `pw_public`, PR в `pw_edt`, перенос спеки в `specs/done/pw-XXX/`.

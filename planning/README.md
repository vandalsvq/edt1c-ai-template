# Planning

Каталог для **рабочих планов и груминга бэклога**, которые ещё не оформились в спеки.

В отличие от `specs/`, документы здесь **транзиентны**: их назначение — собрать контекст, сделать первичную нарезку задач и затем породить отдельные issue + спеки в `specs/<prefix>-<N>/`. После этого черновой план можно либо удалить, либо оставить как историческую справку.

## Когда писать в planning, а когда — сразу в specs

| Если у вас… | → пишите |
| --- | --- |
| Зонтичная инициатива, которую ещё нужно нарезать на 5–20 issue | `planning/<тема>.md` |
| Груминг бэклога / приоритизация milestone | `planning/grooming-<milestone>.md` |
| Реестр чего-то поверх кода (например, форм с документацией) | `planning/<реестр>.md` |
| Конкретная фича/баг с issue → код | сразу `specs/<prefix>-<N>/` |
| Ретро-описание уже работающей подсистемы | `specs/retro/<подсистема>.md` |

## Структура файла плана

Свободная — это рабочий документ, а не контракт. Полезно держать:

1. **Контекст** — зачем этот план, какие issue/спеки уже закрыты по теме.
2. **Перечень кандидатов** — таблица «компонент / размер / статус / комментарий».
3. **Группировка и приоритизация** — что объединяем в одну задачу, что откладываем, что вне области.
4. **Открытые вопросы** — то, что нужно решить до создания issue.

## Примеры

В каталоге [`examples/`](examples/) лежат два реальных плана из проекта PrintWizard — для понимания формата и масштаба:

- [`examples/grooming-milestone.md`](examples/grooming-milestone.md) — груминг бэклога одного milestone: какие issue открыты, какие закрыты, в каком порядке брать, что переносим в следующий milestone.
- [`examples/документация-форм.md`](examples/документация-форм.md) — план зонтичной инициативы (документация форм для LLM): полный реестр форм с размерами и приоритетами, разбиение на батчи задач.

Эти файлы — **не часть текущего проекта**, они показывают формат. Удалите их или замените своими, когда будете адаптировать шаблон.

Выполните [процедуру stage](../../../.claude/skills/stage/SKILL.md) из текущего рабочего дерева. Аргументы возьмите из запроса владельца.

Запускайте роли из [.codex/agents](../../../.codex/agents/) по условиям этапа. Выбирайте профиль по имени, если клиент это поддерживает. Иначе передайте обязанности из его TOML в брифе и укажите фактическую модель и ограничения запуска. Для свежей роли выберите пустую историю (при наличии параметра `fork_turns="none"`). Укажите рабочий каталог, ветку и базовый коммит, критерии спеки, разрешённые файлы и адреса EDT, ожидаемый результат. Если владелец ограничил чтение пакетом, вложите нужные требования в бриф.

Ревьюер получает критерии и дифф без рассуждений автора. Для повторной проверки передайте номера исправлений тому же ревьюеру. Проверьте доступные ему права файловой системы и MCP. Если нужна техническая изоляция, запускайте его в сеансе только для чтения с читающими инструментами MCP без повышения прав. Если клиент ограничивает роль лишь инструкцией, сообщите об этом. Подготовку базы и проверки, требующие записи, проводит уполномоченный участник до независимого ревью.

В Codex исполнителю и тестировщику поручите явный запуск diff-check вместо хуков Claude. Состояние этапа передавайте через файлы плана и коммит. Для следующего этапа начните свежий чат. Замеры по журналам Claude и команду `/clear` используйте только в Claude Code.

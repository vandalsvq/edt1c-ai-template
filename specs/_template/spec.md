## 5. Критерии приёмки и способ проверки

Проверяемый чек-лист. У каждого пункта - способ проверки по лестнице из
[`docs/testability.md`](../../docs/testability.md), и только из тех ступеней,
что доступны в проекте (`CLAUDE.md` → «Тестирование»).

Если проверка требует владельца как оператора интерактивного цикла
(запустить форму, ввести данные, вернуть результат) - в область изменений
(§2) закладывается обвязка автономного прогона: сценарий → лончер → файл
результата. Функциональное тестирование аналитиком или тестировщиком -
штатный способ для видимого пользователю поведения. Ручная проверка
владельцем - только явно перечисленный остаток (визуальная оценка, UX), а
не способ по умолчанию.

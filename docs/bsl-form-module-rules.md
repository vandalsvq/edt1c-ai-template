# Правила модулей форм 1С

Структура модуля, клиент-серверное разделение, директивы компиляции и работа с данными формы.
Готовые приёмы (панель однотипных реквизитов, поле-пароль, подсказки, отметка состояния) -
раздел «Приёмы» ниже. Компоновка формы - граница с кодом и карта формы, имена, раскладка,
чем ставится свойство - [`form-layout-rules.md`](form-layout-rules.md): в цикле этапа форму
собирает верстальщик, а модуль пишется по его карте формы. Что должно получиться по
стандартам 1С (виды форм, раскладка, командные панели, поля, подсказки) -
[`bsl-form-design-8.3.md`](bsl-form-design-8.3.md) и
[`bsl-form-design-8.5.md`](bsl-form-design-8.5.md); образцы и отклонения проекта - в документе
форм проекта, если он ведётся.

## Структура модуля

По стандарту 1С [«Структура модуля» (std455)](https://its.1c.ru/db/v8std/content/455/hdoc). Области **первого уровня** и их порядок - строго такие, пустых областей быть не должно:

```bsl
#Область ОписаниеПеременных
#КонецОбласти

#Область ОбработчикиСобытийФормы
// ПриСозданииНаСервере, ПриОткрытии, ПередЗакрытием
#КонецОбласти

#Область ОбработчикиСобытийЭлементовШапкиФормы
// всё, что не относится к таблицам формы
#КонецОбласти

#Область ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицыФормы>
// своя область на каждую таблицу формы: ...ТаблицыФормыДерево, ...ТаблицыФормыСписок
#КонецОбласти

#Область ОбработчикиКомандФормы
// процедуры из свойства Действие команд формы
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

Объёмный код делится внутри них на подобласти **по смыслу** на втором уровне. **Больше 10 методов в области - дробить обязательно**; имя подобласти - существительное по назначению (`ЗагрузкаПакета`), заглушки (`Прочее`, `Вспомогательные`) запрещены.

Нельзя:

- **группировать методы по «технологии»** - области `ВызовыСервера`, `КлиентскиеМетоды`, `БезКонтекста` запрещены стандартом: серверная обёртка живёт рядом с клиентским методом, который её вызывает;
- вызывать один обработчик события из другого - общее действие выносится в отдельную процедуру;
- оставлять код вне областей;
- называть локальную переменную или параметр именем свойства формы (`Параметры`, `Окно`, `СписокВыбора`): `Параметры = Новый Структура` падает при открытии формы, синтаксический контроль молчит. Список - [`bsl-form-reserved-names.md`](bsl-form-reserved-names.md), сверяться до написания модуля.

Каждая переменная модуля - с комментарием в той же строке; в заголовке модуля рекомендуется описывать параметры формы. Обработчики одного элемента стоят вместе, в порядке следования в панели свойств редактора формы.

### Обработчик события, отданный общему модулю, - с полным набором параметров

Метод общего модуля, которому обработчик передаёт работу, принимает **все** параметры события, включая те, что пока не читает: сигнатура - зеркало события платформы, а не текущей реализации. Понадобился параметр - правится один общий модуль, а убранный пришлось бы возвращать в каждую форму.

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	prj_РаботаСФормами.ПриСозданииНаСервереФормаСписка(ЭтотОбъект, Отказ, СтандартнаяОбработка);
КонецПроцедуры
```

Неиспользуемый параметр экспортного метода диагностика не отмечает - набор сверяется с событием платформы; в докблоке у такого параметра пишется, что он передаётся для полноты контракта.

## Строгая типизация

`// @strict-types` - первая строка нового модуля формы ([`bsl-strict-types.md`](bsl-strict-types.md)): ловит неявную смену типа реквизита, передачу не того типа в обработчик, `Перем` без инициализации. В существующий модуль директива добавляется при первом значимом расширении (примерно от 10 строк нового кода), не при косметической правке.

## Директивы компиляции

| Директива | Контекст | Когда использовать |
|---|---|---|
| `&НаКлиенте` | Клиент | Взаимодействие с UI, обработка ввода |
| `&НаСервере` | Сервер с контекстом формы | **Только** когда метод меняет реквизиты или элементы формы |
| `&НаСервереБезКонтекста` | Сервер без контекста | **Предпочтительно** для операций с данными: нужные данные передаются параметрами |
| `&НаКлиентеНаСервереБезКонтекста` | Клиент и сервер | Вычисления над переданными данными без обращения к БД, `Форма` или `Объект` параметром - один метод с обеих сторон |

Передача контекста формы на сервер без необходимости - антипаттерн ([`bsl-anti-patterns.md`](bsl-anti-patterns.md) №7).

### Порядок методов внутри подобласти

В модулях форм и команд (там, где директивы различаются). Первый ключ - смысл: связанные методы рядом, клиентский метод не отрывается от своей серверной обёртки. Где методы не связаны вызовом: `&НаКлиенте` → `&НаКлиентеНаСервереБезКонтекста` → `&НаСервереБезКонтекста` → `&НаСервере`; внутри директивы процедуры выше функций. Действует в служебных областях; в областях обработчиков порядок иной: события формы - по жизненному циклу, события элементов - по порядку элементов в панели свойств. В существующих модулях порядок наводится при значимой переработке области.

### Суффикс «НаСервере» в именах

Метод с `&НаСервере` или `&НаСервереБезКонтекста` обязан оканчиваться на `НаСервере` (`СписокПользователейИБНаСервере`): по месту вызова виден серверный round-trip. Клиентские и клиент-серверные методы - без суффикса.

## Клиент-серверное взаимодействие

- Не вызывать серверные методы в циклах на клиенте; собирать нужные данные одним вызовом - структура с результатами ([`bsl-anti-patterns.md`](bsl-anti-patterns.md) №6).
- Вычислительный метод над данными формы - `&НаКлиентеНаСервереБезКонтекста` с параметром `Форма` или `Объект`: один метод вызывается с обеих сторон без дублирования.
- **Результат серверного метода - через возвращаемое значение, не через параметр.** Параметры вызова с клиента сериализуются; на клиент возвращается только параметр **без `знач`**, со `знач` заполнение остаётся на сервере молча. Поэтому не `Процедура ЗаполнитьНастройкиНаСервере(знач Настройки)`, а `Функция НастройкиНаСервере(знач Настройки)` с `Возврат Настройки`. Таблица поведения - [`bsl-strict-types.md`](bsl-strict-types.md) §3.

## Управление свойствами элементов

Видимость, доступность, «только просмотр», заголовок, картинка-индикатор элемента зависят от
состояния формы и ставятся из **одного места** - процедуры условного оформления формы.
Обработчики событий свойства элементов не трогают: они меняют данные и зовут пересчёт.

- **Две процедуры `&НаКлиентеНаСервереБезКонтекста`** в области `УправлениеФормой`:
  `УстановитьУсловноеОформлениеРеквизита(Форма, Обработано, ИмяРеквизита)` ставит свойства
  одного элемента или раскрывает набор; `УстановитьУсловноеОформление(Форма, ИменаРеквизитов = "")` -
  вход: имена через запятую или массив, пустая строка - вся форма. Клиент-серверные они
  потому, что один и тот же вызов идёт из `ПриСозданииНаСервере` и из `ПриИзменении`:
  `&НаКлиенте`-вариант на сервере при создании формы не позвать, первичное состояние
  пришлось бы собирать вторым куском кода, и два места разошлись бы при первой же правке.
- **Значения читаются из формы**, а не передаются параметрами: `Форма.<Реквизит>`,
  `Форма.Объект`. Свойства ставятся
  `ОбщегоНазначенияКлиентСервер.УстановитьСвойствоЭлементаФормы(Элементы, Имя, Свойство, Значение)`:
  у программно созданных элементов тип свойства иначе не выводится, отсутствующий элемент
  вызов не роняет.
- **Наборы.** Область `Наборы` раскрывает имя набора (`РеквизитыИнтеграции`,
  `КомандыТабличногоДокумента`) в вызовы по элементам; область `Элементы` держит по одному
  условию на элемент. Пустое имя проходит все ветки; элемент, в который попадают только через
  набор, сравнивается без `ПустаяСтрока`. Массив `Обработано` защищает от повторного расчёта,
  когда элемент входит в несколько наборов.
- **Когда вызывать.** Целиком - из `ПриОткрытии` или `ПриСозданииНаСервере`; по набору - из
  `ПриИзменении`, `ПослеЗаписи`, после серверной операции, из команды, переключающей режим:
  `УстановитьУсловноеОформление(ЭтотОбъект, "РеквизитыИнтеграции")`.
- **Чего не делать.** Метод вида `УстановитьВидимость()` с перечнем
  `Элементы.Имя.Свойство = Значение` - дублирует состояние и считает всё при любом изменении;
  присваивания свойств, разбросанные по обработчикам, - состояние формы расходится при первом
  же новом условии. Платформенное условное оформление таблиц (`УсловноеОформление` формы) -
  отдельная серверная процедура при создании формы, в эту не смешивается (std710).

Скелет:

```bsl
#Область УправлениеФормой

&НаКлиентеНаСервереБезКонтекста
Процедура УстановитьУсловноеОформление(Форма, ИменаРеквизитов = "")

	Если ТипЗнч(ИменаРеквизитов) = Тип("Строка") Тогда
		Если ПустаяСтрока(ИменаРеквизитов) Тогда
			МассивИмен = Новый Массив;
			МассивИмен.Добавить("");
		Иначе
			МассивИмен = СтроковыеФункцииКлиентСервер.РазложитьСтрокуВМассивПодстрок(ИменаРеквизитов, ",");
		КонецЕсли;
	ИначеЕсли ТипЗнч(ИменаРеквизитов) = Тип("Массив") Тогда
		МассивИмен = ИменаРеквизитов;
	Иначе
		Возврат;
	КонецЕсли;

	Обработано = Новый Массив;
	Для Каждого ИмяРеквизита Из МассивИмен Цикл
		УстановитьУсловноеОформлениеРеквизита(Форма, Обработано, СокрЛП(ИмяРеквизита));
	КонецЦикла;

КонецПроцедуры

&НаКлиентеНаСервереБезКонтекста
Процедура УстановитьУсловноеОформлениеРеквизита(Форма, Обработано, ИмяРеквизита)

	Если НЕ Обработано.Найти(ИмяРеквизита) = Неопределено Тогда
		Возврат;
	КонецЕсли;
	Обработано.Добавить(ИмяРеквизита);

	Элементы = Форма.Элементы;

	#Область Наборы

	// Имя набора раскрывается в элементы; пустое имя - вся форма.
	Если ИмяРеквизита = "РеквизитыИнтеграции" ИЛИ ПустаяСтрока(ИмяРеквизита) Тогда
		УстановитьУсловноеОформлениеРеквизита(Форма, Обработано, "ГруппаПодключение");
		УстановитьУсловноеОформлениеРеквизита(Форма, Обработано, "КомандаПроверитьПодключение");
	КонецЕсли;

	#КонецОбласти

	#Область Элементы

	// Элемент, видимый с верхнего уровня, - с ПустаяСтрока; элемент только из набора - без неё.
	Если ИмяРеквизита = "ГруппаПодключение" ИЛИ ПустаяСтрока(ИмяРеквизита) Тогда
		ОбщегоНазначенияКлиентСервер.УстановитьСвойствоЭлементаФормы(Элементы,
			"ГруппаПодключение", "Видимость", Форма.ИнтеграцияИспользовать);
	КонецЕсли;

	Если ИмяРеквизита = "КомандаПроверитьПодключение" Тогда
		ОбщегоНазначенияКлиентСервер.УстановитьСвойствоЭлементаФормы(Элементы,
			"КомандаПроверитьПодключение", "Доступность", ЗначениеЗаполнено(Форма.АдресСервиса));
	КонецЕсли;

	#КонецОбласти

КонецПроцедуры

#КонецОбласти
```

Вызовы: `УстановитьУсловноеОформление(ЭтотОбъект)` из `ПриОткрытии`;
`УстановитьУсловноеОформление(ЭтотОбъект, "РеквизитыИнтеграции")` из
`ИнтеграцияИспользоватьПриИзменении` и после серверной операции, которая меняет состояние.

## Данные формы

Конвертация между данными формы и объектами - `ДанныеФормыВЗначение()` / `ЗначениеВДанныеФормы()`. Реквизиты формы - представления, специфичные для формы, не реквизиты объекта.

### Массив и структура в реквизит формы не кладутся

Реквизит формы произвольного типа принимает только значения, допустимые в данных формы; `Массив`, `Структура`, `Соответствие` к ним не относятся. Присваивание падает при создании формы («Тип "Массив" не может использоваться в данных формы»), EDT этого не ловит. Из коллекций допустимы фиксированные: `ФиксированныйМассив`, `ФиксированнаяСтруктура`, `ФиксированноеСоответствие` - так параметры формы приходят фиксированными коллекциями, и колонка без типа их принимает; собранный в коде формы `Массив` туда класть так же нельзя.

Набор однотипных записей, нужный форме на клиенте (каталог, справочные данные), - реквизит с типом «Таблица значений» и типизированными колонками: строки доступны на клиенте, поиск - `НайтиСтроки`, колонки видны EDT; на сервере заполняется `ЗаполнитьЗначенияСвойств(Таблица.Добавить(), Запись)` или `ЗначениеВДанныеФормы`.

Ошибку не видят ни диагностика, ни серверный тест - только клиентский тест, открывающий форму через `ПолучитьФорму` с параметрами. Заводить его, как только у формы появляется реквизит, заполняемый при создании.

### Обращение через ЭтотОбъект

К реквизитам и методам платформы формы - через `ЭтотОбъект.` (`ЭтотОбъект.ИмяМакета`, `ЭтотОбъект.ОповеститьОВыборе(Результат)`); процедуры и функции самого модуля - без префикса. Общее правило - [`bsl-coding-standards.md`](bsl-coding-standards.md), «Обращение к контексту через `ЭтотОбъект`». Исключения формы: основной реквизит `Объект` и его подреквизиты, служебные коллекции `Элементы`, `Команды`, `Параметры` - без префикса; в `&НаКлиентеНаСервереБезКонтекста`-хелперах форма приходит параметром - `Форма.<Имя>`. Синоним `ЭтаФорма` устарел. Правило для нового кода.

### Префикс `prj_` у реквизитов, элементов и команд формы

Префикс нужен только там, где имя попадает в **чужое** пространство имён: в форме конфигурации-приёмника (заимствованной) реквизиты, элементы и команды расширения обязаны идти с `prj_`; в собственной форме расширения префикс не нужен. Это относится и к добавляемому программно (`ИзменитьРеквизиты`, `Элементы.Добавить`): важна форма-получатель. Панель, встраиваемая в разные формы, называет элементы `<ИмяПодсистемы><Назначение>` (`СинтаксПомощникДерево`). Имена объектов метаданных - всегда с `prj_` (CLAUDE.md).

### Чтение параметров формы

Параметр из схемы формы - по точке: `Параметры.ИмяПараметра`. Опциональный (передаётся ad-hoc) - `ОбщегоНазначенияКлиентСервер.СвойствоСтруктуры(Параметры, "Имя", Дефолт)`. Старый паттерн `Параметры.Свойство("Имя", Перем)` с временной переменной не использовать - три строки на параметр. Компактную инициализацию из 3-5 параметров держать прямо в `ПриСозданииНаСервере`; отдельная процедура оправдана только при логике сверх чтения.

## Приёмы

Готовые образцы типовых вещей. Свойства элементов в них ставятся так же, как в «Управление
свойствами элементов»: процедура `&НаКлиентеНаСервереБезКонтекста` с параметром `Форма` и
`УстановитьСвойствоЭлементаФормы`.

### Панель однотипных реквизитов: дефолты + мерж

Панель из ~5 и более однотипно заполняемых полей (превью настроек, шапка) не обслуживать парой методов «Очистить…»/«Заполнить…» с блоками `?(... = Неопределено, "", ...)` - список полей дублируется трижды. Вместо этого два метода `&НаКлиентеНаСервереБезКонтекста`: `ПустыеЗначения<Панель>()` возвращает структуру дефолтов правильных типов (единственное место со списком полей), а `Обновить<Панель>(Форма, знач Источник = Неопределено)` мержит источник поверх дефолтов и заливает в реквизиты одним циклом. Сброс панели - тот же вызов без источника.

```bsl
&НаКлиентеНаСервереБезКонтекста
Функция ПустыеЗначенияПанели()
	Значения = Новый Структура;
	Значения.Вставить("ОриентацияСтраницы", "");
	Значения.Вставить("МасштабПечати"     , 0);
	Значения.Вставить("ЧерноБелаяПечать"  , Ложь);
	Возврат Значения;
КонецФункции

&НаКлиентеНаСервереБезКонтекста
Процедура ОбновитьПанельНастроек(Форма, знач Источник = Неопределено)
	Значения = ПустыеЗначенияПанели();
	Если НЕ Источник = Неопределено Тогда
		Для Каждого Поле Из Значения Цикл
			Значения[Поле.Ключ] = ОбщегоНазначенияКлиентСервер.СвойствоСтруктуры(
				Источник, Поле.Ключ, Поле.Значение);
		КонецЦикла;
	КонецЕсли;
	Для Каждого Поле Из Значения Цикл
		Форма[Поле.Ключ] = Поле.Значение;
	КонецЦикла;
КонецПроцедуры
```

Имена ключей структуры дефолтов совпадают с именами реквизитов формы; если в источнике имена другие (XDTO-поля, поля БД) - предварительно построить структуру с правильными ключами. Нестандартную конвертацию отдельных полей (Булево → Число для радиокнопок) делать точечно до общего цикла мержа.

### Поле-пароль: реальное значение на клиент не выгружается

Секрет (ключ доступа, пароль прокси) в форме не показывается и на клиент не уезжает. Реквизит поля хранит фиксированный плейсхолдер; запись в хранилище идёт на сервере и только тогда, когда значение заполнено и отличается от плейсхолдера, после записи поле снова получает плейсхолдер. При открытии формы и при смене владельца секрета поле получает плейсхолдер, если секрет установлен, иначе пустую строку.

```bsl
&НаСервере
Процедура СохранитьВведенныйКлючНаСервере()

	Если НЕ ЗначениеЗаполнено(ЭтотОбъект.КлючДоступаДанные)
		ИЛИ ЭтотОбъект.КлючДоступаДанные = ЗначениеЗаполненияПароля() Тогда
		Возврат;
	КонецЕсли;

	prj_ИнтеграцияВызовСервера.ЗаписатьКлючДоступа(Объект.ТипПровайдера, ЭтотОбъект.КлючДоступаДанные);
	ЭтотОбъект.КлючДоступаДанные = ЗначениеЗаполненияПароля();

КонецПроцедуры
```

### Пояснительный текст - в расширенную подсказку, а не в реквизит-надпись

Текст, который объясняет пользователю выбранное значение («что означает этот вариант», «чья учётная запись проверяла доступ», «где хранится настройка»), писать в **расширенную подсказку** самого элемента, а не заводить под него реквизит формы и `ПолеНадписи`:

```bsl
&НаКлиентеНаСервереБезКонтекста
Процедура ОбновитьПодсказкуИсточника(знач Форма)

	ТекстПодсказки = ТекстПодсказкиИсточника(Форма);
	ОбщегоНазначенияКлиентСервер.УстановитьСвойствоЭлементаФормы(Форма.Элементы,
		"ИсточникРасширеннаяПодсказка", "Заголовок", ТекстПодсказки);

КонецПроцедуры
```

Расширенная подсказка есть у каждого элемента формы изначально (`<ИмяЭлемента>РасширеннаяПодсказка`), её видимость включается свойством элемента «Отображение подсказки» = `ShowBottom` / `ShowRight`, а текст ставится как «Заголовок». Реквизит же стоит дороже, чем кажется: он едет на сервер в каждом контекстном вызове, ограничен длиной строки (длинное пояснение молча обрежется), попадает в состав данных формы и в механизмы сохранения настроек. Отличать от **статичного** пояснения - оно задаётся заголовком декорации прямо в форме и кода не требует вовсе.

Реквизит под текст оправдан только там, где текст должен быть форматированным (`ФорматированнаяСтрока` со ссылками) или занимать отдельное место в раскладке, не привязанное ни к какому элементу.

То же и с **отметкой состояния** («годен / не годен», «токен установлен»): это пара декораций - картинка и надпись - в горизонтальной группе, и обе заполняются кодом через `УстановитьСвойствоЭлементаФормы` («Картинка» и «Заголовок»). Реквизит здесь тоже не нужен; видимостью всей отметки управляет группа, а не каждый элемент по отдельности.

```bsl
&НаКлиентеНаСервереБезКонтекста
Процедура УстановитьОтметку(знач Форма, знач Годен, знач Текст)

	ОбщегоНазначенияКлиентСервер.УстановитьСвойствоЭлементаФормы(Форма.Элементы,
		"КартинкаПроверка", "Картинка",
		?(Годен, БиблиотекаКартинок.ОформлениеЗнакФлажок, БиблиотекаКартинок.ОформлениеЗнакКрест));

	ОбщегоНазначенияКлиентСервер.УстановитьСвойствоЭлементаФормы(Форма.Элементы,
		"НадписьПроверка", "Заголовок", Текст);

КонецПроцедуры
```

### Подсказка в пустой ячейке таблицы - колонка с текстом и оформление «Текст»

Когда пустая ячейка таблицы должна подсказывать, что в неё ввести, а подсказка у каждой строки своя, свойство поля `ПодсказкаВвода` не подходит: оно одно на всю колонку. Приём:

1. В табличную часть реквизита формы - колонка с текстом подсказки (`ТекстПодсказки`, строка). На форму она не выводится, заполняется кодом там, где строка получает смысл (например, при выборе свойства строки).
2. Элемент условного оформления на поле ячейки: отбор - поле **не заполнено** и `ТекстПодсказки` **заполнен**; параметр «Текст» - `Новый ПолеКомпоновкиДанных` на колонку подсказки; цвет текста - стилевой `ЦветаСтиля.ПоясняющийТекст` (не `WebЦвета`, [`bsl-form-design-8.3.md`](bsl-form-design-8.3.md)), шрифт - по задумке (например, курсив).

```bsl
&НаСервере
Процедура УстановитьОформлениеПодсказкиПоляНаСервере()

	ЭлементОформления = ЭтотОбъект.УсловноеОформление.Элементы.Добавить();
	ЭлементОформления.Использование	= Истина;
	ЭлементОформления.Представление	= НСтр("ru='Подсказка в пустом поле ИмяПоля'");

	// отбор
	ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбора(ЭлементОформления.Отбор,
		"Состав.ИмяПоля",, ВидСравненияКомпоновкиДанных.НеЗаполнено,, Истина);
	ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбора(ЭлементОформления.Отбор,
		"Состав.ТекстПодсказки",, ВидСравненияКомпоновкиДанных.Заполнено,, Истина);

	// оформление
	ПолеПодсказки	= Новый ПолеКомпоновкиДанных("Состав.ТекстПодсказки");
	ШрифтПодсказки	= Новый Шрифт(Элементы.Состав.Шрифт, , , , Истина);
	Оформление		= ЭлементОформления.Оформление;
	Оформление.УстановитьЗначениеПараметра("Текст"		, ПолеПодсказки);
	Оформление.УстановитьЗначениеПараметра("ЦветТекста"	, ЦветаСтиля.ПоясняющийТекст);
	Оформление.УстановитьЗначениеПараметра("Шрифт"		, ШрифтПодсказки);

	// поля
	ИмяПоля = Элементы.СоставИмяПоля.Имя;
	ПолеОформления = ЭлементОформления.Поля.Элементы.Добавить();
	ПолеОформления.Поле = Новый ПолеКомпоновкиДанных(ИмяПоля);

КонецПроцедуры
```

Пустая колонка подсказки - ячейка выглядит как обычно; подсказка есть, а поле пустое - виден серый текст. Значение поля оформление не меняет и в данные не попадает; при входе в редактирование ячейка пуста. Одного элемента оформления хватает на все строки, сколько бы разных подсказок ни было, - заводить элемент на каждый вариант текста не нужно.

Когда текст подсказки один для всей колонки («не проверено», «нет в базе»), колонка-подсказка не нужна: элемент условного оформления с отбором «поле не заполнено», параметрами «Текст» (строка) и «ЦветТекста» = `ЦветаСтиля.ПоясняющийТекст`.

### Кнопки и запреты таблицы

- **Кнопки встроенной командной панели адресуются по имени** (`Форма<Команда>`, `<Таблица><Команда>`) через ту же точку управления свойствами (раздел «Управление свойствами элементов»): доступность и видимость команд формы и таблицы ставятся там же, где остальные свойства, хотя инструменты MCP эти кнопки не видят.
- **Запрет действия - свойством таблицы, не кнопки**: удаление строки по условию снимается `ИзменятьСоставСтрок` у таблицы, а не видимостью кнопки «Удалить» - вместе с кнопкой уходит и клавиша. Таблице с удалением по условию «Только просмотр» не ставится: он выключает стандартную «Удалить» при любом `ИзменятьСоставСтрок`. Запрет правки ячеек - `ТолькоПросмотр` у колонок, запрет перестановки строк - `ИзменятьПорядокСтрок` и «Перетаскивание» таблицы выключены.

## Возврат результата формы

Форма, возвращающая результат по кнопке («Записать и закрыть», «Применить»), делает это парой `ОповеститьОВыборе` + `Закрыть` с проверкой `Открыта()`:

```bsl
&НаКлиенте
Процедура ЗаписатьИЗакрыть(Команда)

	Результат = Новый Структура;
	Результат.Вставить("НовыйКлюч", Объект.НовыйКлючПараметров);

	ЭтотОбъект.ОповеститьОВыборе(Результат);
	Если ЭтотОбъект.Открыта() Тогда
		ЭтотОбъект.Закрыть(Результат);
	КонецЕсли;

КонецПроцедуры
```

`ОповеститьОВыборе` - единый канал результата при модальном открытии (`РежимОткрытияОкнаФормы.БлокироватьОкноВладельца`) и при немодальном с обработчиком выбора. Проверка `Открыта()` обязательна: внешний `ОбработкаВыбора` мог уже закрыть форму, и безусловный `Закрыть()` упадёт.

## Асинхронные вызовы

Новый клиентский код пишется на асинхронных методах платформы (`Ждать ВопросАсинх(...)`, `Ждать Список.ВыбратьЭлементАсинх(...)`), а не на колбэках с `ОписаниеОповещения`; существующие колбэки не переписываются. Обработчики событий формы `Асинх` не бывают (параметр `Отказ` будет проигнорирован) - из обычного обработчика вызывается отдельная `Асинх`-процедура; обработчики команд `Асинх` делать можно. Таблица соответствия методов, факты платформы (открытие формы аналога `Асинх` не имеет) и паттерны - [`bsl-async.md`](bsl-async.md).

## Поведение формы по стандартам 1С

Что форма делает в коде - по стандартам ИТС `v8std` разделов «Реализация работы формы»,
«Формы списков» и «Диалог с пользователем» (ссылки - [`bsl-form-design-8.3.md`](bsl-form-design-8.3.md),
«Источники»). Вёрстка формы - там же, разделы 1-9.

### Открытие и результат

- **Только `ОткрытьФорму`** с параметрами в структуре; `ПолучитьФорму` с последующей настройкой
  свойств формы не применяется (std404 п.1-3). Параметры объявлены на закладке «Параметры»
  формы и читаются по имени (std741 п.3, «Чтение параметров формы» выше). Форма, работающая
  только с параметрами, не назначается основной; если другой нет - проверка параметров с
  понятным исключением (std741 п.1-2).
- **Результат** - `Закрыть(Результат)` или `ОповеститьОВыборе` («Возврат результата формы»
  выше); обращаться к реквизитам чужой формы после закрытия нельзя (std404 п.4).
- **В `ПриОткрытии` не открывать другие формы**; открытие и закрытие формы - не в одном
  обработчике (std404 п.5).
- **Экспортных процедур в модуле формы нет**, кроме обработчиков оповещений и подключаемых
  процедур библиотек (std630 п.1); параметризация и обновление формы снаружи - `ОткрытьФорму`,
  `Оповестить`, `ОповеститьОбИзменении`. Модальные окна и синхронные вызовы запрещены (std703,
  «Асинхронные вызовы» выше).

### Форма объекта

Для форм, основной реквизит которых - объект базы (std800):

- Все изменения объекта инициирует пользователь; при открытии и после записи объект не
  меняется (`ПриСозданииНаСервере`, `ПриЧтенииНаСервере`, `ПриОткрытии`, `ПослеЗаписи*` объект не
  трогают); заполнение нового объекта - `ОбработкаЗаполнения` в модуле объекта (п.1, п.5).
- Запись без явного намерения пользователя не выполняется; команда вне стандартного списка
  («Записать», «Записать и закрыть», «Провести», «Пометить на удаление»), которая запишет
  объект, предупреждает и даёт отменить (п.3). Объект из `РеквизитФормыВЗначение` не
  записывается в обход формы (п.4). `Модифицированность = Ложь` не ставится (п.6).
- Команды, меняющие объект, помечены «Изменяет данные» (std537).

### Списки

- **Команда в форме динамического списка** учитывает группировку: строки группировки
  пропускаются, при единственной выделенной группировке - предупреждение (std495).
- **Список обновляется явно** после команды, меняющей объекты: `ОповеститьОбИзменении` на
  ссылку или тип, при нескольких объектах - один раз в конце (std558 п.2); список без основной
  таблицы - `Оповестить("Запись_<ИмяОбъекта>", ...)` из `ПослеЗаписи` формы объекта с явной
  проверкой имени события в `ОбработкаОповещения` (п.3).
- **Динамический список**: основная таблица задана, реквизит «Ссылка» в списке, условия -
  параметрами, без соединений с подзапросами (std489, std702, std732, std768). История
  выбора у поля ввода - «Авто», если прикладная логика не требует иного (std744).

### Диалог с пользователем

- **Ошибки проверки заполнения** - в панель сообщений формы с привязкой к полю (при БСП -
  `ОбщегоНазначения.СообщитьПользователю` / `...Клиент`); проверки вне транзакции - до записи, в
  `ОбработкаПроверкиЗаполнения` (std400 п.1.1). `Сообщить()` не используется (std418).
- **Ошибка локальной команды** - `ПоказатьПредупреждение` без обработчика (`ПредупреждениеАсинх`
  с `Ждать` - только если после окна продолжается код, [`bsl-async.md`](bsl-async.md)); если есть выход - `ВопросАсинх` с
  вариантами (std400 п.1.3); ситуация, делающая работу бессмысленной, - исключение с причиной.
- **Успех сообщается, когда он не очевиден** («Обработано 5 документов»):
  `ПоказатьПредупреждение`, если нужно остановить пользователя, иначе
  `ПоказатьОповещениеПользователя`; молча «проглотить» нажатие кнопки нельзя (п.1.4). Без формы
  на экране - оповещение; ход клиентской операции - `Состояние` (п.1.5). Протокол операции из
  многих сообщений - отдельное поле или форма итога (п.1.2).
- **Длительная серверная операция** - фоновое задание с индикацией и отменой (при БСП -
  `ДлительныеОперации`) (std642). Длительная клиентская операция (сеть, файлы) - только по
  явному действию пользователя, не в обработчике ожидания и не в `ПриИзменении` поля
  (std755): проверка пути - кнопкой «Проверить».

### Клиент и сервер

- **Контекстный вызов** оправдан, когда платформа сама оптимизирует передачу (табличный
  документ, коллекции данных формы); остальное - `&НаСервереБезКонтекста` с минимальными
  параметрами; коллекции формы и табличный документ по значению на сервер не передаются
  (std636 п.2-3).
- **`ПриАктивизацииСтроки`** не вызывает сервер напрямую: однократный обработчик ожидания с
  запоминанием `ИдентификаторТекущейСтроки` (std636 п.2.2). В клиентских `ПередЗаписью`,
  `ПослеЗаписи`, `ПередЗакрытием`, `ПриЗакрытии` контекстный вызов невозможен (п.2.1).
- **Коллекция формы от 20 строк** обходится и ищется на сервере одним вызовом (std628).
  Табличный документ в веб-клиенте: пересчёт после правки ячейки - на клиенте, иначе один
  бесконтекстный вызов (std533).
- **Автоматически формируемые элементы** платформа пересоздаёт - после смены
  `ОсновнаяТаблица` свойства кнопок ставятся заново (std536); элементы, добавленные
  пользователем через «Изменить форму», коду недоступны - `ТекущаяСтраница` и `ТекущийЭлемент`
  проверяются на `Неопределено` (std545).
- **Условное оформление** настраивается при создании формы и потом не меняется; строки
  целиком им не скрываются; имена полей - из `Элементы.<Имя>.Имя`, не литералы (std710).

### Чек-лист

Автоматически по модулю ([`tools/form-audit/form-audit.py`](../tools/form-audit/form-audit.py)): `Параметры.Свойство`, сервер в
`ПриАктивизацииСтроки`, `Сообщить`, `ПолучитьФорму`, экспорт в модуле формы,
`Модифицированность = Ложь`. Руками: результат формы через `ОповеститьОВыборе` / `Закрыть`;
ошибки в панель сообщений, результат операции сообщён, длительное - фоновым заданием; нет
коллекций по значению на сервер; список обновлён после команды.

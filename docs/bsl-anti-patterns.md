# Антипаттерны и производительность BSL

Критические антипаттерны, проблемы производительности и нарушения best practices для разработки 1С.

---

## Критические антипаттерны (обязательно исправлять)

### 1. Запрос в цикле — CRITICAL

**Влияние:** O(n) обращений к БД вместо O(1)

```bsl
// CRITICAL: N обращений к БД
Для Каждого Строка Из Данные Цикл
	Запрос = Новый Запрос("ВЫБРАТЬ ... ГДЕ Ссылка = &Ссылка");
	Запрос.УстановитьПараметр("Ссылка", Строка.Ссылка);
	РезультатЗапроса = Запрос.Выполнить();
КонецЦикла;

// Оптимально: 1 обращение к БД
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ ...
|ГДЕ
|	Ссылка В (&СписокСсылок)";
Запрос.УстановитьПараметр("СписокСсылок",
	Данные.ВыгрузитьКолонку("Ссылка"));
РезультатЗапроса = Запрос.Выполнить();
```

### 2. Обращение к реквизитам через точку — CRITICAL

**Влияние:** загрузка всего объекта из БД

```bsl
// CRITICAL: полная загрузка объекта для каждого реквизита
ИНН         = Контрагент.ИНН;
КПП         = Контрагент.КПП;
Наименование = Контрагент.Наименование;

// Оптимально: один целевой запрос через БСП
Реквизиты    = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(
	Контрагент, "ИНН, КПП, Наименование");
ИНН          = Реквизиты.ИНН;
КПП          = Реквизиты.КПП;
Наименование = Реквизиты.Наименование;
```

Методы БСП:

| Метод | Назначение |
|---|---|
| `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` | Один реквизит одной ссылки |
| `ОбщегоНазначения.ЗначенияРеквизитовОбъекта` | Несколько реквизитов одной ссылки |
| `ОбщегоНазначения.ЗначениеРеквизитаОбъектов` | Один реквизит нескольких ссылок |

### 3. Подзапрос в SELECT — CRITICAL

**Влияние:** выполнение N+1 запросов

```bsl
// CRITICAL: подзапрос выполняется для каждой строки
"ВЫБРАТЬ
|	Заказы.Ссылка,
|	(ВЫБРАТЬ СУММА(Оплаты.Сумма)
|	 ИЗ Документ.Оплата КАК Оплаты
|	 ГДЕ Оплаты.Заказ = Заказы.Ссылка) КАК СуммаОплат
|ИЗ
|	Документ.Заказ КАК Заказы"

// Оптимально: временная таблица + соединение
"ВЫБРАТЬ
|	Оплаты.Заказ КАК Заказ,
|	СУММА(Оплаты.Сумма) КАК СуммаОплат
|ПОМЕСТИТЬ ВТИтогиОплат
|ИЗ
|	Документ.Оплата КАК Оплаты
|СГРУППИРОВАТЬ ПО
|	Оплаты.Заказ
|ИНДЕКСИРОВАТЬ ПО
|	Заказ
|;
|ВЫБРАТЬ
|	Заказы.Ссылка КАК Ссылка,
|	ЕСТЬNULL(ИтогиОплат.СуммаОплат, 0) КАК СуммаОплат
|ИЗ
|	Документ.Заказ КАК Заказы
|	    ЛЕВОЕ СОЕДИНЕНИЕ ВТИтогиОплат КАК ИтогиОплат
|	    ПО Заказы.Ссылка = ИтогиОплат.Заказ"
```

## Высокий приоритет

### 4. Фильтр виртуальной таблицы в ГДЕ — HIGH

**Влияние:** полный перебор таблицы вместо использования индекса

```bsl
// HIGH: фильтр после вычисления виртуальной таблицы
"ВЫБРАТЬ
|	Остатки.Номенклатура КАК Номенклатура,
|	Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
|ГДЕ
|	Остатки.Склад = &Склад"

// Оптимально: фильтр в параметрах виртуальной таблицы
"ВЫБРАТЬ
|	Остатки.Номенклатура КАК Номенклатура,
|	Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки"
```

### 5. Отсутствие ПЕРВЫЕ N — HIGH

```bsl
// HIGH: загрузка всех записей без ограничения
"ВЫБРАТЬ
|	Контрагенты.Ссылка КАК Ссылка
|ИЗ
|	Справочник.Контрагенты КАК Контрагенты"

// Оптимально:
"ВЫБРАТЬ ПЕРВЫЕ 10
|	Контрагенты.Ссылка КАК Ссылка
|ИЗ
|	Справочник.Контрагенты КАК Контрагенты"
```

### 6. Множественные клиент-серверные вызовы — HIGH

```bsl
// HIGH: несколько серверных вызовов вместо одного
&НаКлиенте
Процедура Обработать(Команда)
	Данные1 = ПолучитьДанные1НаСервере();
	Данные2 = ПолучитьДанные2НаСервере();
	Данные3 = ПолучитьДанные3НаСервере();
КонецПроцедуры

// Оптимально:
&НаКлиенте
Процедура Обработать(Команда)
	ВсеДанные = ПолучитьВсеДанныеНаСервере();
КонецПроцедуры

&НаСервереБезКонтекста
Функция ПолучитьВсеДанныеНаСервере()
	Результат = Новый Структура;
	Результат.Вставить("Данные1", ПолучитьДанные1());
	Результат.Вставить("Данные2", ПолучитьДанные2());
	Результат.Вставить("Данные3", ПолучитьДанные3());
	Возврат Результат;
КонецФункции
```

### 7. &НаСервере вместо &НаСервереБезКонтекста — HIGH

```bsl
// HIGH: ненужная передача контекста формы
&НаСервере
Функция ПолучитьДанныеНаСервере()
	Возврат ВыполнитьЗапрос();
КонецФункции

// Оптимально:
&НаСервереБезКонтекста
Функция ПолучитьДанныеНаСервере(Параметры)
	Возврат ВыполнитьЗапрос(Параметры);
КонецФункции
```

### 8. НачатьТранзакцию() внутри Попытка — HIGH

```bsl
// HIGH: ОтменитьТранзакцию() вызовется, даже если НачатьТранзакцию() не выполнялась
Попытка
	НачатьТранзакцию();
	// ...
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию();
КонецПопытки;

// Правильно: НачатьТранзакцию() строго ДО Попытка
НачатьТранзакцию();
Попытка
	// ...
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию();
	ЗаписьЖурналаРегистрации(
		"Модуль.Функция",
		УровеньЖурналаРегистрации.Ошибка, , ,
		ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
	ВызватьИсключение;
КонецПопытки;
```

### 9. Админ-API без привилегированного режима — HIGH

Методы платформы, требующие административных прав ИБ (`ПользователиИнформационнойБазы.ПолучитьПользователей()`, `НайтиПоИмени()`, `НайтиПоУникальномуИдентификатору()`, чтение чужих настроек из `ХранилищеСистемныхНастроек`, выборка журнала регистрации по пользователям), падают у пользователей с прикладными ролями (`prj_Печать` и т.п.). В серверном методе, доступном не-администраторам, включать привилегированный режим.

```bsl
// HIGH: у пользователя без админ-прав ИБ вызов упадёт
Функция СписокПользователейИБНаСервере()
	Возврат ПользователиИнформационнойБазы.ПолучитьПользователей();
КонецФункции

// Правильно: привилегированный режим в начале процедуры
Функция СписокПользователейИБНаСервере()
	УстановитьПривилегированныйРежим(Истина);
	Возврат ПользователиИнформационнойБазы.ПолучитьПользователей();
КонецФункции
```

Явный сброс `УстановитьПривилегированныйРежим(Ложь)` не нужен — режим снимается при выходе из метода. Право пользователя на саму функцию проверять отдельно (прикладной ролью проекта), привилегированный режим — только для технического обхода проверки прав платформы.

## Средний приоритет

### 10. Отсутствие кеширования — MEDIUM

```bsl
// MEDIUM: повторные дорогие вызовы
Для Каждого Строка Из ТаблицаДанных Цикл
	Курс = ПолучитьКурсВалюты(Строка.Валюта, Строка.Дата);
КонецЦикла;

// Оптимально: кеширование через Соответствие
КэшКурсов = Новый Соответствие;
Для Каждого Строка Из ТаблицаДанных Цикл
	Ключ = Строка.Валюта + "|" + Формат(Строка.Дата, "ДФ=yyyyMMdd");
	Курс = КэшКурсов.Получить(Ключ);
	Если Курс = Неопределено Тогда
		Курс = ПолучитьКурсВалюты(Строка.Валюта, Строка.Дата);
		КэшКурсов.Вставить(Ключ, Курс);
	КонецЕсли;
КонецЦикла;
```

### 11. Алгоритм O(n²) — MEDIUM

```bsl
// MEDIUM: вложенный цикл поиска — экспоненциальная деградация
Для Каждого Строка1 Из Таблица1 Цикл
	Для Каждого Строка2 Из Таблица2 Цикл
		Если Строка1.Ключ = Строка2.Ключ Тогда
			// Обработка
		КонецЕсли;
	КонецЦикла;
КонецЦикла;

// Оптимально: O(n) через Соответствие
ИндексТаблицы2 = Новый Соответствие;
Для Каждого Строка2 Из Таблица2 Цикл
	ИндексТаблицы2.Вставить(Строка2.Ключ, Строка2);
КонецЦикла;

Для Каждого Строка1 Из Таблица1 Цикл
	Строка2 = ИндексТаблицы2.Получить(Строка1.Ключ);
	Если Строка2 <> Неопределено Тогда
		// Обработка
	КонецЕсли;
КонецЦикла;
```

### 12. Глубокая вложенность — MEDIUM

Более 4 уровней условий/циклов. Применять guard clauses (см. [`bsl-refactoring.md`](bsl-refactoring.md)).

### 13. ТекущаяДата() для меток времени — MEDIUM

`ТекущаяДата()` возвращает локальное время машины: на клиенте оно может расходиться с сервером (часовой пояс, рассинхрон часов), в клиент-серверной ИБ метки времени «прыгают». Для меток времени, идентификаторов, имён файлов брать сеансовое время: на сервере — `ТекущаяДатаСеанса()`, на клиенте — `ОбщегоНазначенияКлиент.ДатаСеанса()`.

```bsl
// MEDIUM: локальное время клиентской машины
ИмяФайла = "Выгрузка_" + Формат(ТекущаяДата(), "ДФ=yyyyMMdd_HHmmss");

// Правильно: серверное время, синхронизированное для сеанса
ИмяФайла = "Выгрузка_" + Формат(ОбщегоНазначенияКлиент.ДатаСеанса(), "ДФ=yyyyMMdd_HHmmss");
```

Исключение: чисто интерфейсные замеры на клиенте («прошло N секунд от нажатия») — там локальное `ТекущаяДата()` уместно.

### 14. Цикл для проверки наличия элемента — MEDIUM

Для проверки «есть ли значение в коллекции» использовать встроенный поиск, а не обход `Для Каждого`.

```bsl
// MEDIUM: ручной цикл ради проверки наличия
ЕстьЭлемент = Ложь;
Для Каждого Элемент Из Массив Цикл
	Если Элемент = Значение Тогда
		ЕстьЭлемент = Истина;
		Прервать;
	КонецЕсли;
КонецЦикла;

// Правильно:
ЕстьЭлемент = Массив.Найти(Значение) <> Неопределено;
```

По коллекциям: Массив/СписокЗначений — `.Найти(Значение)`; ТаблицаЗначений — `.Найти(Значение, "Колонка")` или `.НайтиСтроки(Отбор).Количество() > 0`; Структура — `.Свойство("Имя")`. Цикл оправдан, только если условие сложнее равенства или нужна обработка каждого элемента.

### 15. Удаление существующих методов при правке — MEDIUM

При редактировании модуля не удалять существующие методы и заглушки, даже «неиспользуемые» — особенно помеченные `//@skip-check module-unused-method - может пригодится`: это осознанный задел владельца. Править модуль точечными правками, а не полной перезаписью файла (перезапись молча теряет соседние методы). Заполнить пустое тело заглушки реализацией — правильно (это её назначение); удалить заглушку, концептуально заменённую новой логикой, можно только по решению владельца, не первой итерацией — промежуточное состояние «заглушка + реализация рядом» валидно.

### 16. Придуманный метод платформенного типа — MEDIUM

Метод, которого у типа нет, но который «должен бы быть по аналогии»: код пишется гладко, компилятор молчит до выполнения, а падает уже в рантайме. Самый частый случай — сортировка `Массива`: её нет, `Сортировать` есть у `ТаблицаЗначений`, `ДеревоЗначений` и (как `СортироватьПоЗначению`) у `СписокЗначений`.

```bsl
// MEDIUM: у Массива нет метода Сортировать
Части = Новый Массив;
Части.Добавить(Значение);
Части.Сортировать();

// Правильно — коллекция, которая умеет сортировать:
Части = Новый СписокЗначений; // СписокЗначений из Строка
Части.Добавить(Значение);
Части.СортироватьПоЗначению();
Возврат СтрСоединить(Части.ВыгрузитьЗначения(), ";");
```

Проверять по справочнику, а не по памяти: `/bsl-check Массив -m` (все методы типа) либо `/bsl-check Массив.Сортировать`. Дешевле одного прогона.

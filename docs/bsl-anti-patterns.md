# Антипаттерны и производительность BSL

Критические антипаттерны, проблемы производительности и нарушения best practices для разработки 1С.

| № | Антипаттерн | Серьёзность | Что искать |
|---|---|---|---|
| 1 | Запрос в цикле | CRITICAL | `Для Каждого` с `Новый Запрос` внутри |
| 2 | Обращение через точку | CRITICAL | `.Реквизит` у ссылочных типов |
| 3 | Подзапрос в SELECT | CRITICAL | Вложенный `ВЫБРАТЬ` в списке полей |
| 4 | Фильтр ВТ в ГДЕ | HIGH | Условия на результатах виртуальных таблиц |
| 5 | Нет ПЕРВЫЕ N | HIGH | Большие запросы без `ПЕРВЫЕ` |
| 6 | Множественные серверные вызовы | HIGH | Последовательные `НаСервере`-вызовы с клиента |
| 7 | &НаСервере вместо БезКонтекста | HIGH | Серверный вызов, не использующий контекст формы |
| 8 | НачатьТранзакцию() внутри Попытка | HIGH | `Попытка` перед `НачатьТранзакцию()` |
| 9 | Админ-API без привилегированного режима | HIGH | `ПолучитьПользователей` и т.п. без `УстановитьПривилегированныйРежим` |
| 10 | Нет кеширования | MEDIUM | Повторные дорогие вызовы с одинаковыми параметрами |
| 11 | Циклы O(n²) | MEDIUM | Вложенные циклы поиска совпадений |
| 12 | Глубокая вложенность | MEDIUM | >4 уровней условий/циклов |
| 13 | ТекущаяДата() для меток времени | MEDIUM | `ТекущаяДата()` вместо сеансового времени |
| 14 | Цикл для проверки наличия | MEDIUM | `Для Каждого` с одним `Если =` вместо `.Найти()` |
| 15 | Удаление существующих методов | MEDIUM | Пропавшие методы/заглушки в diff, перезапись модуля целиком |
| 16 | Придуманный метод типа | MEDIUM | `Массив.Сортировать()` и прочие «по аналогии» - сверять `/bsl-check` |

## Критические антипаттерны (обязательно исправлять)

### 1. Запрос в цикле - CRITICAL

**Влияние:** O(n) обращений к БД вместо O(1)

```bsl
// CRITICAL: N обращений к БД
Для Каждого Строка Из Данные Цикл
	Запрос = Новый Запрос("ВЫБРАТЬ ... ГДЕ Ссылка = &Ссылка");
	Запрос.УстановитьПараметр("Ссылка", Строка.Ссылка);
	РезультатЗапроса = Запрос.Выполнить();
КонецЦикла;

// Оптимально: 1 обращение к БД
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ ...
|ГДЕ
|	Ссылка В (&СписокСсылок)";
Запрос.УстановитьПараметр("СписокСсылок", Данные.ВыгрузитьКолонку("Ссылка"));
РезультатЗапроса = Запрос.Выполнить();
```

### 2. Обращение к реквизитам через точку - CRITICAL

**Влияние:** загрузка всего объекта из БД

```bsl
// CRITICAL: полная загрузка объекта для каждого реквизита
ИНН         = Контрагент.ИНН;
КПП         = Контрагент.КПП;
Наименование = Контрагент.Наименование;

// Оптимально: один целевой запрос через БСП
Реквизиты    = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(
	Контрагент, "ИНН, КПП, Наименование");
ИНН          = Реквизиты.ИНН;
КПП          = Реквизиты.КПП;
Наименование = Реквизиты.Наименование;
```

Методы БСП: `ЗначениеРеквизитаОбъекта` (один реквизит одной ссылки), `ЗначенияРеквизитовОбъекта` (несколько реквизитов одной ссылки), `ЗначениеРеквизитаОбъектов` (один реквизит нескольких ссылок).

### 3. Подзапрос в SELECT - CRITICAL

**Влияние:** выполнение N+1 запросов

```bsl
// CRITICAL: подзапрос выполняется для каждой строки
"ВЫБРАТЬ
|	Заказы.Ссылка,
|	(ВЫБРАТЬ СУММА(Оплаты.Сумма)
|	 ИЗ Документ.Оплата КАК Оплаты
|	 ГДЕ Оплаты.Заказ = Заказы.Ссылка) КАК СуммаОплат
|ИЗ
|	Документ.Заказ КАК Заказы"

// Оптимально: временная таблица + соединение
"ВЫБРАТЬ
|	Оплаты.Заказ КАК Заказ,
|	СУММА(Оплаты.Сумма) КАК СуммаОплат
|ПОМЕСТИТЬ ВТИтогиОплат
|ИЗ
|	Документ.Оплата КАК Оплаты
|СГРУППИРОВАТЬ ПО
|	Оплаты.Заказ
|ИНДЕКСИРОВАТЬ ПО
|	Заказ
|;
|ВЫБРАТЬ
|	Заказы.Ссылка КАК Ссылка,
|	ЕСТЬNULL(ИтогиОплат.СуммаОплат, 0) КАК СуммаОплат
|ИЗ
|	Документ.Заказ КАК Заказы
|	    ЛЕВОЕ СОЕДИНЕНИЕ ВТИтогиОплат КАК ИтогиОплат
|	    ПО Заказы.Ссылка = ИтогиОплат.Заказ"
```

## Высокий приоритет

### 4. Фильтр виртуальной таблицы в ГДЕ - HIGH

**Влияние:** полный перебор таблицы вместо использования индекса

```bsl
// HIGH: фильтр после вычисления виртуальной таблицы
"ВЫБРАТЬ
|	Остатки.Номенклатура КАК Номенклатура,
|	Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
|ГДЕ
|	Остатки.Склад = &Склад"

// Оптимально: фильтр в параметрах виртуальной таблицы
"ВЫБРАТЬ
|	Остатки.Номенклатура КАК Номенклатура,
|	Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки"
```

### 5. Отсутствие ПЕРВЫЕ N - HIGH

Выборка без ограничения там, где нужны первые записи: `ВЫБРАТЬ ПЕРВЫЕ 10 Контрагенты.Ссылка КАК Ссылка ...`.

### 6. Множественные клиент-серверные вызовы - HIGH

```bsl
// HIGH: несколько серверных вызовов вместо одного
&НаКлиенте
Процедура Обработать(Команда)
	Данные1 = ПолучитьДанные1НаСервере();
	Данные2 = ПолучитьДанные2НаСервере();
КонецПроцедуры

// Оптимально:
&НаКлиенте
Процедура Обработать(Команда)
	ВсеДанные = ПолучитьВсеДанныеНаСервере();
КонецПроцедуры

&НаСервереБезКонтекста
Функция ПолучитьВсеДанныеНаСервере()
	Результат = Новый Структура;
	Результат.Вставить("Данные1", ПолучитьДанные1());
	Результат.Вставить("Данные2", ПолучитьДанные2());
	Возврат Результат;
КонецФункции
```

### 7. &НаСервере вместо &НаСервереБезКонтекста - HIGH

Серверный метод формы, которому не нужны реквизиты и элементы формы, объявлен `&НаСервере` - контекст формы едет на сервер зря. Делать `&НаСервереБезКонтекста`, данные передавать параметрами ([`bsl-form-module-rules.md`](bsl-form-module-rules.md), «Директивы компиляции»).

### 8. НачатьТранзакцию() внутри Попытка - HIGH

`ОтменитьТранзакцию()` вызовется и там, где `НачатьТранзакцию()` не выполнялась. `НачатьТранзакцию()` - строго **до** `Попытка`; полный шаблон с логированием - [`bsl-coding-standards.md`](bsl-coding-standards.md), «Транзакции».

### 9. Админ-API без привилегированного режима - HIGH

Методы платформы, требующие административных прав ИБ (`ПользователиИнформационнойБазы.ПолучитьПользователей()`, `НайтиПоИмени()`, чтение чужих настроек из `ХранилищеСистемныхНастроек`, выборка журнала регистрации по пользователям), падают у пользователей с прикладными ролями. В серверном методе, доступном не-администраторам, включать привилегированный режим в начале метода:

```bsl
Функция СписокПользователейИБНаСервере()
	УстановитьПривилегированныйРежим(Истина);
	Возврат ПользователиИнформационнойБазы.ПолучитьПользователей();
КонецФункции
```

Явный сброс не нужен - режим снимается при выходе из метода. Право пользователя на саму функцию проверять отдельно ролью; привилегированный режим - только технический обход проверки прав платформы.

## Средний приоритет

### 10. Отсутствие кеширования - MEDIUM

Повторные дорогие вызовы с одинаковыми параметрами в цикле - кеш в `Соответствие`: ключ из параметров, при промахе вычислить и положить.

```bsl
КэшКурсов = Новый Соответствие;
Для Каждого Строка Из ТаблицаДанных Цикл
	Ключ = Строка.Валюта + "|" + Формат(Строка.Дата, "ДФ=yyyyMMdd");
	Курс = КэшКурсов.Получить(Ключ);
	Если Курс = Неопределено Тогда
		Курс = ПолучитьКурсВалюты(Строка.Валюта, Строка.Дата);
		КэшКурсов.Вставить(Ключ, Курс);
	КонецЕсли;
КонецЦикла;
```

### 11. Алгоритм O(n²) - MEDIUM

Вложенный цикл поиска совпадений по ключу - заменить индексом: один проход по второй таблице в `Соответствие` (ключ → строка), затем `Получить(Строка1.Ключ)` в первом цикле.

### 12. Глубокая вложенность - MEDIUM

Более 4 уровней условий/циклов. Применять guard clauses ([`bsl-refactoring.md`](bsl-refactoring.md)).

### 13. ТекущаяДата() для меток времени - MEDIUM

`ТекущаяДата()` - локальное время машины: на клиенте расходится с сервером, в клиент-серверной ИБ метки «прыгают». Для меток времени, идентификаторов, имён файлов - сеансовое время: на сервере `ТекущаяДатаСеанса()`, на клиенте `ОбщегоНазначенияКлиент.ДатаСеанса()`. Исключение - чисто интерфейсные замеры на клиенте («прошло N секунд от нажатия»).

### 14. Цикл для проверки наличия элемента - MEDIUM

«Есть ли значение в коллекции» - встроенный поиск, не обход: Массив/СписокЗначений - `.Найти(Значение) <> Неопределено`; ТаблицаЗначений - `.Найти(Значение, "Колонка")` или `.НайтиСтроки(Отбор).Количество() > 0`; Структура - `.Свойство("Имя")`. Цикл оправдан, только если условие сложнее равенства или нужна обработка каждого элемента.

### 15. Удаление существующих методов при правке - MEDIUM

При редактировании модуля не удалять существующие методы и заглушки, даже «неиспользуемые» - особенно помеченные `//@skip-check module-unused-method - может пригодится`: это осознанный задел владельца. Править точечно, не перезаписью файла (перезапись молча теряет соседние методы). Заполнить пустое тело заглушки реализацией - правильно; удалить заглушку, замещённую новой логикой, - только по решению владельца, не первой итерацией.

### 16. Придуманный метод платформенного типа - MEDIUM

Метод, которого у типа нет, но который «должен бы быть по аналогии»: компилятор молчит, падает рантайм. Частый случай - `Массив.Сортировать()`: сортировать умеют `ТаблицаЗначений`, `ДеревоЗначений` и `СписокЗначений` (`СортироватьПоЗначению`).

```bsl
Части = Новый СписокЗначений; // СписокЗначений из Строка
Части.Добавить(Значение);
Части.СортироватьПоЗначению();
Возврат СтрСоединить(Части.ВыгрузитьЗначения(), ";");
```

Проверять по справочнику, а не по памяти: `/bsl-check Массив -m` (все методы типа) либо `/bsl-check Массив.Сортировать`.

# Справочник языка запросов 1С

Синтаксис, источники данных, виртуальные таблицы, соединения, временные таблицы, типовые паттерны.

Оптимизация и производительность — [`bsl-query-optimization.md`](bsl-query-optimization.md)
Функции и выражения — [`bsl-query-functions.md`](bsl-query-functions.md)

---

## Структура запроса

Канонический порядок предложений (обязательное — отмечено, остальные — опционально):

```sql
ВЫБРАТЬ [РАЗРЕШЕННЫЕ] [РАЗЛИЧНЫЕ] [ПЕРВЫЕ <N>]
    <список полей>
ИЗ
    <источники данных>
[ГДЕ <условие>]
[СГРУППИРОВАТЬ ПО <поля>]
[ИМЕЮЩИЕ <условие>]

[ОБЪЕДИНИТЬ [ВСЕ]
ВЫБРАТЬ ...]

[УПОРЯДОЧИТЬ ПО <поля> [ВОЗР | УБЫВ]]
[АВТОУПОРЯДОЧИВАНИЕ]

[ИТОГИ <агрегаты> ПО [ОБЩИЕ] <контрольные точки>]
```

| Ключевое слово | Значение |
|----------------|----------|
| `ВЫБРАТЬ` | SELECT — обязательно, начинает запрос |
| `РАЗРЕШЕННЫЕ` | Применять ограничения RLS. Использовать по умолчанию |
| `РАЗЛИЧНЫЕ` | DISTINCT — убрать дублирующие строки |
| `ПЕРВЫЕ N` | Вернуть только первые N строк (аналог LIMIT — другого способа нет) |
| `ИЗ` | FROM — источники данных |
| `ГДЕ` | WHERE — фильтр строк |
| `СГРУППИРОВАТЬ ПО` | GROUP BY |
| `ИМЕЮЩИЕ` | HAVING — фильтр групп |
| `ОБЪЕДИНИТЬ [ВСЕ]` | UNION [ALL] |
| `УПОРЯДОЧИТЬ ПО` | ORDER BY. `ВОЗР` = ASC, `УБЫВ` = DESC |
| `АВТОУПОРЯДОЧИВАНИЕ` | Автосортировка по представлению (применять редко) |
| `ИТОГИ` | TOTALS — вычислить агрегирующие итоги с подитогами |

Комментарии: `// только однострочные`.

Минимальный пример:

```sql
ВЫБРАТЬ
    Ссылка,
    Наименование
ИЗ
    Справочник.Контрагенты
ГДЕ
    НЕ ПометкаУдаления
```

## Виртуальные таблицы

Вычисляются на лету из данных регистра. **Всегда передавать условия отбора параметрами ВТ, а не в ГДЕ** — критично для производительности.

### Регистр накопления

```sql
// Текущие остатки (без даты = на сейчас):
РегистрНакопления.ОстаткиТоваров.Остатки(, Номенклатура = &Ном)

// Остатки на дату:
РегистрНакопления.ОстаткиТоваров.Остатки(&Дата, Склад = &Склад)

// Обороты за период:
РегистрНакопления.ОстаткиТоваров.Обороты(&НачДата, &КонДата, , Номенклатура = &Ном)

// Остатки и обороты:
РегистрНакопления.ОстаткиТоваров.ОстаткиИОбороты(&НачДата, &КонДата, , , Номенклатура = &Ном)
```

**Суффиксы ресурсов регистра накопления:**

| Виртуальная таблица | Суффикс | Пример |
|---------------------|---------|--------|
| `.Остатки` | `<Ресурс>Остаток` | `КоличествоОстаток` |
| `.Обороты` | `<Ресурс>Оборот` | `КоличествоОборот` |
| `.ОстаткиИОбороты` | `<Ресурс>НачальныйОстаток` | `КоличествоНачальныйОстаток` |
| `.ОстаткиИОбороты` | `<Ресурс>Приход` | `КоличествоПриход` |
| `.ОстаткиИОбороты` | `<Ресурс>Расход` | `КоличествоРасход` |
| `.ОстаткиИОбороты` | `<Ресурс>Оборот` | `КоличествоОборот` |
| `.ОстаткиИОбороты` | `<Ресурс>КонечныйОстаток` | `КоличествоКонечныйОстаток` |

```sql
// Пример — обороты со всеми суффиксами:
ВЫБРАТЬ
    Об.Номенклатура,
    Об.КоличествоПриход,
    Об.КоличествоРасход,
    Об.КоличествоОборот,
    Об.КоличествоНачальныйОстаток,
    Об.КоличествоКонечныйОстаток
ИЗ
    РегистрНакопления.ТоварыНаСкладах.ОстаткиИОбороты(&Нач, &Кон, , , ) КАК Об
```

### Регистр сведений

```sql
// Срез последних (актуальные значения):
РегистрСведений.КурсыВалют.СрезПоследних(&Дата, Валюта = &Валюта)

// Срез первых:
РегистрСведений.КурсыВалют.СрезПервых(&Дата, Валюта = &Валюта)
```

### Регистр бухгалтерии

5 виртуальных таблиц: Остатки, Обороты, ОстаткиИОбороты, ОборотыДтКт, ДвиженияССубконто.

```sql
// Остатки на дату:
РегистрБухгалтерии.Хозрасчетный.Остатки(&Период, , Счет = &Счет)

// Обороты за период:
РегистрБухгалтерии.Хозрасчетный.Обороты(&НачДата, &КонДата, Месяц, , Счет В (&Счета), )

// Остатки и обороты:
РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты(&НачДата, &КонДата, Авто, , , Счет = &Счет)

// Обороты Дт-Кт (детальные корреспонденции):
РегистрБухгалтерии.Хозрасчетный.ОборотыДтКт(&НачДата, &КонДата, , , , )

// Детальные записи с субконто:
РегистрБухгалтерии.Хозрасчетный.ДвиженияССубконто(&НачДата, &КонДата, )
```

**Параметры ВТ регистра бухгалтерии (позиционно):**

| Виртуальная таблица | Параметры |
|---------------------|-----------|
| `.Остатки` | Период, Субконто, Условие |
| `.Обороты` | НачалоПериода, КонецПериода, Периодичность, Субконто, Условие, КорСубконто |
| `.ОстаткиИОбороты` | НачалоПериода, КонецПериода, Периодичность, МетодДополненияПериодов, Субконто, Условие |
| `.ОборотыДтКт` | НачалоПериода, КонецПериода, Периодичность, СубконтоДт, СубконтоКт, Условие |
| `.ДвиженияССубконто` | НачалоПериода, КонецПериода, Условие, Порядок, Первые |

Значения `Периодичность`: Авто, Период, Год, Полугодие, Квартал, Месяц, Декада, Неделя, День, Регистратор, Запись.

**Суффиксы ресурсов регистра бухгалтерии:**

| Виртуальная таблица | Суффикс | Пример |
|---------------------|---------|--------|
| `.Остатки` | `<Ресурс>Остаток` | `СуммаОстаток` |
| `.Остатки` | `<Ресурс>ОстатокДт/Кт` | `СуммаОстатокДт` |
| `.Остатки` | `<Ресурс>РазвернутыйОстатокДт/Кт` | `СуммаРазвернутыйОстатокДт` |
| `.Обороты` | `<Ресурс>Оборот` | `СуммаОборот` |
| `.Обороты` | `<Ресурс>ОборотДт/Кт` | `СуммаОборотДт` |
| `.Обороты` | `<Ресурс>КорОборотДт/Кт` | `СуммаКорОборотДт` |
| `.ОстаткиИОбороты` | `<Ресурс>НачальныйОстатокДт/Кт` | `СуммаНачальныйОстатокДт` |
| `.ОстаткиИОбороты` | `<Ресурс>ОборотДт/Кт` | `СуммаОборотДт` |
| `.ОстаткиИОбороты` | `<Ресурс>КонечныйОстатокДт/Кт` | `СуммаКонечныйОстатокДт` |

Суффиксы без Дт/Кт (`СуммаОстаток`, `СуммаОборот`) — для сбалансированных ресурсов.

```sql
// Пример — остатки и обороты бухрегистра:
ВЫБРАТЬ
    Об.Счет,
    Об.Субконто1,
    Об.СуммаНачальныйОстатокДт КАК НачОстДт,
    Об.СуммаОборотДт,
    Об.СуммаОборотКт,
    Об.СуммаКонечныйОстатокДт КАК КонОстДт
ИЗ
    РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты(
        &НачДата, &КонДата, Авто, , , Счет = &Счет) КАК Об
```

## Псевдонимы таблиц

```sql
Справочник.Номенклатура КАК Товары
```

Псевдонимы — всегда **информативные**, понятные без контекста:

- Нельзя: однобуквенные (`Р`, `Т`) или бессмысленные аббревиатуры (`ВТДок`, `ДокГР`)
- Для длинных имён — осмысленное сокращение: `РасчетыНДФЛ`, `ВедомостиЗП`
- Для временных таблиц — повторить имя ВТ или сократить осмысленно

```sql
// Плохо:
РегистрНакопления.РасчетыНалогоплательщиковСБюджетом КАК Р

// Хорошо:
РегистрНакопления.РасчетыНалогоплательщиковСБюджетом КАК РасчетыНДФЛ
```

Псевдоним обязателен при самосоединении или двойном использовании одной таблицы.

## Иерархические справочники

```sql
// Прямые потомки (один уровень):
ВЫБРАТЬ Наименование
ИЗ Справочник.Номенклатура
ГДЕ Родитель = &Родитель

// Все элементы группы и подгрупп:
ВЫБРАТЬ Наименование
ИЗ Справочник.Номенклатура
ГДЕ Ссылка В ИЕРАРХИИ (&Группа)

// Только листовые элементы (не группы):
ГДЕ ЭтоГруппа = ЛОЖЬ

// Только группы:
ГДЕ ЭтоГруппа = ИСТИНА
```

- `Родитель = &Родитель` — только прямые потомки (один уровень)
- `Ссылка В ИЕРАРХИИ (&Группа)` — все вложенные уровни
- **Не использовать:** `В ИЕРАРХИИ (ПустаяСсылка)` — крайне медленно

## Поля и составные типы

- `*` — выбрать все реальные поля (виртуальные поля не включаются)
- Псевдоним: `<выражение> КАК <Псевдоним>` — уникальны в рамках запроса
- Вложенные поля через точку: `Товары.Номенклатура.Наименование`

### КРИТИЧНО: разыменование полей составного типа

Обращение через точку к полю составного типа создаёт неявные JOIN со **всеми** возможными таблицами. Это резко снижает производительность.

**Всегда сужать тип через ВЫРАЗИТЬ:**

```sql
// Плохо — JOIN ко всем возможным таблицам-регистраторам:
ВЫБРАТЬ Регистратор.Номер ИЗ РегистрНакопления.ОстаткиТоваров

// Хорошо — один JOIN:
ВЫБРАТЬ ВЫРАЗИТЬ(Регистратор КАК Документ.РеализацияТоваровУслуг).Номер
ИЗ РегистрНакопления.ОстаткиТоваров
ГДЕ Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
```

### Обработка NULL

- `ЕСТЬNULL(поле, значение_по_умолчанию)` — для полей из LEFT JOIN
- Проверка NULL: `ЕСТЬ NULL` / `НЕ ЕСТЬ NULL` (не `= NULL`)

## Условия ГДЕ и ИМЕЮЩИЕ

### Операторы

| Оператор | Синтаксис | Примечание |
|----------|-----------|------------|
| Равно | `=` | |
| Не равно | `<>` | |
| Сравнение | `<`, `>`, `<=`, `>=` | |
| И | `И` | |
| ИЛИ | `ИЛИ` | Избегать в ГДЕ — ломает индексы |
| НЕ | `НЕ` | |
| Диапазон | `МЕЖДУ X И Y` | Включительно с обеих сторон |
| В списке | `В (зн1, зн2, ...)` | |
| В подзапросе | `В (ВЫБРАТЬ ...)` | |
| Проверка NULL | `ЕСТЬ NULL` / `НЕ ЕСТЬ NULL` | Не `= NULL` |
| Проверка типа | `ССЫЛКА Документ.Реализация...` | Проверяет тип ссылки |
| Шаблон | `ПОДОБНО "шаблон"` | `%` — любая строка, `_` — один символ |
| ВЫБОР | `ВЫБОР КОГДА ... ТОГДА ... ИНАЧЕ ... КОНЕЦ` | Только в дополнительных условиях |

**Приоритет:** `НЕ` > `И` > `ИЛИ`. Скобки для явного порядка.

### Ключевые правила

- **ИЛИ снижает использование индекса.** Заменять на `В (...)` или разбивать через `ОБЪЕДИНИТЬ ВСЕ`
- **ВЫБОР в ГДЕ:** только в дополнительных (неиндексируемых) условиях
- **Арифметика в ГДЕ:** только в дополнительных условиях
- **ПОДОБНО:** не должен начинаться с `%` или `_` в индексируемом условии

## Соединения

```sql
ИЗ Документ.РеализацияТоваровУслуг КАК Док
    ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Контрагенты КАК Конт
    ПО Док.Контрагент = Конт.Ссылка
```

| Тип | Синтаксис |
|-----|-----------|
| Внутреннее | `ВНУТРЕННЕЕ СОЕДИНЕНИЕ ... ПО` |
| Левое внешнее | `ЛЕВОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ ... ПО` |
| Правое внешнее | `ПРАВОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ ... ПО` |
| Полное внешнее | `ПОЛНОЕ [ВНЕШНЕЕ] СОЕДИНЕНИЕ ... ПО` |

**Правила:**
- **Никогда не использовать вложенные соединения** (JOIN подзапроса, который сам содержит JOIN). Заменять временными таблицами
- Для LEFT JOIN: индексировать поля соединения правой таблицы
- Для INNER JOIN: индексировать поля большей таблицы

## Группировка и итоги

### СГРУППИРОВАТЬ ПО

```sql
ВЫБРАТЬ
    Контрагент,
    СУММА(СуммаДокумента) КАК Итого,
    КОЛИЧЕСТВО(РАЗЛИЧНЫЕ Ссылка) КАК КолДок
ИЗ Документ.РеализацияТоваровУслуг
СГРУППИРОВАТЬ ПО
    Контрагент
ИМЕЮЩИЕ
    СУММА(СуммаДокумента) > 1000
```

Агрегатные функции: `СУММА`, `СРЕДНЕЕ`, `МИНИМУМ`, `МАКСИМУМ`, `КОЛИЧЕСТВО`, `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ ...)`.

Каждое неагрегируемое поле в ВЫБРАТЬ должно быть в СГРУППИРОВАТЬ ПО.

### ИТОГИ

```sql
ИТОГИ СУММА(СуммаДокумента) ПО ОБЩИЕ, Контрагент
```

Вычисляет строки подытогов, вставленные между строками детализации.

**Расширенный синтаксис:**

```sql
ИТОГИ
    СУММА(Количество), СУММА(Сумма)
ПО
    ОБЩИЕ,
    Контрагент,
    ПЕРИОДАМИ(Дата, МЕСЯЦ, &НачДата, &КонДата)
```

`ПЕРИОДАМИ(<поле>, <периодичность>, <начало>, <конец>)` — для полей типа дата. Варианты периодичности: `СЕКУНДА`, `МИНУТА`, `ЧАС`, `ДЕНЬ`, `НЕДЕЛЯ`, `МЕСЯЦ`, `КВАРТАЛ`, `ГОД`, `ДЕКАДА`, `ПОЛУГОДИЕ`.

### Группирующие наборы

Несколько группировок за один проход:

```sql
ВЫБРАТЬ
    Контрагент,
    Номенклатура,
    СУММА(Сумма) КАК Итого
ИЗ Документ.РеализацияТоваровУслуг.Товары
СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ
    (
        (Контрагент),
        (Номенклатура),
        (Контрагент, Номенклатура)
    )
```

Функция `СГРУППИРОВАНОПО(<поле>)` — определить, в рамках какого набора получена строка.

## Временные таблицы

Использовать для разбивки сложных запросов на шаги, устранения вложенных подзапросов, повышения производительности.

```sql
// Шаг 1: собрать элементы во временную таблицу
ВЫБРАТЬ
    Ссылка КАК Номенклатура
ПОМЕСТИТЬ ВТ_Товары
ИЗ
    Справочник.Номенклатура
ГДЕ
    Наименование ПОДОБНО &Маска
ИНДЕКСИРОВАТЬ ПО
    Номенклатура
;
// Шаг 2: получить остатки для этих элементов
ВЫБРАТЬ
    Ост.Номенклатура КАК Номенклатура,
    Ост.КоличествоОстаток КАК Остаток
ИЗ
    РегистрНакопления.ОстаткиТоваров.Остатки(
        ,
        Номенклатура В (ВЫБРАТЬ Номенклатура ИЗ ВТ_Товары)
    ) КАК Ост
```

**Правила:**
- Запросы в пакете разделяются `;`
- `ПОМЕСТИТЬ <Имя>` создаёт ВТ (после списка полей ВЫБРАТЬ, перед ИЗ)
- `ИНДЕКСИРОВАТЬ ПО <поле>` — добавлять для ВТ с >1000 строк, используемых в соединениях или `В`
- Минимизировать объём данных и количество полей ВТ
- Никогда не создавать/удалять ВТ в цикле
- Предпочитать ВТ вложенным подзапросам в условиях соединений

---

## Параметры запроса

Внешние значения, передаваемые в запрос. Синтаксис: `&ИмяПараметра`.

```sql
ВЫБРАТЬ * ИЗ Справочник.Контрагенты ГДЕ Наименование ПОДОБНО &Маска
```

**Правила:**
- Всегда использовать параметры для внешних значений — не конкатенировать строки в текст запроса
- Значения перечислений — через `ЗНАЧЕНИЕ(...)` в тексте запроса, не как параметр: `ГДЕ Тип = ЗНАЧЕНИЕ(Перечисление.ТипыЦен.Оптовая)`
- Дата в параметрах: передавать объект Дата BSL (`Дата(2024, 1, 15)`)
- Булево: `ИСТИНА` / `ЛОЖЬ` в тексте запроса, или `Истина`/`Ложь` как параметр

## Синтаксис ОБЪЕДИНИТЬ

```sql
ВЫБРАТЬ Поле1, Поле2 ИЗ Таблица1
ОБЪЕДИНИТЬ [ВСЕ]
ВЫБРАТЬ Поле1, Поле2 ИЗ Таблица2
```

- `ОБЪЕДИНИТЬ` — убирает дубликаты (медленнее)
- `ОБЪЕДИНИТЬ ВСЕ` — сохраняет дубликаты (быстрее, предпочтительно)
- Количество столбцов должно совпадать
- Имена и типы столбцов берутся из **первого** запроса

---

## ПОДОБНО — шаблоны поиска

```sql
ГДЕ Наименование ПОДОБНО "Шаблон"
```

| Символ | Значение | Пример |
|--------|----------|--------|
| `%` | Любая строка (0+ символов) | `"%молоко%"` — содержит «молоко» |
| `_` | Ровно один символ | `"__-__"` — соответствует «12-34» |
| `[abc]` | Один символ из набора | `"[АБВ]%"` — начинается с А, Б или В |
| `[^abc]` | Один символ НЕ из набора | `"[^0-9]%"` — не начинается с цифры |
| `[a-z]` | Один символ из диапазона | `"[А-Я]%"` — начинается с заглавной кириллицы |

**Символ экранирования:**
```sql
ГДЕ Код ПОДОБНО "%#_%" СПЕЦСИМВОЛ "#"
// ищет буквальное подчёркивание в Код
```

**Производительность:** шаблон не должен начинаться с `%` или `_` в индексируемом условии — такой шаблон запрещает использование индекса.

## ССЫЛКА — проверка типа

Проверяет, указывает ли значение составного типа на конкретную таблицу.

```sql
ГДЕ Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
```

Часто используется вместе с ВЫРАЗИТЬ:

```sql
ВЫБРАТЬ
    ВЫБОР
        КОГДА Регистратор ССЫЛКА Документ.Реализация
            ТОГДА ВЫРАЗИТЬ(Регистратор КАК Документ.Реализация).Контрагент
        КОГДА Регистратор ССЫЛКА Документ.Поступление
            ТОГДА ВЫРАЗИТЬ(Регистратор КАК Документ.Поступление).Контрагент
    КОНЕЦ КАК Контрагент
ИЗ РегистрНакопления.ОстаткиТоваров
```

## Подзапросы в В (IN)

```sql
ГДЕ Контрагент В (
    ВЫБРАТЬ Ссылка ИЗ Справочник.Контрагенты ГДЕ Город = &Город
)
```

**Правила:**
- Подзапрос должен возвращать ровно один столбец
- Избегать сложных подзапросов (соединения, составные типы, вложенные подзапросы) — использовать ВТ
- Для больших наборов фильтра ВТ + `В (ВЫБРАТЬ ... ИЗ ВТ)` эффективнее литерального списка

## ПУСТАЯТАБЛИЦА

Используется в ОБЪЕДИНИТЬ, когда один запрос имеет вложенную таблицу (ТЧ), а другой — нет.

```sql
// Запрос 1 — есть ТЧ Товары
ВЫБРАТЬ Ссылка, Товары.(Номенклатура, Количество)
ИЗ Документ.РеализацияТоваровУслуг

ОБЪЕДИНИТЬ ВСЕ

// Запрос 2 — нет ТЧ, подставляем пустую
ВЫБРАТЬ Ссылка, ПУСТАЯТАБЛИЦА.(Номенклатура, Количество)
ИЗ Документ.ВозвратТоваров
```

Имена внутри `ПУСТАЯТАБЛИЦА.(...)` должны совпадать с псевдонимами реальной ТЧ.

## Типовые паттерны

**1. Поиск по наименованию (нечёткий):**
```sql
ВЫБРАТЬ Ссылка, Наименование
ИЗ Справочник.Контрагенты
ГДЕ Наименование ПОДОБНО &Маска
// параметр Маска = "%рога%"
```

**2. Последние N документов:**
```sql
ВЫБРАТЬ ПЕРВЫЕ 10
    Ссылка, Дата, Номер, СуммаДокумента
ИЗ Документ.РеализацияТоваровУслуг
УПОРЯДОЧИТЬ ПО Дата УБЫВ
```

**3. Текущие остатки (ВТ, без даты = сейчас):**
```sql
ВЫБРАТЬ Номенклатура, КоличествоОстаток
ИЗ РегистрНакопления.ОстаткиТоваров.Остатки(, Номенклатура = &Ном) КАК Ост
```

**4. Срез последних регистра сведений:**
```sql
ВЫБРАТЬ Валюта, Курс
ИЗ РегистрСведений.КурсыВалют.СрезПоследних(&Дата,) КАК Курсы
```

**5. Подсчёт по группе:**
```sql
ВЫБРАТЬ
    Контрагент,
    КОЛИЧЕСТВО(*) КАК Кол
ИЗ Документ.РеализацияТоваровУслуг
СГРУППИРОВАТЬ ПО Контрагент
УПОРЯДОЧИТЬ ПО Кол УБЫВ
```

**6. Проверка существования:**
```sql
ВЫБРАТЬ ПЕРВЫЕ 1 Ссылка
ИЗ Справочник.Контрагенты
ГДЕ ИНН = &ИНН
```

**7. Исключить помеченные на удаление:**
```sql
ГДЕ НЕ ПометкаУдаления
```

**8. Получить структуру таблицы (запрос без строк):**
```sql
ВЫБРАТЬ ПЕРВЫЕ 0 * ИЗ Справочник.Контрагенты
```

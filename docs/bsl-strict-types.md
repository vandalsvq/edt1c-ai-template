# Строгая типизация BSL (// @strict-types)

Руководство по написанию типизированного кода на встроенном языке 1С в среде EDT.

Основано на [методических рекомендациях 1C-Company](https://github.com/1C-Company/v8-code-style/blob/master/docs/checks/code_typification.md)
и адаптировано под соглашения проекта (см. [`../CLAUDE.md`](../CLAUDE.md)).

---

## 1. Аннотация модуля

Первая строка нового модуля до первого семантического объекта (области, процедуры, переменной):

```bsl
// @strict-types

#Область ПрограммныйИнтерфейс
```

**Когда ставить:** все новые модули.
**Когда не ставить:** существующие модули без отдельной задачи на рефакторинг.

---

## 2. Документирование процедур и функций

Комментарий размещается **перед директивой компиляции**:

```bsl
// Возвращает параметры области макета по умолчанию.
//
// Параметры:
//  ИмяОбласти - Строка - имя области в макете.
//
// Возвращаемое значение:
//  см. НовыеПараметрыОбласти
//
&НаСервере
Функция ПараметрыОбластиПоУмолчанию(знач ИмяОбласти)
```

В модуле с `// @strict-types` doc-блок обязателен для **всех** методов — экспортных и неэкспортных, включая обработчики событий. Типы в секциях `Параметры` / `Возвращаемое значение` нужны анализатору EDT для вывода типов в вызывающем коде, поэтому их отсутствие у приватного метода ломает типизацию ничуть не меньше, чем у экспортного.

**Секции:**

| Секция | Обязательна |
|--------|-------------|
| Описание | Для всех методов — одна содержательная строка (не дословный повтор имени) |
| Параметры | Если у метода есть параметры |
| Возвращаемое значение | Для всех `Функция` |
| Пример | Опционально |

Это сознательное исключение из правила «не комментировать по умолчанию» ([`bsl-coding-standards.md`](bsl-coding-standards.md)): doc-блок — не пояснение к коду, а типовая аннотация.

**Единственное послабление:** если назначение метода полностью раскрыто именем, секция `Описание` может быть короткой, но секции `Параметры` / `Возвращаемое значение` с типами опускать нельзя.

```bsl
// Сумма по строкам табличной части.
//
// Параметры:
//  Строки - ТаблицаЗначений - строки с числовым полем Сумма.
//
// Возвращаемое значение:
//  Число
//
&НаКлиентеНаСервереБезКонтекста
Функция ИтогоПоСтрокам(знач Строки)
```

## 3. Параметр `знач`

Входные параметры, которые не изменяются внутри метода, объявляются с `знач`:

```bsl
Функция НайтиЭлемент(знач Ссылка, знач ТипПоиска) Экспорт
```

Ключевое слово пишется в **нижнем регистре** — `знач`, не `Знач`.

## 4. Типизация параметров и возвращаемых значений

### Ссылочные типы — выбор по специфичности

```bsl
// Конкретный тип (предпочтительно):
//  Объект - СправочникСсылка.pw_Макеты

// Вид (если конкретный тип неизвестен):
//  Объект - СправочникСсылка
//  Документ - ДокументСсылка

// Обобщённый (если вид также неизвестен):
//  Элемент - ЛюбаяСсылка
```

### Неопределено как допустимый тип

```bsl
// Параметры:
//  Ссылка - СправочникСсылка.pw_Макеты, Неопределено

// Возвращаемое значение:
//  - СправочникСсылка.pw_Макеты - найденный элемент.
//  - Неопределено - если элемент не найден.
```

### Несколько типов

Через запятую (краткая форма):

```bsl
// Параметры:
//  Значение - Строка, Число - описание применяется ко всем типам
```

С описанием для каждого типа (с новой строки):

```bsl
// Параметры:
//  Значение - Строка - строковое представление.
//           - Число  - числовое значение.
```

## 5. Переменные — инициализация с типом

### Запрет `Перем` без типа

`Перем` без начального значения инициализирует переменную типом `Неопределено` — EDT не отследит последующую смену типа.

НЕПРАВИЛЬНО:

```bsl
Процедура ОбработкаСтрок(Коллекция)
	Перем ТекущаяСсылка;

	Для Каждого Строка Из Коллекция Цикл
		ТекущаяСсылка = Строка.Ссылка;
	КонецЦикла;
	Объект = ТекущаяСсылка.ПолучитьОбъект(); // тип — Неопределено
```

ПРАВИЛЬНО:

```bsl
Процедура ОбработкаСтрок(Коллекция)
	ТекущаяСсылка = Справочники.pw_Макеты.ПустаяСсылка();

	Для Каждого Строка Из Коллекция Цикл
		ТекущаяСсылка = Строка.Ссылка;
	КонецЦикла;
	Объект = ТекущаяСсылка.ПолучитьОбъект();
```

### Запрет смены типа переменной

После инициализации тип переменной не должен меняться.

### Инициализация переменной до цикла/условия

Нельзя инициализировать переменную внутри цикла или условия и использовать её за пределами этого блока — EDT не сможет отследить тип.

### Инлайн-типизация

> **Инлайн-типизация — исключение, а не норма.** Применять только когда невозможно спроектировать код прозрачно для анализатора. В общем случае предпочитать функции-конструкторы.

Когда тип не выводится автоматически (например, результат универсальной функции), указывается в комментарии в строке:

```bsl
Элемент = ПолучитьОбъектПоАдресу(Адрес); // СправочникОбъект.pw_Макеты -
```

Для сложного объекта (Структура, ТЗ, массив из структур) инлайн-типизация **не работает** — тип не помещается в одну строку. Нужна ссылка на конструктор:

```bsl
Данные = ПолучитьИзВременногоХранилища(Адрес); // см. НовыеПараметрыПечати
```

Инлайн-комментарий также используется для **расширения** расчётных типов, которые EDT вывел сам, дополнительным типом, который анализатор не видит:

```bsl
// EDT вычислил Массив|Число из веток кода.
// Добавляем Булево, которое не выводится автоматически:
МояПеременная = ...; // Булево -
```

### Переменные модуля

Типизируются так же, как локальные переменные. Инициализацию выполнять в `ПриСозданииНаСервере` (серверные) или `ПриОткрытии` (клиентские):

```bsl
#Область ОписаниеПеременных

&НаКлиенте
Перем ТекущийИдентификатор; // Число -

&НаКлиенте
Перем КэшПараметров; // см. НовыеПараметрыКэша

#КонецОбласти

...

// Инициализация в обработчике:
ТекущийИдентификатор = -1;
КэшПараметров = НовыеПараметрыКэша();
```

## 6. Структура — инициализация ключей

Ключи структуры инициализировать с пустым значением нужного типа — иначе свойство получает тип `Неопределено` и EDT не отследит смену типа при присвоении.

НЕПРАВИЛЬНО:

```bsl
Параметры = Новый Структура("Ссылка");
Параметры.Ссылка = СправочникОбъект.Ссылка; // тип поля — Неопределено
```

ПРАВИЛЬНО:

```bsl
Параметры = Новый Структура("Ссылка", Справочники.pw_Макеты.ПустаяСсылка());
Параметры.Ссылка = СправочникОбъект.Ссылка;
```

или через `Вставить`:

```bsl
Параметры = Новый Структура;
Параметры.Вставить("Ссылка", СправочникОбъект.Ссылка);
```

**Нельзя** добавлять ключи в структуру через внешний метод и затем использовать их — EDT не видит связи:

```bsl
// НЕПРАВИЛЬНО — МойМодуль.ЗаполнитьПараметры добавляет МоеСвойство, но EDT не знает этого
Параметры = Новый Структура;
МойМодуль.ЗаполнитьПараметры(Параметры);
Если Параметры.МоеСвойство = ... // тип — Неопределено
```

Безопасный доступ к «чужим» ключам структуры:

```bsl
Если Параметры.Свойство("МоеСвойство") Тогда
	МоеСвойство = Параметры["МоеСвойство"]; // СправочникСсылка.pw_Макеты -
КонецЕсли;
```

### Двуаргументная форма `Свойство` — не использовать

`Структура.Свойство("Ключ", Переменная)` не даёт типизации: EDT не анализирует OUT-параметр, переменная остаётся `Неопределено`.

НЕПРАВИЛЬНО:

```bsl
Перем МояПеременная;
Если Параметры.Свойство("МоеСвойство", МояПеременная) Тогда
	МояПеременная = МояПеременная + ""; // тип — Неопределено
КонецЕсли;
```

ПРАВИЛЬНО — инициализировать переменную заранее, затем одноаргументная форма:

```bsl
МояПеременная = "";
Если Параметры.Свойство("МоеСвойство") Тогда
	МояПеременная = Параметры.МоеСвойство; // Строка -
КонецЕсли;
```

### Структура как параметр: обязательна ссылка на конструктор

Если функция получает структуру как параметр, EDT не может вывести её ключи автоматически, если структура создана в другом модуле. Принимающий метод должен указывать ссылку на конструктор:

```bsl
// НЕПРАВИЛЬНО — EDT не знает ключи структуры:
// Параметры:
//  НастройкиПечати - Структура

// ПРАВИЛЬНО — ссылка на конструктор:
// Параметры:
//  НастройкиПечати - см. НовыеНастройкиПечати
Процедура ОбработатьНастройки(НастройкиПечати)
	НастройкиПечати.ИмяШаблона = "Основной"; // EDT знает тип поля
```

## 7. Массив

При обращении к элементам массива — указывать тип элементов.

НЕПРАВИЛЬНО:

```bsl
Список = Новый Массив;
Список.Добавить(Ссылка);
Для Каждого Эл Из Список Цикл
	Объект = Эл.ПолучитьОбъект(); // тип — Неопределено
```

ПРАВИЛЬНО — инлайн-комментарий:

```bsl
Список = Новый Массив; // Массив из СправочникСсылка.pw_Макеты -
Список.Добавить(Ссылка);
Для Каждого Элемент Из Список Цикл
	Объект = Элемент.ПолучитьОбъект();
```

ПРАВИЛЬНО — функция-конструктор:

```bsl
Список = НовыйСписокМакетов();
Список.Добавить(Ссылка);

// Возвращаемое значение:
//  Массив из СправочникСсылка.pw_Макеты
Функция НовыйСписокМакетов()
	Возврат Новый Массив;
КонецФункции
```

В документирующих комментариях:

```bsl
// Параметры:
//  Макеты - Массив из СправочникСсылка.pw_Макеты
```

## 8. Таблица значений и дерево значений

Описывать все колонки. Для параметров экспортных методов — ссылаться на функцию-конструктор, не описывать колонки inline.

ПРАВИЛЬНО — возвращаемое значение:

```bsl
// Возвращаемое значение:
//  ТаблицаЗначений:
//   * Ссылка  - СправочникСсылка.pw_Макеты
//   * Статус  - Число
//   * Ошибка  - Строка
Функция ТаблицаРезультатовПечати()
	...
	Возврат Таблица;
КонецФункции
```

ПРАВИЛЬНО — параметр через ссылку:

```bsl
// Параметры:
//  Таблица - см. ТаблицаРезультатовПечати
Процедура ОбработатьРезультаты(Таблица)
```

Строка таблицы:

```bsl
// Параметры:
//  Строка - СтрокаТаблицыЗначений: см. ТаблицаРезультатовПечати
Процедура ОбработатьСтроку(Строка)
```

Если таблица произвольная, но код обращается к определённым колонкам:

```bsl
// Параметры:
//  Таблица - ТаблицаЗначений - произвольная таблица с полем Ссылка:
//   * Ссылка - ЛюбаяСсылка
Процедура ОбработатьПоСсылке(Таблица) Экспорт
```

## 9. Соответствие и список значений

Для `Соответствие` и `СписокЗначений` нельзя указать типы ключа/значения инлайн — только через функцию-конструктор.

```bsl
// Возвращаемое значение:
//  Соответствие из КлючИЗначение:
//   * Ключ    - Строка
//   * Значение - Массив из ДокументСсылка
Функция НовоеСоответствиеДокументов()
	Возврат Новый Соответствие;
КонецФункции
```

```bsl
// Возвращаемое значение:
//  СписокЗначений из СправочникСсылка.pw_Макеты
Функция НовыйСписокМакетовДляВыбора()
	Возврат Новый СписокЗначений;
КонецФункции
```

При получении из хранилища — ссылка на конструктор:

```bsl
Данные = ПолучитьИзВременногоХранилища(Адрес); // см. НовоеСоответствиеДокументов
```

## 10. Функции-конструкторы и функции-получатели

### Конструктор (`НовыйXxx` / `НоваяXxx`)

Создаёт и возвращает пустой объект данных с инициализированными полями.
Используется когда объект данных создаётся в текущем модуле:

```bsl
// Возвращаемое значение:
//  Структура:
//   * ИмяОбласти  - Строка
//   * ТипОбласти  - Число
//   * Параметры   - Соответствие из КлючИЗначение
Функция НовыеПараметрыОбласти()
	Результат = Новый Структура;
	Результат.Вставить("ИмяОбласти", "");
	Результат.Вставить("ТипОбласти", 0);
	Результат.Вставить("Параметры", Новый Соответствие);
	Возврат Результат;
КонецФункции
```

Вызывающий код:

```bsl
Параметры = НовыеПараметрыОбласти();
Параметры.ИмяОбласти = "Заголовок";
ОбработатьОбласть(Параметры);
```

### Получатель (`ПолучитьXxx` / имя объекта как функция)

Используется когда объект создаётся не в текущем модуле (форма, СКД, запрос), но нужно типизировать результат:

```bsl
// Возвращаемое значение:
//  ДеревоЗначений:
//   * Наименование - Строка
//   * Ключ         - Строка
//   * Уровень      - Число
Функция ДеревоЭлементовОбласти(Форма, ИмяЭлемента)
	Возврат Форма.РеквизитФормыВЗначение(ИмяЭлемента);
КонецФункции
```

**Не создавать фиктивные конструкторы** — только ради ссылки, без реального создания объекта.

## 11. Типы форм и элементов

### Обобщённые типы

```bsl
// Параметры:
//  Форма   - ФормаКлиентскогоПриложения
//  Поле    - ПолеФормы
//  Группа  - ГруппаФормы
//  Таблица - ТаблицаФормы
//  Декор   - ДекорацияФормы
```

### Конкретная форма

Когда известна конкретная форма:

```bsl
// Параметры:
//  Форма - см. Справочник.pw_Макеты.Форма.ФормаЭлемента
```

### Реквизит и элемент конкретной формы

```bsl
// Параметры:
//  Объект  - см. Справочник.pw_Макеты.Форма.ФормаЭлемента.Объект
//  Элемент - см. Справочник.pw_Макеты.Форма.ФормаСписка.Элементы.Список
```

### Расширение типа формы

Для форм объектов, документов, динамических списков:

```bsl
// Параметры:
//  Форма - РасширениеУправляемойФормыДляОбъектов
```

### Описание реквизитов «интерфейсной» формы

Когда общий код рассчитывает на наличие определённых реквизитов/элементов:

```bsl
// Параметры:
//  Форма - ФормаКлиентскогоПриложения:
//   * pw_ОбластьПредпросмотра - ДекорацияФормы
//   * pw_НастройкиПечати      - Структура: см. НовыеНастройкиПечати
```

### Получение и открытие форм

Строковый литерал с именем формы передавать первым параметром — только тогда EDT выведет конкретный тип формы:

```bsl
// ПРАВИЛЬНО — EDT знает тип формы:
Форма = ПолучитьФорму("Справочник.pw_Макеты.Форма.ФормаЭлемента");

// НЕПРАВИЛЬНО — EDT видит только ФормаКлиентскогоПриложения:
ИмяФормы = "Справочник.pw_Макеты.Форма.ФормаЭлемента";
Форма = ПолучитьФорму(ИмяФормы);
```

### Строковый индекс для именованных коллекций

Не обращаться к элементам через строковый индекс напрямую:

```bsl
// НЕПРАВИЛЬНО:
Элементы["Наименование"].Видимость = Ложь;

// ПРАВИЛЬНО — прямое обращение:
Элементы.Наименование.Видимость = Ложь;
```

Если элемент создан программно — присвоить в переменную с инлайн-типом:

```bsl
Элемент = Элементы["pw_ДинамическийЭлемент"]; // ПолеФормы -
Элемент.Видимость = Ложь;
Элемент.Доступность = Истина;
```

## 12. Запросы

Выборку/выгрузку из запроса с динамически формируемым текстом — оборачивать в функцию-получатель:

```bsl
// Возвращаемое значение:
//  ВыборкаИзРезультатаЗапроса:
//   * Ссылка     - СправочникСсылка.pw_Макеты
//   * Наименование - Строка
```

## 13. Сужение типа

Внутри условия `ТипЗнч(...) = Тип("...")` EDT сужает тип переменной до проверяемого:

```bsl
Если ТипЗнч(Объект) = Тип("СправочникОбъект.pw_Макеты") Тогда
	Объект.pw_ТипМакета = ТипМакета; // EDT знает точный тип
КонецЕсли;
```

Условие должно быть простым (без `И`, `ИЛИ` с другими условиями).

## 14. Временное хранилище и другие контейнеры

При получении объекта из хранилища — ссылка на конструктор в инлайн-комментарии:

```bsl
// Помещаем:
ПоместитьВоВременноеХранилище(НовыеПараметрыПечати(), Адрес);

// Получаем с указанием типа:
Параметры = ПолучитьИзВременногоХранилища(Адрес); // см. НовыеПараметрыПечати
```

То же применяется к `ДополнительныеПараметры` у обработчиков оповещения — при необходимости:

```bsl
// ДополнительныеПараметры свойства можно не описывать,
// но при обращении к конкретным полям — указывать тип инлайн:
Ссылка = ДополнительныеПараметры.Ссылка; // СправочникСсылка.pw_Макеты -
```

## 15. Ограничение составных типов

Избегать параметров с несовместимыми типами:
- `Строка` и `СправочникОбъект` — повод для рефакторинга
- `Число` и `Массив` — повод для рефакторинга
- Коллекции (`Массив`, `ТЗ`, `Структура`) и простые типы в одном параметре

Допустимые составные типы: `Строка, Число`, `ЛюбаяСсылка, Неопределено`, несколько конкретных ссылочных типов схожей природы.

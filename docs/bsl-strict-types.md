# Строгая типизация BSL (// @strict-types)

Руководство по написанию типизированного кода на встроенном языке 1С в среде EDT.

Основано на [методических рекомендациях 1C-Company](https://github.com/1C-Company/v8-code-style/blob/master/docs/checks/code_typification.md)
и адаптировано под соглашения проекта (см. [`../CLAUDE.md`](../CLAUDE.md)). Замечания EDT по коду (`SU*`), их причины и
лечение - таблицей в §18.

---

## 1. Аннотация модуля

Первая строка нового модуля до первого семантического объекта (области, процедуры, переменной):

```bsl
// @strict-types

#Область ПрограммныйИнтерфейс
```

**Когда ставить:** все новые модули. **Когда не ставить:** существующие модули без отдельной задачи на рефакторинг (скилл `strict-module`).

---

## 2. Документирование процедур и функций

В модуле с `// @strict-types` doc-блок обязателен для **всех** методов - экспортных, неэкспортных, обработчиков событий: типы в секциях `Параметры` / `Возвращаемое значение` нужны анализатору EDT для вывода типов в вызывающем коде. Это сознательное исключение из правила «не комментировать по умолчанию» ([`bsl-coding-standards.md`](bsl-coding-standards.md)): doc-блок - типовая аннотация, а не пояснение к коду.

Комментарий размещается **перед директивой компиляции**; секции идут в порядке вызова - описание, `Параметры:`, `Возвращаемое значение:`:

```bsl
// Возвращает параметры области макета по умолчанию.
//
// Параметры:
//	ИмяОбласти - Строка - имя области в макете.
//
// Возвращаемое значение:
//	см. НовыеПараметрыОбласти
//
&НаСервере
Функция ПараметрыОбластиПоУмолчанию(знач ИмяОбласти)
```

| Секция | Обязательна |
| --- | --- |
| Описание | Для всех методов - одна содержательная строка (не дословный повтор имени) |
| Параметры | Если у метода есть параметры |
| Возвращаемое значение | Для всех `Функция` |
| Пример | Опционально |

Единственное послабление: если назначение метода полностью раскрыто именем, описание может быть коротким, но секции `Параметры` / `Возвращаемое значение` с типами не опускаются никогда.

Добавляя параметр методу без параметров, секцию `Параметры:` **вставляют перед** `Возвращаемое значение:`, а не дописывают в конец.

### Отступы и выравнивание - табы

Отступы внутри блока - табы (ширина 4) в обоих местах: перед именем параметра и между именем и тире с типом. Имена выравниваются по общей колонке - первый таб-стоп за самым длинным именем; продолжения вариантного типа и строки свойств (`*`) - по своему уровню тем же правилом. Одиночная строка выравнивания не требует - тире отбивается одним пробелом. Описание параметра - одной строкой; если перенос неизбежен, выравнивание продолжения под текстом - исключение, а не правило.

```bsl
// Параметры:
//	Ключ				- Строка - идентификатор соединения.
//	МодульОбработчиков	- ОбщийМодуль - модуль с обработчиками;
//						- Неопределено - обработчики берутся из этого модуля.
//	Событие				- Структура:
//		* Вид		- Строка - вид события.
//		* Момент	- Дата - момент события на клиенте.
```

Пробелы в этих местах в редакторе выглядят так же, поэтому расхождение не видно глазом - проверять (POSIX-классы, а не `-P`: в Git for Windows `grep -P` может отказать по локали):

```bash
grep -nE '^[[:space:]]*// {2,}[^[:space:]]'
grep -nE '^[[:space:]]*//.*[^[:space:]] {2,}-'
```

### Составной тип - каждый тип с новой строки

Когда значение может быть **нескольких типов**, каждый тип - отдельной строкой-элементом: `//` + таб + `-` + тип + `-` + описание, дефис **перед каждым** типом. Инлайн через запятую (`СправочникСсылка.Организации, Неопределено`) допустим, когда описание типов не требуется. Частая ошибка - дефис только у первого типа.

```bsl
// Возвращаемое значение:
//	- СправочникСсылка.Организации - найденная организация
//	- Неопределено - если организация не найдена
Функция НайтиОрганизацию(знач ИНН) Экспорт
```

### Перечень свойств - лесенка отступов по уровням вложенности

Уровень задаётся числом табов после `//`: **1 таб** - имя параметра и объявление типа (`ФиксированнаяСтруктура:`, `ТаблицаЗначений:`); **2 таба** - свойства этой коллекции (`* Имя`); **3 и далее** - свойства вложенных коллекций (`** Имя`). Частая ошибка - свойства на одном уровне с объявлением типа: вложенность перестаёт читаться.

```bsl
// Возвращаемое значение:
//	ФиксированнаяСтруктура:
//		* Объекты		- ФиксированныйМассив из ФиксированнаяСтруктура:
//			** ПолноеИмя	- Строка
//			** Синоним		- Строка
//		* ВсегоНайдено	- Число - находок до применения лимита.
```

### Структура с произвольным набором ключей - `Структура из КлючИЗначение`

Когда состав ключей задаёт не наш код (ответ внешнего API, разобранный JSON, элемент макета), перечислять свойства через `*` нельзя: набор неизвестен, а типизация потребует вернуть каждое заявленное. Описывается пара ключ/значение (словарь, который заполняет наш код, - §9):

```bsl
// Параметры:
//	Сообщение - Структура из КлючИЗначение - разобранный ответ внешнего сервиса:
//		* Ключ		- Строка - имя свойства ответа.
//		* Значение	- Строка - текстовые свойства ответа.
//					- Произвольный - прочие свойства, здесь не читаются.
```

### Ссылочный докблок обёртки

Обёртка над методом другого модуля часто обходится ссылкой `// см. <Модуль>.<Метод>`. Если имя параметра обёртки совпадает с именем метода, на который ведёт ссылка типа в целевом докблоке, тип через ссылку не проносится (SU25, SU30). Такая обёртка получает свой блок `Параметры:`, а функция - и `Возвращаемое значение` (иначе SU28):

```bsl
// Плохо - обёртка со ссылочным докблоком: SU25 и SU30 на НастройкиПровайдера
// см. ОбработкаОбъект.prj_Настройки.ЗаписатьНастройкиПровайдера
Функция ЗаписатьНастройкиПровайдера(знач НастройкиПровайдера) Экспорт

// Хорошо - свой блок у обёртки:
// Параметры:
//	НастройкиПровайдера - Структура: см. prj_НастройкиКлиентСервер.НастройкиПровайдера
//
// Возвращаемое значение:
//	Булево - записаны ли настройки
Функция ЗаписатьНастройкиПровайдера(знач НастройкиПровайдера) Экспорт
```

### Ссылка на набор значений в описании параметра

`см.` в любом месте описания EDT читает как ссылку на тип: если строковый параметр берёт значения из набора (функции общего модуля, которая возвращает структуру допустимых строк), «см. prj_Перечисления.X» превращает тип в `Структура` набора, и вызов со строкой даёт SU24. Набор называется словами: `Канал - Строка - канал из набора prj_Перечисления.КаналИнструментов.`

### Аннотация типа для ОбъектXDTO

`ОбъектXDTO("ИмяТипа")` и `ФабрикаXDTO.Создать(...)` возвращают абстрактный `ОбъектXDTO` без полей (SU83 на каждое поле, SU15 на методы коллекций). Сразу после вызова - комментарий с полным именем типа; в докблоках возвращаемого значения - та же аннотация (`ОбъектXDTO - см. XDTOПакет.prj_Schema.Template`):

```bsl
ПриемникXDTO = ОбъектXDTO("Template"); // см. XDTOПакет.prj_Schema.Template
ТипInfo = ФабрикаXDTO.Тип(ПространствоИмен, "Info");
ОбъектInfo = ФабрикаXDTO.Создать(ТипInfo); // см. XDTOПакет.prj_Schema.Info
```

Пакет указывается тот, из которого создан объект.

## 3. Параметр `знач`

`знач` защищает **привязку** параметра (нельзя переназначить его другим объектом), но **не содержимое**. По умолчанию все входные параметры объявляются с `знач` - и простые типы, и коллекции; не городить обходные `?()`/локальные переменные, чтобы «сохранить оригинал». Пишется в нижнем регистре.

- **Простой тип** (Строка, Число, Дата, Булево) с `знач` - копия: переназначение тем же типом ради нормализации (`Идентификатор = ВРег(СокрЛП(Идентификатор))`) идиоматично.
- **Ссылочный тип** (Структура, Массив, ТаблицаЗначений, Соответствие) с `знач` **не клонируется**: мутация содержимого видна снаружи - допустимо и часто намеренно (подробнее - [`bsl-coding-standards.md`](bsl-coding-standards.md), «Структуры и коллекции передаются по ссылке»). Запрещена только смена типа переменной.

Исключения из «`знач` по умолчанию»:

- **out-параметр** - метод присваивает ему новое значение для вызывающего (накопитель, `Результат = ...`);
- **платформенные сигнатуры** - `Отказ`, `СтандартнаяОбработка`, `ДанныеВыбора` в обработчиках событий: платформа читает их **после** возврата, `знач` сломает механизм. Обработчики оповещений (`Результат`, `ДопПараметры`) и команд (`Команда`) тоже без `знач` - сигнатуру диктует платформа;
- **параметр, который заполняет метод, вызываемый с клиента на сервер** - раздел ниже.

### Граница клиент → сервер: `знач` меняет поведение, а не только контракт

Вызов серверного метода **с клиента** (общий модуль «Вызов сервера», `&НаСервере`, `&НаСервереБезКонтекста`) - не передача по ссылке: параметры сериализуются, на сервер приезжает копия.

| Параметр | Поведение на границе |
| --- | --- |
| **без `знач`** | платформа сериализует значение обратно и присваивает переменной вызывающего - заполнение на сервере на клиенте **видно** (ценой трафика в обе стороны) |
| **со `знач`** | обратной передачи нет, изменения остаются на сервере |

`знач` у параметра, который серверный метод **заполняет**, тихо ломает сценарий: ошибки нет, клиент получает исходные данные. Внутри одного тира тот же код работает - дефект находится долго. Правильно - возвращать результат функцией; если возвращаемое значение занято, допустим out-параметр без `знач` с пометкой в `Параметры:`, что параметр заполняется методом, либо структура с обоими значениями:

```bsl
// Плохо: Контекст.ИмяРасширения на клиент не вернётся
Функция ПодготовитьКонтекст(знач Контекст) Экспорт
	Контекст.ИмяРасширения = ОбъектРасширения.Имя;
	Возврат "";
КонецФункции

// Хорошо
Функция ПодготовитьКонтекст(знач Контекст) Экспорт
	Контекст.ИмяРасширения = ОбъектРасширения.Имя;
	Возврат Контекст;
КонецФункции
```

Следствия: параметр без `знач` возвращается вызывающему **копией**, а не тем же объектом - локальная переменная, взятая из реквизита объекта, заполненное сервером в реквизит не донесёт, записать нужно явно; сборку и обработку данных дешевле держать в `КлиентСервер`-модуле на вызывающей стороне, чем гонять коллекцию на сервер ради мутации.

## 4. Типизация параметров и возвращаемых значений

### Ссылочные типы - выбор по специфичности

Конкретный тип (`СправочникСсылка.prj_Макеты`) предпочтительно; вид (`СправочникСсылка`, `ДокументСсылка`), если конкретный неизвестен; `ЛюбаяСсылка`, если неизвестен и вид.

### Неопределено как допустимый тип

```bsl
// Параметры:
//	Ссылка - СправочникСсылка.prj_Макеты, Неопределено

// Возвращаемое значение:
//	- СправочникСсылка.prj_Макеты - найденный элемент.
//	- Неопределено - если элемент не найден.
```

**Структура со свойствами или Неопределено: Неопределено первым.** Если структура расписана свойствами прямо в докблоке, в обратном порядке EDT считает свойства продолжением последнего варианта и даёт SU24 на каждом `Возврат Неопределено`. Структура через конструктор (`- Структура: см. НовыйМакет`) порядку не чувствительна.

```bsl
// Возвращаемое значение:
//	- Неопределено - макета нет.
//	- Структура - найденный макет:
//		* Ссылка			- СправочникСсылка.prj_Макеты
//		* Наименование		- Строка
```

### Несколько типов

Через запятую, когда описание общее (`Значение - Строка, Число - описание`); с описанием для каждого - строками-элементами (§2, «Составной тип»).

### Объект метаданных: общий тип плюс вид, у которого есть свойство

`ОбъектМетаданных` не несёт свойств конкретного вида (`ТабличныеЧасти`, `Измерения`, `ДлинаКода`). Сужать параметр до одного вида нельзя - метод работает с любым; в шапке к общему типу добавляется вид, у которого читаемое свойство есть, **минимальным покрытием** фактически читаемых свойств. Методу, который объект только передаёт дальше, союз не нужен. Элемент цикла и промежуточная переменная получают вид инлайн-подсказкой.

```bsl
// Параметры:
//	ОбъектМетаданных	- ОбъектМетаданных - найденный объект.
//						- ОбъектМетаданныхДокумент

Для Каждого Реквизит Из ТабличнаяЧасть.СтандартныеРеквизиты Цикл // ОбъектМетаданныхРеквизит
МетаКоллекция = Метаданные[ИмяКоллекции]; // КоллекцияОбъектовМетаданных
```

## 5. Переменные - инициализация с типом

- **`Перем` без типа запрещён**: переменная получает тип `Неопределено`, и EDT не отследит смену. Инициализировать значением нужного типа: `ТекущаяСсылка = Справочники.prj_Макеты.ПустаяСсылка();`.
- **Смена типа переменной запрещена** после инициализации.
- **Инициализация до цикла/условия**: переменная, инициализированная внутри блока и используемая за его пределами, тип теряет.

### Инлайн-типизация

> Исключение, а не норма: применять, когда код нельзя спроектировать прозрачно для анализатора. В общем случае - функции-конструкторы (§10).

Когда тип не выводится автоматически (результат универсальной функции), он указывается в комментарии в строке; для сложного объекта (Структура, ТЗ, массив из структур) инлайн не работает - нужна ссылка на конструктор. Инлайн также расширяет расчётный тип типом, который анализатор не видит. Подсказка привязывается к **последней строке оператора**, поэтому длинный вызов можно перенести:

```bsl
Элемент = ПолучитьОбъектПоАдресу(Адрес); // СправочникОбъект.prj_Макеты -
Данные = ПолучитьИзВременногоХранилища(Адрес); // см. НовыеПараметрыПечати
МояПеременная = ...; // Булево -
Настройки = prj_СлужебныйКлиентСервер.ПрочитатьНастройкиРаздела(
	Разделы.Общие); // Структура: см. prj_СлужебныйКлиентСервер.СписокНастроекРазделаОбщие
```

Инлайн-подсказка уместна там, где тип источника неизвестен, а не поверх объявленного возврата промежуточной функции, и **не переносится в тип свойства структуры** (оба случая - SU24, §18).

### Переменные модуля

Типизируются так же; инициализация - в `ПриСозданииНаСервере` (серверные) или `ПриОткрытии` (клиентские):

```bsl
#Область ОписаниеПеременных

&НаКлиенте
Перем ТекущийИдентификатор; // Число -

&НаКлиенте
Перем КэшПараметров; // см. НовыеПараметрыКэша

#КонецОбласти
```

## 6. Структура - инициализация ключей

Ключи инициализировать значением нужного типа (`Новый Структура("Ссылка", Справочники.prj_Макеты.ПустаяСсылка())` или через `Вставить`), иначе свойство получает тип `Неопределено`. Ключи, добавленные внешним методом (`МойМодуль.ЗаполнитьПараметры(Параметры)`), EDT не видит; безопасный доступ к «чужим» ключам:

```bsl
Если Параметры.Свойство("МоеСвойство") Тогда
	МоеСвойство = Параметры["МоеСвойство"]; // СправочникСсылка.prj_Макеты -
КонецЕсли;
```

### Структура без перечня свойств: ключ - обходом, а не литералом

У структуры, описанной как `Структура из КлючИЗначение` без перечня свойств (JSON Schema аргумента, где `enum` есть не у каждого), чтение `Схема["enum"]` даёт SU235. Ключ разбирается обходом `Для Каждого ПолеСхемы Из СхемаАргумента Цикл` с проверкой `ПолеСхемы.Ключ = "enum"`. Если состав ключей известен заранее, лучше описать его в конструкторе (§10).

### Двуаргументная форма `Свойство` - не использовать

`Структура.Свойство("Ключ", Переменная)` не даёт типизации: EDT не анализирует OUT-параметр. Инициализировать переменную заранее, затем одноаргументная форма и чтение через точку:

```bsl
МояПеременная = "";
Если Параметры.Свойство("МоеСвойство") Тогда
	МояПеременная = Параметры.МоеСвойство; // Строка -
КонецЕсли;
```

### Структура как параметр: обязательна ссылка на конструктор

Структуру, созданную в другом модуле, EDT не разберёт по параметру `Структура`; принимающий метод указывает `НастройкиПечати - см. НовыеНастройкиПечати`. Границы ссылки `см.`:

- **цель - возвращаемое значение метода**, экспортного, если модуль другой. Ссылка на параметр другого метода не разрешается: тип остаётся неизвестным, обход даёт SU83 на `Ключ` / `Значение`. Тип параметра объявляется прямо;
- **раскрывается один уровень**: `* Реквизит - Структура: см. Метод` хватает, пока свойство передаётся дальше целиком; для `Реквизит.Поле.Получить(...)` состав расписывается через `**` в том методе, где идёт обращение;
- **объявленный тип совпадает с записываемым**: `ФиксированнаяСтруктура` там, где код пишет результат функции с типом `Структура`, даёт SU91 и SU213.

## 7. Массив

При обращении к элементам указывать тип элементов - инлайн-комментарием или функцией-конструктором:

```bsl
Список = Новый Массив; // Массив из СправочникСсылка.prj_Макеты -

// Возвращаемое значение:
//	Массив из СправочникСсылка.prj_Макеты
Функция НовыйСписокМакетов()
	Возврат Новый Массив;
КонецФункции
```

В докблоках: `Макеты - Массив из СправочникСсылка.prj_Макеты`.

`Произвольный` **не** пересекается с `ЛюбаяСсылка`: перед передачей нетипизированного значения в параметр `ЛюбаяСсылка` оно сужается инлайном (`Свойство = Значение; // ЛюбаяСсылка`), иначе SU70.

## 8. Таблица значений и дерево значений

Описывать все колонки. Для параметров экспортных методов - ссылаться на функцию-конструктор, не описывать колонки inline:

```bsl
// Возвращаемое значение:
//	ТаблицаЗначений:
//		* Ссылка	- СправочникСсылка.prj_Макеты
//		* Статус	- Число
Функция ТаблицаРезультатовПечати()

// Параметры:
//	Таблица			- см. ТаблицаРезультатовПечати
//	Строка			- СтрокаТаблицыЗначений: см. ТаблицаРезультатовПечати
//	СтрокаМакета	- СтрокаТаблицыЗначений: см. Справочники.prj_Сборки.МакетыПоСборке
```

Таблицу из модуля менеджера ссылка называет через менеджер объекта, как в коде вызова. Произвольная таблица, у которой код читает определённые колонки, - `ТаблицаЗначений - произвольная таблица с полем Ссылка:` и строка `* Ссылка - ЛюбаяСсылка`.

## 9. Соответствие, структура-словарь и список значений

Типы ключа/значения указываются только через функцию-конструктор:

```bsl
// Возвращаемое значение:
//	Соответствие из КлючИЗначение:
//		* Ключ		- Строка
//		* Значение	- Массив из ДокументСсылка
Функция НовоеСоответствиеДокументов()
	Возврат Новый Соответствие;
КонецФункции

// Возвращаемое значение:
//	СписокЗначений из СправочникСсылка.prj_Макеты
Функция НовыйСписокМакетовДляВыбора()
	Возврат Новый СписокЗначений;
КонецФункции
```

Параметризованной формы `КлючИЗначение(Тип, Тип)` в языке нет - ни в docblock, ни в инлайне: `Кэш = Новый Соответствие; // Соответствие из КлючИЗначение` без типов либо ссылка на конструктор. При получении из хранилища - `// см. НовоеСоответствиеДокументов`.

### Структура-словарь

`Структура`, у которой состав ключей определяется в рантайме, документируется так же, как `Соответствие`, - через `из КлючИЗначение` с описанием `Ключ` / `Значение`. Структура с фиксированным составом полей описывается перечислением полей (§10), `из КлючИЗначение` к ней не применяется. Внутри описания родительской структуры уровень вложенности растёт (`**`):

```bsl
// Возвращаемое значение:
//	Структура:
//		* Выполнено			- Булево - текст запроса успешно обработан
//		* ПараметрыЗапроса	- Структура из КлючИЗначение:
//			** Ключ		- Строка - имя параметра
//			** Значение	- Структура: см. ОписаниеПараметраЗапроса
```

Фиксированные варианты аннотируются теми же конструкциями: `ФиксированноеСоответствие из КлючИЗначение`, `ФиксированнаяСтруктура`.

### Обход словаря

Элемент цикла `Для Каждого ... Из` по `Соответствие` или структуре-словарю имеет тип `КлючИЗначение`. Тип извлечённого значения EDT не выводит - уточнять инлайн-комментарием или ссылкой `см.`:

```bsl
Для Каждого ДанныеПоля Из СтрокиПоПолю Цикл
	ИмяПоля		= ДанныеПоля.Ключ;
	СтрокаПлана	= ДанныеПоля.Значение; // СтрокаТаблицыЗначений: см. ШаблонПланаАгрегатов
КонецЦикла;
```

## 10. Функции-конструкторы и функции-получатели

**Конструктор** (`НовыйXxx` / `НоваяXxx`) создаёт и возвращает пустой объект с инициализированными полями - когда объект данных создаётся в текущем модуле:

```bsl
// Возвращаемое значение:
//	Структура:
//		* ИмяОбласти	- Строка
//		* ТипОбласти	- Число
//		* Параметры		- Соответствие из КлючИЗначение
Функция НовыеПараметрыОбласти()
	Результат = Новый Структура;
	Результат.Вставить("ИмяОбласти"	, "");
	Результат.Вставить("ТипОбласти"	, 0);
	Результат.Вставить("Параметры"	, Новый Соответствие);
	Возврат Результат;
КонецФункции
```

**Получатель** (`ПолучитьXxx` / имя объекта как функция) - когда объект создаётся не в текущем модуле (форма, СКД, запрос), но нужно типизировать результат: `Функция ДеревоЭлементовОбласти(Форма, ИмяЭлемента)` с расписанными колонками возвращает `Форма.РеквизитФормыВЗначение(ИмяЭлемента)`.

**Не создавать фиктивные конструкторы** - только ради ссылки, без реального создания объекта.

## 11. Типы форм и элементов

```bsl
// Обобщённые типы:
//	Форма	- ФормаКлиентскогоПриложения
//	Поле	- ПолеФормы
//	Группа	- ГруппаФормы
//	Таблица	- ТаблицаФормы
//	Декор	- ДекорацияФормы
// Конкретная форма, её реквизит и элемент:
//	Форма	- см. Справочник.prj_Макеты.Форма.ФормаЭлемента
//	Объект	- см. Справочник.prj_Макеты.Форма.ФормаЭлемента.Объект
//	Элемент	- см. Справочник.prj_Макеты.Форма.ФормаСписка.Элементы.Список
// Расширение типа для форм объектов, документов, списков:
//	Форма	- РасширениеУправляемойФормыДляОбъектов
```

Тип формы - `ФормаКлиентскогоПриложения`, не устаревшее `УправляемаяФорма`.

### Описание реквизитов «интерфейсной» формы

Когда общий код рассчитывает на определённые реквизиты или элементы, они перечисляются свойствами параметра `Форма`. Так же объявляется реквизит, который форма получает программно (`ИзменитьРеквизиты`): обращение к нему даёт SU83, а свойство у параметра снимает замечание без индексатора и без `@skip-check`. Метод, который реквизит создаёт, объявляет его состав, остальные ссылаются через `см.`.

```bsl
// Параметры:
//	Форма - ФормаКлиентскогоПриложения:
//		* prj_ОбластьПредпросмотра	- ДекорацияФормы
//		* prj_НастройкиПечати		- Структура: см. НовыеНастройкиПечати
//		* _КопияДанныхФормы_		- Произвольный - служебный реквизит, создаётся этим методом.
```

### Получение и открытие форм

Строковый литерал с именем формы - первым параметром `ПолучитьФорму("Справочник.prj_Макеты.Форма.ФормаЭлемента")`: только тогда EDT выводит конкретный тип формы; через переменную с именем - лишь `ФормаКлиентскогоПриложения`.

### Строковый индекс для именованных коллекций

Не `Элементы["Наименование"]`, а `Элементы.Наименование`. Элемент, созданный программно, - в переменную с инлайн-типом: `Элемент = Элементы["prj_ДинамическийЭлемент"]; // ПолеФормы -`.

## 12. Запросы

**Состав полей выборки типизация из текста запроса не выводит** - ни при динамически собранном тексте, ни при литерале в той же процедуре. Поля берутся только из doc-описания метода, который возвращает выборку: выполнение запроса выносится в метод-исполнитель, поля перечисляются в его `Возвращаемое значение` - **все**, которые запрос может вернуть, включая появляющиеся в отдельных ветках сборки текста; разброс типов - строками-элементами:

```bsl
// Возвращаемое значение:
//	ВыборкаИзРезультатаЗапроса:
//		* Ссылка		- СправочникСсылка.prj_Макеты
//		* Наименование	- Строка
//		* Код			- Строка
//						- Число - у вида может быть числовой код.
//
Функция ВыборкаМакетовДляПечати(знач ОтборПараметры)
	ТекстЗапроса = ТекстЗапросаМакетов(ОтборПараметры);
	Запрос = Новый Запрос(ТекстЗапроса);
	РезультатЗапроса = Запрос.Выполнить();
	Возврат РезультатЗапроса.Выбрать();
КонецФункции
```

Без обёртки `Выборка.<поле>` остаётся нераспознанным: подсказка не предлагает, опечатку никто не поймает, тип приходится дописывать инлайном у каждого присваивания. То же относится к `Выгрузить()`: таблицу описывает doc-блок метода-исполнителя, а не текст запроса.

## 13. Сужение типа

Внутри простого условия `ТипЗнч(Объект) = Тип("СправочникОбъект.prj_Макеты")` EDT сужает тип переменной до проверяемого. Условие без `И` / `ИЛИ` с другими условиями.

## 14. Временное хранилище и другие контейнеры

При получении из хранилища - ссылка на конструктор инлайном: `Параметры = ПолучитьИзВременногоХранилища(Адрес); // см. НовыеПараметрыПечати`. То же у `ДополнительныеПараметры` обработчиков оповещения при обращении к конкретным полям: `Ссылка = ДополнительныеПараметры.Ссылка; // СправочникСсылка.prj_Макеты -`.

## 15. Реквизит объекта, объявленный без типа

Реквизит с пустым составом типов (`<type/>` в MDO) даёт SU83 на каждом обращении через точку; объявление типа владельца не помогает. Лечится чтением по имени в служебном аксессоре с объявленным возвращаемым значением - индексное обращение SU83 не вызывает; запись - парная процедура (`Объект[ИмяРеквизита] = Значение;`):

```bsl
// Возвращаемое значение:
//	Структура: см. НовыйКонтекст
Функция КонтекстОбъекта(знач Объект)
	Возврат Объект[ИмяРеквизитаКонтекст()];
КонецФункции
```

**Локальная переменная держит ссылку, а не реквизит**: если между получением и использованием вызывается метод, который перезаписывает реквизит, переменная указывает на прежний объект. После вызова сервера без `знач` заполненное приходит копией - вернуть в реквизит явно (§3).

**Экспортная переменная модуля объекта.** Запись через точку (`ОбработкаОбъект.ПрефиксКаталога = ...`) даёт тот же SU83: типы свойств объекта EDT берёт из MDO. Инлайн у объявления видит только свой модуль, индексатор в рантайме не работает. Пути три: парный экспортный метод-установщик, отказ от записи (значение совпадает с дефолтом объекта) либо точечный `@skip-check property-return-type` с разрешения владельца.

## 16. Ограничение составных типов

Избегать несовместимых типов в одном параметре: `Строка` и `СправочникОбъект`, `Число` и `Массив`, коллекция и простой тип - повод для рефакторинга. Допустимо: `Строка, Число`, `ЛюбаяСсылка, Неопределено`, несколько ссылочных типов схожей природы.

---

## 17. Тип параметра неэкспортного метода выводится и из мест вызова

У неэкспортного метода EDT берёт тип параметра не только из докблока, но и из того, что передают в вызовах внутри модуля. Значение `Соответствие.Получить(...)` - `Произвольный` (или `Неопределено`), и такой аргумент размывает объявленный тип: замечания появляются уже в теле метода. Значение приводится к объявленному типу в месте вызова - `НовоеДействие("", Строка(Класс), Ложь)` - когда пустое значение допустимо и проверяется дальше; если отсутствие ключа - ошибка, проверить `Неопределено` до вызова.

## 18. Ловушки анализатора EDT: код замечания, причина, лечение

Замечания `get_diagnostics` ищутся здесь по коду. Нумерация `SU*` - плагина codepilot1c, в `@skip-check` её писать нельзя (§19).

## 19. Подавление проверки EDT точечно: `.suppress` и `Default.cset`

Решение о подавлении - владельца (CLAUDE.md, «Строгая типизация»). Когда оно есть:

- **один объект** - EDT создаёт файл `<Имя>.suppress` рядом с объектом в `src/` (`src/CommonModules/prj_Перечисления/prj_Перечисления.suppress`, запись `<suppressions key="com.e1c.v8codestyle.md:common-module-name-client-server" value="true"/>`). Файл коммитится, иначе подавление остаётся на одной машине;
- **проверка целиком для проекта** - `.settings/Default.cset` (JSON, `"<id-проверки>": { "enabled": false }`, в git). Исключений по объектам внутри `.cset` нет. Что реально записал EDT, смотреть в дереве;
- **коды `SU*`** - нумерация плагина codepilot1c, в `@skip-check` их писать нельзя; неверный id EDT молча игнорирует.

Id проверки по тексту ошибки: jar `com.e1c.v8codestyle.bsl` из `bundles.info` активной установки EDT, в нём `messages_ru.properties` даёт класс проверки по тексту, строковые константы класса (`re.findall(rb'[ -~]{4,}')` по `.class`; `strings` на macOS на них падает) - id вида `method-too-many-params`. Тексты проверок метаданных - `check.descriptions/ru/*.html` в jar `com.e1c.v8codestyle.md`.

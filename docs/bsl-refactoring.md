# Правила рефакторинга BSL

---

## Подход

1. **Top-down анализ** — сначала понять бизнес-логику: построить цепочку вызовов и проследить поток данных.
2. **Bottom-up рефакторинг** — начать с низкоуровневых утилитарных функций.
3. **Интеграция** — встроить обновлённые компоненты в высокоуровневые процедуры.

---

## Когда рефакторить

| Критерий | Порог |
|---|---|
| Цикломатическая сложность | >15 (количество независимых путей выполнения) |
| Длина функции | >200 строк |
| Дублирование кода | 3+ повторения одного блока |
| Уровень вложенности | >3 уровней Если/Цикл |
| Количество параметров | >5 |
| God-модуль | >2000 строк |

Не рефакторить код, который не затронут текущей задачей (если не запрошено явно).

---

## Техники

### 1. Извлечение метода

Выделить логически самостоятельный блок в отдельную процедуру/функцию:

```bsl
// До:
Процедура ОбработатьДокумент(Документ)
    // ... 50 строк валидации ...
    // ... 80 строк расчёта сумм ...
    // ... 30 строк записи движений ...
КонецПроцедуры

// После:
Процедура ОбработатьДокумент(Документ)
    ПроверитьКорректность(Документ);
    РассчитатьСуммы(Документ);
    ЗаписатьДвижения(Документ);
КонецПроцедуры
```

### 2. Guard clauses — ранний выход

Заменить вложенные `Если` на проверки в начале с ранним выходом:

```bsl
// Плохо: глубокая вложенность
Если Условие1 Тогда
    Если Условие2 Тогда
        Если Условие3 Тогда
            // Логика
        КонецЕсли;
    КонецЕсли;
КонецЕсли;

// Хорошо: ранний выход
Если НЕ Условие1 Тогда
    Возврат;
КонецЕсли;
Если НЕ Условие2 Тогда
    Возврат;
КонецЕсли;
Если НЕ Условие3 Тогда
    Возврат;
КонецЕсли;
// Логика
```

Ранний выход в цикле через `Продолжить`:

```bsl
// Плохо:
Для Каждого Строка Из ТаблицаДанных Цикл
    Если Строка.Активна Тогда
        Если ЗначениеЗаполнено(Строка.Контрагент) Тогда
            ОбработатьСтроку(Строка);
        КонецЕсли;
    КонецЕсли;
КонецЦикла;

// Хорошо:
Для Каждого Строка Из ТаблицаДанных Цикл
    Если НЕ Строка.Активна Тогда
        Продолжить;
    КонецЕсли;
    Если НЕ ЗначениеЗаполнено(Строка.Контрагент) Тогда
        Продолжить;
    КонецЕсли;
    ОбработатьСтроку(Строка);
КонецЦикла;
```

### 3. Консолидация дублирующего кода

Повторяющийся блок (3+ раз) — выносить в общий метод с параметрами:

```bsl
// До: три одинаковых блока обхода результата запроса

// После:
Процедура ОбработатьРезультатЗапроса(Запрос)
    РезультатЗапроса = Запрос.Выполнить();
    Выборка = РезультатЗапроса.Выбрать();
    Пока Выборка.Следующий() Цикл
        ОбработатьЗапись(Выборка);
    КонецЦикла;
КонецПроцедуры
```

### 4. Замена магических значений

Выносить литералы в именованные переменные:

```bsl
// До:
Если ДнейПросрочки > 30 Тогда
    Штраф = Сумма * 0.01;
КонецЕсли;

// После:
МаксДнейБезШтрафа = 30;
СтавкаШтрафа      = 0.01;

Если ДнейПросрочки > МаксДнейБезШтрафа Тогда
    Штраф = Сумма * СтавкаШтрафа;
КонецЕсли;
```

### 5. Кеширование повторных вычислений

Использовать `Соответствие` как кеш для дорогих операций в цикле — см. [`bsl-anti-patterns.md`](bsl-anti-patterns.md) п.9.

### 6. Батчинг клиент-серверных переходов

Собирать данные на клиенте, передавать одним вызовом — см. [`bsl-anti-patterns.md`](bsl-anti-patterns.md) п.6.

### 7. Переиспользование существующего кода

Перед написанием нового кода проверять общие модули и БСП. Например, `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` вместо отдельного запроса.

### 8. Декомпозиция при доработке существующего метода

При добавлении нового блока логики в существующий метод — выделять его в отдельный изолированный метод, а не встраивать внутрь. Исходная функция остаётся тонкой обёрткой; новая логика живёт рядом.

Правила:

- Новый блок логики в существующей функции → отдельный метод, вызываемый из исходной.
- Построение структур-«контрактов» (результат функции, промежуточная структура) → отдельная функция-конструктор (по образцу существующих `СхемаНаборДанныхКоллекция`, `ШаблонТаблицыДанныхНабора` и т.п.).
- Выделенный метод может «ничего не делать», если вход пустой — тогда ранний выход внутри него, а не условная ветка в исходной функции.
- Не добавлять в сигнатуру существующей функции новые флаги-переключатели — лучше новая функция рядом.

```bsl
// Плохо: в существующую функцию добавляется новый блок расчётов.
Функция НаборДанныхКоллекция(знач СтрокаНабора, знач ДанныеНабора)
    // ... существующая сборка коллекции ...

    // Новый блок (50 строк расчёта агрегатов) — усложняет функцию.
    Для Каждого СтрокаПлана Из ПланАгрегатов Цикл
        // ...
    КонецЦикла;

    // ... сборка результата ...
КонецФункции

// Хорошо: новая логика вынесена; исходная функция остаётся короткой.
Функция НаборДанныхКоллекция(знач СтрокаНабора, знач ДанныеНабора)
    // ... существующая сборка коллекции ...

    Итоги = РассчитатьИтогиНабора(СтрокаНабора, Коллекция);

    // ... сборка результата ...
КонецФункции

Функция РассчитатьИтогиНабора(знач СтрокаНабора, знач Коллекция)
    Итоги = Новый Структура;
    Если НЕ ЕстьРаботаДляНабора(СтрокаНабора) Тогда
        Возврат Итоги;
    КонецЕсли;
    // ... расчёт, заполнение Итоги ...
    Возврат Итоги;
КонецФункции
```

Функцию, возвращающую результат, предпочитать процедуре с «out-параметром». Вызов `Итоги = Рассчитать(...)` читается яснее, чем `Рассчитать(..., Итоги)` — у выделенного метода нет неявного побочного эффекта на внешнюю переменную.

---

## Принципы

- **Сохранять поведение** — рефакторинг не меняет что делает код, только как
- **Атомарные шаги** — каждое изменение проверяемо отдельно
- **Ясность важнее краткости** — не превращать понятный код в «умный»
- **Не over-engineer** — не создавать абстракции для одноразовых операций

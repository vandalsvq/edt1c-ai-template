# Промпт первичной инициализации проекта

Этот документ — пошаговая инструкция для **Claude Code**, как настроить новый проект, созданный из шаблона `edt1c-ai-template`. Используется один раз сразу после клонирования.

## Подготовка пользователя (до запуска Claude)

Перед запуском промпта выполните три действия вручную:

1. **Склонируйте шаблон в свой проект.**

   ```bash
   cp -r edt1c_ai_template my-project
   cd my-project
   rm -rf .git && git init
   ```

   Или используйте «Use this template» на GitHub, затем `git clone <url>`.

2. **Создайте EDT-проект** в корне репозитория (без этого промпт остановится — проект нужен, чтобы автоматически вытащить имя, префикс и платформу):

   - В EDT: `File → New → 1C:Enterprise project`.
   - Имя проекта на латинице: `<Каталог>.<НазваниеПроекта>` (например, `MyCompany.MyProject`).
   - Префикс объектов: например, `prj_`.
   - Тип: `Configuration` (новая конфигурация) / `Configuration extension` (расширение) / `Library` (библиотека).
   - Версия платформы 1С — желаемая.
   - Расположение каталога — корень репозитория (рядом с `CLAUDE.md`).

   После создания в репозитории появится каталог `<Каталог>.<НазваниеПроекта>/src/Configuration/Configuration.mdo` (или аналогичный для расширения/библиотеки).

3. **Запустите Claude Code** в корне репозитория и дайте задачу:

   > Выполни инструкцию из `docs/project-init.md`.

---

## Алгоритм для Claude (выполнять последовательно)

> **Идемпотентность.** Промпт можно запускать повторно (например, после добавления EDT-проекта позже или при смене состава). Перед каждым изменением файла — прочитай текущее состояние и спроси пользователя: пропустить / обновить / переделать. Не перезаписывай уже заполненные значения без подтверждения.
>
> **Тон.** Все вопросы и сообщения — на русском языке.

### Шаг 0. Предварительные проверки

1. Убедись, что текущий каталог — git-репозиторий (`git status`). Если нет — попроси пользователя выполнить `git init` и вернуться.
2. **Проверь историю git.** Если последний коммит — это коммит шаблона (`init: шаблон репозитория для разработки 1С в EDT с Claude Code` или ему подобный, проверь `git log -1 --format=%s`), значит репозиторий получен через `git clone` шаблона и унаследовал его историю. Спроси пользователя:
   - **Чистая история** (рекомендуется для нового проекта) — выполни `rm -rf .git && git init && git branch -m main` (или `master`, по выбранной релизной ветке на Шаге 1). Это деструктивное действие — попроси явное подтверждение.
   - **Сохранить историю шаблона** — оставь как есть; пользователь дальше сам решает, ребейзить или нет.
3. Найди EDT-проект: ищи каталоги, где `src/Configuration/Configuration.mdo` или `src/ConfigurationExtension/ConfigurationExtension.mdo` или `src/<...>.mdo` (используй `Glob`/`Bash`).
4. **Если EDT-проект не найден — остановись.** Покажи пользователю инструкцию из раздела «Подготовка пользователя» (пункт 2) и попроси создать проект через EDT, затем запустить промпт повторно. Дальше не двигайся.
5. Если найдено несколько EDT-проектов — спроси, какой основной (он попадёт в раздел «Проект» CLAUDE.md), какие — host/extension/library (они попадут в таблицу «EDT-воркспейс»).

### Шаг 1. Сбор данных о проекте

Извлеки автоматически из EDT-проекта:

- **Каталог EDT-проекта** — имя найденного каталога.
- **Имя проекта (латиницей)** — из имени каталога или из `Configuration.mdo` (атрибут `name`).
- **Тип проекта** — по структуре: `Configuration` / `ConfigurationExtension` / `Library`.
- **Версия платформы 1С** — из `Configuration.mdo` (атрибут `compatibilityMode` / `version`).
- **Текущая версия конфигурации** — из `Configuration.mdo` (атрибут `version`).
- **Префикс объектов** — попробуй определить по именам существующих объектов в `Catalogs/`, `CommonModules/`, `Subsystems/` (общий префикс перед `_`). Если префикса нет или объекты ещё не созданы — спроси.

Спроси у пользователя одной серией вопросов (используй `AskUserQuestion`):

- **Краткое описание проекта** — одно предложение для CLAUDE.md и README.md.
- **URL трекера задач** — например, GitHub Issues, Jira, Linear, или «нет трекера».
- **Релизная ветка** — default `main` (если ветка `main` уже создана в репо) или `master`.
- **Ветка разработки** — default `develop`. Если разработка ведётся прямо в релизной ветке — спроси и зафиксируй.
- **Формат имени feature-ветки** — default `feature/<prefix>-<N>`.
- **Формат коммита** — default `<URL issue> <описание на русском>`.
- **Соглашение об инкременте версии** — оставить пример из шаблона или предложить своё.

Сохрани все ответы в плоскую структуру в памяти (в виде таблицы) — она понадобится на следующих шагах.

### Шаг 2. Заполнить `CLAUDE.md`

1. Прочитай `CLAUDE.md`.
2. **Удали блок-предупреждение** в начале:

   ```markdown
   > Это **шаблон**. Перед началом работы заполните разделы со знаком `<...>` под свой проект и удалите этот блок-предупреждение.
   ```

3. Замени плейсхолдеры (`<...>`) собранными данными в следующих разделах:
   - **«Проект»** — имя, описание, каталог EDT-проекта, префикс, платформа, трекер.
   - **«EDT-воркспейс»** — таблица заполняется только если EDT-проектов больше одного. Иначе оставь раздел с одной строкой или удали таблицу и оставь короткую заметку.
   - **«Соглашения по коду»** — префикс уже подставится в строку про новые объекты.
   - **«Ветки и коммиты»** — релизная и dev-ветки, формат feature-ветки, формат коммита, соглашение об инкременте версии. Путь к `Configuration.mdo` обнови под фактический.
   - **«Структура»** — приведи дерево каталогов под фактическое имя EDT-проекта (или нескольких).
4. **Не трогай** разделы с пустыми таблицами «Ключевые подсистемы / Обработки / Общие модули / Роли» — оставь как есть, с инструкцией пользователю заполнить их по мере появления (можно добавить TODO-заметку «заполняется по мере роста проекта»).
5. Сохрани файл.

### Шаг 3. Адаптировать `README.md`

Текущий `README.md` — это README шаблона. Спроси у пользователя:

- **Сгенерировать новый README с нуля** под проект (заголовок, описание, ссылки на CLAUDE.md / specs / docs, краткая инструкция «как разрабатывать»), или
- **Оставить текущий и адаптировать** (поменять заголовок и описание, остальное оставить как есть).

Сделай выбранное. В обоих случаях:

- Замени заголовок и описание на данные проекта.
- Удали раздел «Источник» про PrintWizard, если пользователь явно не попросит сохранить.
- Удали разделы «Как использовать» (шаги 1–7 шаблона) — они больше не актуальны.

### Шаг 4. MCP-сервер `codepilot1c`

Проверь, подключён ли MCP-сервер `codepilot1c`:

```bash
claude mcp list 2>/dev/null | grep -i codepilot1c
```

- **Если найден** — сообщи: «MCP `codepilot1c` подключён» и переходи к Шагу 5.
- **Если не найден** — спроси у пользователя:
  - **Подключить сейчас.** Покажи общую команду подключения (`claude mcp add codepilot1c <команда-запуска>`) и попроси подсказать корректную команду/URL для его среды (это зависит от того, как `codepilot1c` распространяется у пользователя — это не публичный сервер). Дождись подтверждения и проверь повторно.
  - **Отложить.** Сообщи: «Можно подключить позже через `claude mcp add`. Без MCP `codepilot1c` инструменты типизации, метаданных, форм и СКД будут недоступны — ссылочный материал в `docs/codepilot1c-reference.md`».

### Шаг 5. Skill `bsl-check`

Спроси у пользователя одно из трёх:

- **Подключить сейчас** (skill будет работать после настройки).
- **Отложить** (оставить файлы как есть, настроить позже руками по `docs/bsl-check-setup.md`).
- **Не нужен** (удалить skill из шаблона целиком).

#### 5.A. «Подключить сейчас»

Действуй по `docs/bsl-check-setup.md`, выполняя шаги от имени пользователя:

1. **Найти `hbk_md`.** Спроси путь или предложи default `~/Repository/hbk_md`. Проверь, существует ли каталог.
   - **Не существует** — спроси разрешения и склонируй: `git clone https://github.com/vandalsvq/hbk_md.git <path>`. Это сетевая операция, требующая подтверждения.
   - **Существует, но без `.claude/1c-syntax-check.py`** — каталог занят чем-то другим. Спроси другой путь.
2. **Проверить готовый справочник.** Найди `<hbk_md>/shcntx_ru_v*/search-index-ru.json`.
   - **Найден** — справочник готов, переходи к шагу 5.A.4.
   - **Не найден** — нужно разобрать `.hbk`. Перейди к шагу 5.A.3.
3. **Разобрать `.hbk`.**
   - Спроси у пользователя путь к файлу справочника `*.hbk` (обычно `shcntx_ru.hbk` из дистрибутива платформы или с диска ИТС).
   - Спроси версию платформы в формате `X.X.X.X` (например, `8.5.1.1302`) — чтобы переименовать `.hbk` под convention утилиты.
   - Скопируй файл: `cp <user-path> <hbk_md>/<X.X.X.X>.hbk`.
   - Запусти разбор: `cd <hbk_md> && python3 process_hbk_complete.py`. Это может занять несколько минут.
   - Проверь, что появился `<hbk_md>/shcntx_ru_v<X.X.X.X>/search-index-ru.json`. Если нет — покажи вывод утилиты и сообщи об ошибке, дальше не двигайся.
4. **Прописать путь в `.claude/settings.local.json`.** `SKILL.md` редактировать не надо — он берёт каталог из переменной `HBK_MD_HOME`. Если `settings.local.json` ещё нет — скопируй из `.example` (см. Шаг 6 ниже). Затем:
   - В секции `env` подставь абсолютный путь к каталогу `<hbk_md>`:

     ```json
     "env": { "HBK_MD_HOME": "<abs-path-to-hbk_md>" }
     ```

   - В `permissions.allow` убедись, что есть две строки (в `.example` они уже добавлены, не дублируй):

     ```json
     "Bash(: \"${HBK_MD_HOME:?*)",
     "Bash(python3 \"$HBK_MD_HOME/.claude/1c-syntax-check.py\":*)"
     ```

5. **Проверить.** Запусти `python3 <abs-path-to-hbk_md>/.claude/1c-syntax-check.py Структура.Вставить`. Должно вернуть `✓ Структура.Вставить (Structure.Insert)`. Если нет — покажи вывод и продиагностируй (раздел Troubleshooting в `docs/bsl-check-setup.md`).

#### 5.B. «Отложить»

Не трогай файлы skill. Сообщи: «Skill зарегистрирован, но не настроен. Когда будете готовы — пройдите `docs/bsl-check-setup.md`».

#### 5.C. «Не нужен»

Удали:

- каталог `.claude/skills/bsl-check/`,
- документ `docs/bsl-check-setup.md`,
- упоминания skill `bsl-check` в `CLAUDE.md` (раздел «Skill `bsl-check`», строку про «Сомнения в API…» в разделе «Инструменты»),
- упоминания в `README.md` (шаг про подключение skill, строку в дереве «Что внутри», если она там осталась).

### Шаг 6. Локальные permissions Claude Code

Если `.claude/settings.local.json` отсутствует — скопируй из `.claude/settings.local.json.example`. Если шаг 5.A уже создал/изменил файл — пропусти.

### Шаг 7. Чистка примеров `planning/`

В каталоге `planning/examples/` лежат примеры из проекта PrintWizard — они нужны только как референс формата. Спроси:

- **Удалить** — оставить пустой `planning/examples/` или вообще убрать каталог. Рекомендуй удалять, если проект не на основе PrintWizard.
- **Оставить** — пропустить.

### Шаг 8. Стартовая версия конфигурации (опционально)

Текущая версия в `Configuration.mdo` уже выставлена EDT при создании проекта (обычно `1.0.0.1`). Спроси: использовать как есть или сменить на другую (например, `2026.1.0.0` под convention из шаблона). Если меняем — отредактируй `Configuration.mdo`, атрибут `version`.

### Шаг 9. Первый коммит (опционально)

Спроси: «Создать первый коммит с настройкой проекта?»

- **Да** — выполни:

  ```bash
  git add CLAUDE.md README.md docs/ specs/ planning/ .claude/skills/ .claude/settings.json .claude/settings.local.json.example .gitignore <EDT-каталог>/
  git commit -m "init: настройка проекта <ИмяПроекта>"
  ```

  Файл `.claude/settings.local.json` не коммитим (он в `.gitignore`).

- **Нет** — оставь изменения в working tree.

### Шаг 10. Финал — самоудаление промпта

Покажи сводку:

- Что заполнено в CLAUDE.md / README.md.
- Что сделано с MCP `codepilot1c` (подключён / отложено).
- Что сделано с skill `bsl-check` (подключён / отложен / удалён).
- Был ли первый коммит.

Спроси: «Удалить `docs/project-init.md` и упоминания о нём в README/CLAUDE.md? (рекомендуется — промпт больше не нужен)».

- **Да** — удали `docs/project-init.md` и убери ссылки на него из `README.md` (раздел про инициализацию) и `CLAUDE.md`, если они есть.
- **Нет** — оставь как есть. Документ можно использовать повторно при перенастройке.

После всего — кратко скажи пользователю: «Готово. Можно создавать первую спеку: `cp -r specs/_template specs/<prefix>-001`».

## Что делать, если промпт прерван посередине

Промпт идемпотентен. Запусти его повторно — он определит текущее состояние:

- Уже заполненный CLAUDE.md (нет `<...>` плейсхолдеров) — спросит, нужно ли менять, или пропустит.
- Skill уже подключён (в `.claude/settings.local.json` есть `env.HBK_MD_HOME` и оба permission-правила) — спросит, нужно ли переподключать.
- Если после прерывания ты не уверен в состоянии — спрашивай у пользователя, не действуй наугад.

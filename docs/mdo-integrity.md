# Целостность MDO-файлов (EDT)

Правила поддержания согласованности MDO-файлов конфигурации 1С в формате EDT.

---

## UUID - уникальность обязательна

Каждый UUID в атрибутах `uuid`, `typeId`, `valueTypeId` должен быть **глобально уникальным** по всем MDO-файлам проекта.

**Запрещено:**
- Копировать UUID между MDO-файлами
- Использовать последовательные или placeholder UUID при генерации метаданных

**Способ генерации:** каждый UUID генерировать отдельно:
- Python: `uuid.uuid4()`
- PowerShell: `[guid]::NewGuid()`

---

## Ссылки на объекты метаданных

Перед добавлением ссылок на объекты в:
- Exchange plans (`<content><mdObject>`)
- Subsystems (`<content>`)
- Event subscriptions
- Defined types

**Проверить, что объект существует** в конфигурации.

**Типичные ошибки:**
- Ссылки на объекты из другой версии конфигурации
- Ссылки на несуществующие объекты
- Опечатки в именах объектов

**Последствия битых ссылок:** платформа выдаёт ошибку при загрузке - несоответствие типов в `Content.xml`.

## Регистр сведений: ресурс или реквизит

Для непериодического независимого регистра сведений платформе всё равно: ресурсы и
реквизиты лежат в одной таблице, одинаково доступны в запросе и у менеджера записи,
одинаково индексируются. Виртуальных таблиц среза у непериодического регистра нет -
единственное место, где платформа обходится с ними по-разному, не задействовано.
Принципиальна разница только у регистров накопления и бухгалтерии, где ресурсы
участвуют в итогах.

Поэтому граница проводится по смыслу, а не по технике:

- **Ресурс** - то, ради чего запись существует: значение, адресуемое измерениями, и его
  состояние.
- **Реквизит** - обстоятельства записи: как, чем и почём она получена. Метрики,
  длительности, идентификаторы источника, диагностика, служебные даты.

Проверочный вопрос: *если это поле убрать, запись перестанет быть собой или просто
станет хуже описанной?* Первое - ресурс, второе - реквизит.

**Менять вид поля у регистра с данными - дорого.** Ресурсы и реквизиты в MDO живут
разными коллекциями, и перенос выглядит как удаление одного поля и создание другого.
UUID при ручном переносе блока сохраняется, но сохранит ли платформа данные при
обновлении ИБ - вопрос, который проверяется на копии базы, а не предполагается.
Отсюда правило: **вид поля выбирается при заведении**, а не правится потом. Единственное
дешёвое окно - пока поле не уехало в релиз.

## Стандартные атрибуты табличных частей

Блок `<standardAttributes><name>LineNumber</name>...</standardAttributes>` в MDO-файлах табличных частей **не добавлять** - платформа добавляет его автоматически.

## `Form.form`, написанный руками: значения перечислений сверять с соседними формами

EDT принимает в `Form.form` значения перечислений шире, чем конфигуратор: валидация проекта
чистая, а падает загрузка в ИБ - с ошибкой уровня XML, без указания элемента формы:

```text
Ошибка загрузки/выгрузки конфигурации
по причине:
Исключение XDTO произошло при чтении файла- zip:///DataProcessors/<Объект>/Forms/<Форма>/Ext/Form.xml
по причине:
Несоответствие свойства и элемента данных XDTO:
Свойство: 'Group'
```

Известный случай: корневое `<group>` формы (группировка подчинённых элементов) - конфигуратор
принимает `Vertical`, но не `Auto`, хотя `Auto` допустим у `behavior`, `throughAlign`,
`currentRowUse` внутри `UsualGroupExtInfo` и потому легко попадает в файл по аналогии.

**Перед обновлением ИБ** - сверить значения с формами, сделанными дизайнером; отклонение видно
сразу:

```bash
grep -rn "^  <group>" --include=Form.form src | awk -F: '{print $3}' | sort | uniq -c
```

Имя свойства из текста ошибки (`Group`) - это имя из XDTO-пакета конфигуратора, а не тег
`.form`: искать по смыслу, а не подстрокой.

## Сочетания клавиш (`<shortcut>`, `Новый СочетаниеКлавиш`)

### 1. Нотация - только Ctrl/Alt/Shift

EDT на macOS сериализует сочетания клавиш в мак-нотации: `Cmd+P`, `Option+P`.
Платформа на Windows такие модификаторы не распознаёт - сочетание вырождается
в **голую букву**, и команда срабатывает при обычном наборе текста.

Пункт касается проектов, где хоть кто-то работает в EDT на macOS: при разработке только
на Windows или Linux мак-нотация в файлах не появляется. Пункт 2 - для всех.

**Правило:** в `<shortcut>` (файлы `.form` и `.mdo`) допустимы только `Ctrl`, `Alt`,
`Shift` и их комбинации. Нормализация: `Cmd` → `Ctrl`, `Option` → `Alt`.
Кроссплатформенность не страдает: на macOS платформа сама отображает `Ctrl`/`Alt`
на `Cmd`/`Option`.

### 2. Основная клавиша - только F-ряд, предпочтительно `Shift+F<N>`

Одной нормализации мало. Буква в сочетании ломает набор текста и после неё: клиент
перехватывает клавишу по позиции, и в русской раскладке перестаёт печататься
соответствующая буква (`Ctrl+P` - «З», `Ctrl+E` - «У»). У общей команды
(`CommonCommand`) эффект глобальный, во всех окнах клиента. Цифры не спасают - ими
ломается ввод цифр.

Перечисление `Клавиша` допускает как основную клавишу только `A...Z`, `_0..._9`,
`Num0...Num9`, `NumAdd`/`NumDecimal`/`NumDivide`/`NumMultiply`/`NumSubtract`,
`F1...F12`, `Space`, `BackSpace`, `Break`. `Enter`, `Insert`, `Delete`, `Tab` назначить
нельзя - выбор сводится к F-ряду.

`Shift+F<N>` - единственный класс, свободный сразу в трёх ОС:

| Класс | Кем занят |
| --- | --- |
| `Ctrl+F2`...`Ctrl+F8` | macOS: строка меню, Dock, окно, панель, плавающее окно, режим Tab, меню статуса |
| `Ctrl+F1`...`Ctrl+F4` | Linux/KDE: переключение рабочих столов |
| `Ctrl+F9`...`Ctrl+F12` | Linux/KDE: эффекты рабочего стола (`Ctrl+F12` - Dashboard) |
| `Alt+F1/F2/F4/F7`...`Alt+F10` | Linux: оконный менеджер; Windows: `Alt+F4` |
| `Ctrl+Alt+F1`...`Ctrl+Alt+F12` | Linux: виртуальные консоли |
| **`Shift+F<N>`** | **свободен во всех трёх ОС** |

Зарезервировано платформой 1С (стандарт 430): `F1`, `Shift+F1`, `Alt+F1`, `F2`,
`Ctrl+F2` (калькулятор), `F3`, `Shift+F3`, `F4`, `Shift+F4` (очистка поля),
`Ctrl+Shift+F4`, `F6`, `Shift+F6`, `Ctrl+F6`, `Ctrl+Shift+F6`, `Ctrl+F4`, `F9`,
`Ctrl+F9`, `F10`, `Shift+F10`, `Alt+F10`, `Ctrl+X/C/V/A`, `Ctrl+Z/Y`, `Ctrl+B/I/U`,
`Ctrl+F/H/T`, `Ctrl+N/O/S/P`, `Ctrl+Shift+P`, `Ctrl+Shift+F`. Голые `F7`, `F8`, `F11`,
`F12` заняты в прикладных решениях.

Занятые проектом сочетания вести списком здесь же или в `CLAUDE.md` - иначе вторая
команда молча перекроет первую.

### Проверка

Обязательна после назначения сочетаний в EDT и уместна перед любым коммитом, затрагивающим
формы, общие команды или модули, создающие команды формы. Первый grep ловит мак-нотацию
(п. 1) и нужен, если в EDT работают на macOS: совпадений быть не должно. Второй и третий -
для всех, сверяются глазами: основная клавиша везде из F-ряда (п. 2).

```bash
grep -rnE '<shortcut>[^<]*(Cmd|Option|Command)' --include=Form.form --include='*.mdo' <EDT-проект>/src
grep -rhoE '<shortcut>[^<]+' --include=Form.form --include='*.mdo' <EDT-проект>/src | sort -u
grep -rn 'Новый СочетаниеКлавиш' --include='*.bsl' <EDT-проект>/src
```

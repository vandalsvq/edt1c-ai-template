# Зарезервированные имена в модулях форм 1С

---

## Правило

В модулях форм **запрещено** использовать как имена локальных переменных имена стандартных свойств
формы и её элементов:

- `Параметры` (Parameters) - параметры самой формы
- `ПараметрыВыбора` (ChoiceParameters)
- `СвязиПараметровВыбора` (ChoiceParameterLinks)
- `СписокВыбора` (ChoiceList)
- `ПараметрыОтбора` (Filter)
- `ОтборСтрок` (RowFilter)
- `Окно` (Window) - окно, в котором открыта форма; свойство только для чтения, поэтому
  присвоение падает уже в рантайме: «Поле объекта недоступно для записи (Окно)»
- `Доступность` (Enabled) - Булево; присвоение структуры даёт `SU91` («Тип значения
  "Булево" заменён на "Структура"»), а обращение к полям такой переменной - `SU83` и
  `SU70` на каждое поле. Диагностика указывает на строку присвоения, поэтому причина
  читается не сразу: и вызываемая функция, и её докблок выглядят правильными

> Список основан на практическом опыте и может быть неполным. При подозрении на конфликт имён - проверить в конфигураторе.

---

## Причина

Платформа 1С в контексте `&НаСервере` модуля формы может интерпретировать присвоение `ПараметрыВыбора = ...` как попытку установить свойство элемента формы, а не локальную переменную. Если тип значения не совпадает с ожидаемым (`ФиксированныйМассив(ПараметрВыбора)`) - ошибка «Несоответствие типов».

С `Параметры` то же самое на уровне формы: имя занято её параметрами (`ДанныеФормыСтруктура`), и присвоение структуры даёт `SU91` («Тип значения "ДанныеФормыСтруктура" заменён»), а обращение к полю - `SU83` и `SU71` («Обращение к несуществующему параметру формы»).

---

## Как именовать

Использовать конкретные имена с контекстом:

```bsl
// Плохо:
ПараметрыВыбора = Новый Массив;

// Хорошо (→ - символ таба, см. bsl-coding-standards.md «Отступы и выравнивание - табы»):
ПараметрыВыбораНоменклатуры→= Новый Массив;
ПараметрыВыбораСтатьи→→= Новый Массив;
```

# Стандарты кода BSL

Стандарты написания кода на платформе 1С:Предприятие. Префикс объектов и название проекта - см. [`../CLAUDE.md`](../CLAUDE.md).

---

## Комментарии

**Не добавлять комментарии по умолчанию.** Код должен быть понятен без них. Комментарии уместны только когда добавляют ценность, которую нельзя выразить кодом:

- Мотивация неочевидного решения (почему именно такой подход)
- Нетривиальный алгоритм (суть, не пересказ кода)
- Ограничения и граничные случаи
- Контракты экспортных функций (параметры, возвращаемое значение)
- Технический долг (TODO, FIXME)

**Запрещено:**

- `// Получаем данные`, `// Проверяем условие` - дублируют код
- Комментарии к каждой строке
- Комментарии-разделители (`// ---`, `// ***`) вместо `#Область`
- Комментарий, дословно повторяющий имя функции

> **Doc-блоки - отдельная история.** Правило «не комментировать по умолчанию» относится к поясняющим комментариям внутри кода. В модулях с `// @strict-types` doc-блок метода (секции `Параметры` / `Возвращаемое значение` с типами) **обязателен для всех методов**, включая неэкспортные и обработчики событий - это типовые аннотации, на которые опирается анализатор EDT. См. [`bsl-strict-types.md`](bsl-strict-types.md).

### В комментарии - причина, а не история

Комментарий отвечает, **почему код такой**. Обстоятельства, при которых это
выяснилось - даты проверок, номера задач, имена моделей и провайдеров, цифры
замеров, ссылки на прогоны - живут в спеке (`specs/<prefix>-<N>/plan.md`), а не
в модуле: в коде они устаревают и раздувают то, что читают на бегу.

```bsl
// Плохо: причина утонула в отчёте о замере
// Отбор по дате - параметром виртуальной таблицы. Замер 2026-08-05 на базе
// клиента: в ГДЕ запрос отрабатывал 12 секунд на 400 тыс. движений, с
// параметром - 0.3 с. Проверяли на 8.3.21 и 8.3.24, разница одинаковая.

// Хорошо: осталась причина
// Отбор по дате - параметром виртуальной таблицы, а не в ГДЕ: иначе платформа
// сначала разворачивает весь период и фильтрует уже готовый результат.
```

Дата или номер задачи уместны там, где без них нельзя разобраться: ссылка на
внешний баг-трекер, срок действия обходного решения, привязка к версии платформы.

### Тире - только дефис-минус, длинное и среднее запрещены

**Везде, без исключений по видам текста**: код, строковые литералы, сообщения
пользователю и `НСтр`, комментарии и шапки методов, макеты и тексты форм, спеки
(`specs/`, `planning/`), документация, сообщения коммитов, комментарии к задачам.
Разрешён только дефис-минус `-` (U+002D). Запрещены em-dash (U+2014), en-dash
(U+2013), минус (U+2212), неразрывный дефис (U+2011) - здесь они названы кодами
намеренно, чтобы начертание нельзя было скопировать из документа в код.

Причины разные, но правило одно, чтобы не приходилось помнить границу:

- в docblock дефис - разделитель, которого ждёт парсер EDT (`Параметр - Тип - описание`);
- в коде и ключах длинное тире визуально неотличимо от дефиса, поэтому ошибка
  не видна при чтении и проявляется молча;
- в текстах - единообразие: разнобой тире в одном файле выглядит неряшливо.

```bsl
// Хорошо:
//	АдресХранилища - Строка - адрес временного хранилища
// Ключ хранится по провайдеру: при смене - плейсхолдер либо пусто.
Сообщение = НСтр("ru='Шаблон не найден - выберите другой макет'");
```

Не считаются нарушением и не правятся **записанные артефакты**: трассировки
внешних ответов, артефакты закрытых задач в `specs/done/` (прототипы,
скрипты-генераторы), входные исследования и вендоренные копии сторонних
проектов - это зафиксированные как есть записи, а не текст, который мы ведём.

Проверка перед коммитом:

```bash
git diff --cached -U0 | grep -nP '^\+.*[\x{2010}-\x{2015}\x{2212}]'
```

### Порядок секций docblock: описание, `Параметры:`, `Возвращаемое значение:`

Секции идут в порядке вызова: сначала описание метода, затем что он принимает, затем что
отдаёт. Порядок нарушается обычно не при написании метода, а при правке: у метода без
параметров docblock кончался возвращаемым значением, и новая секция `Параметры:`
дописывается в конец. Добавляя параметр существующему методу, секцию **вставляют перед**
`Возвращаемое значение:`, а не приписывают следом.

### Составной тип в `Возвращаемое значение:` и `Параметры:` - каждый тип с новой строки

Когда значение может быть **нескольких типов**, каждый тип оформляется отдельной строкой-элементом: `//` + таб + `-` (дефис-минус) + тип + `-` + описание. Дефис ставится **перед каждым** типом.

```bsl
// Возвращаемое значение:
//	- СправочникСсылка.Организации - найденная организация
//	- Неопределено - если организация не найдена
Функция НайтиОрганизацию(знач ИНН) Экспорт
```

Допустим, но нежелателен инлайн-вариант через запятую (без разбивки по строкам) - только когда описание типов не требуется:

```bsl
// Возвращаемое значение:
//	СправочникСсылка.Организации, Неопределено - организация или Неопределено
```

Частая ошибка: перечислить типы списком, но забыть дефис перед вторым и последующими:

```bsl
// НЕПРАВИЛЬНО - дефис только у первого типа:
// Возвращаемое значение:
//	- СправочникСсылка.Организации - организация
//	Неопределено - не найдена
```

Одиночный тип пишется как обычно, без ведущего дефиса-элемента (см. пример в разделе «Структура модулей»).

### Перечень свойств - лесенка отступов по уровням вложенности

Уровень задаётся числом табов после `//`, звёздочки идут после отступа:

- **1 таб** - имя параметра и объявление типа (`ФиксированнаяСтруктура:`, `ТаблицаЗначений:`);
- **2 таба** - свойства этой коллекции (`* Имя`);
- **3 таба и далее** - свойства вложенных коллекций (`** Имя`, `*** Имя`).

```bsl
// Возвращаемое значение:
//	ФиксированнаяСтруктура:
//		* Объекты		- ФиксированныйМассив из ФиксированнаяСтруктура:
//			** ПолноеИмя	- Строка
//			** Синоним		- Строка
//		* ВсегоНайдено	- Число - находок до применения лимита.
```

Частая ошибка - оставить свойства на одном уровне с объявлением типа: тип и его
свойства сливаются в один список, а вложенность коллекций перестаёт читаться.

```bsl
// НЕПРАВИЛЬНО - свойства не отбиты от объявления типа:
//	ФиксированнаяСтруктура:
//	* Объекты		- ФиксированныйМассив из ФиксированнаяСтруктура:
//		** ПолноеИмя	- Строка
```

Выравнивание тире внутри блока - табами, по самому длинному имени этого уровня;
сдвиг блока ровно на один таб выравнивание сохраняет (все табстопы уезжают на те же
4 колонки). Одиночная строка в секции выравнивания не требует - тире отбивается
одним пробелом.

### Структура с произвольным набором ключей - `Структура из КлючИЗначение`

Когда состав ключей задаёт не наш код (тело ответа внешнего API, разобранный JSON,
элемент макета), перечислять свойства через `*` нельзя - их набор неизвестен, а
строгая типизация будет требовать вернуть каждое заявленное. Описывается пара
ключ/значение:

```bsl
// Параметры:
//	Сообщение - Структура из КлючИЗначение - разобранный ответ внешнего сервиса:
//		* Ключ		- Строка - имя свойства ответа.
//		* Значение	- Строка - текстовые свойства ответа.
//					- Произвольный - прочие свойства, здесь не читаются.
```

## Структура модулей

Порядок областей в общем модуле:

1. `#Область ПрограммныйИнтерфейс` - экспортные, доступны всем, документированы
2. `#Область СлужебныйПрограммныйИнтерфейс` - экспортные, доступны внутри подсистемы
3. `#Область СлужебныеПроцедурыИФункции` - неэкспортные

Состав и порядок областей первого уровня закреплены и не меняются. **Больше 10 методов
в области - дробить на подобласти второго уровня** по назначению или связанности;
меньше - по усмотрению автора. Имя подобласти - существительное в именительном падеже,
по назначению (`РазборОглавления`, `ЗагрузкаПакета`); имена-заглушки (`Прочее`,
`Вспомогательные`, `Общее`) запрещены - они не сообщают ничего сверх имени
родительской области.

Внутри области или подобласти, при прочих равных, процедуры располагаются выше функций.
Связность важнее порядка: методы, вызывающие друг друга, стоят рядом. Дополнительное
упорядочивание по директиве компиляции есть в модулях форм и команд - см.
[`bsl-form-module-rules.md`](bsl-form-module-rules.md).

В существующих модулях порядок наводится при значимой переработке области, а не
отдельной правкой ради порядка.

Документация экспортных функций:

```bsl
// Возвращает параметры области макета по имени.
//
// Параметры:
//	Имя - Строка - имя области
//
// Возвращаемое значение:
//	Структура - параметры области
//
Функция ПолучитьПараметрыОбласти(Имя) Экспорт
```

## Именование

### Переменные

Не использовать венгерскую нотацию: `МассивКонтрагентов` → `Контрагенты`.
Исключение: типы коллекций (`ТаблицаКлиентов`, `СписокДокументов`).

Не использовать имена из глобального контекста 1С как имена переменных:
`Документы`, `Справочники`, `РегистрыСведений`, `РегистрыНакопления`, `Метаданные`, `Константы`, `ПараметрыСеанса` и т.д.

```bsl
// Плохо:
Документы = Новый Массив;

// Хорошо:
СписокДокументов = Новый Массив;
```

Не использовать имена примитивных типов и одноимённых функций преобразования -
`Строка`, `Число`, `Дата`, `Булево`, - а также имена конструируемых типов: `Массив`,
`Структура`, `Соответствие`, `Тип`. `Строка(Значение)`, `Число(Значение)`,
`Дата(Год, Месяц, День)` - функции глобального контекста, и переменная занимает их имя
в пределах метода: вызвать функцию оттуда уже нельзя. Чаще всего попадается «строка
табличной части» - называть её предметно.

```bsl
// Плохо: в этом методе больше не написать Строка(Дата)
Для Каждого Строка Из Объект.Сообщения Цикл

// Хорошо:
Для Каждого СтрокаСообщения Из Объект.Сообщения Цикл
```

Правило - для нового кода. Существующий чистить отдельной правкой, а не попутно:
в модуле обычно соседствуют и вызовы `Строка(...)`, и переменные с этим именем,
и механическая замена ломает первые.

Не использовать ключевые слова языка BSL как имена переменных, параметров и функций:

| Группа | Слова |
| --- | --- |
| Логические операторы | `И`, `ИЛИ`, `НЕ` |
| Условия | `Если`, `Тогда`, `ИначеЕсли`, `Иначе`, `КонецЕсли` |
| Циклы | `Для`, `Каждого`, `Из`, `По`, `Цикл`, `КонецЦикла`, `Пока`, `Прервать`, `Продолжить` |
| Процедуры и функции | `Процедура`, `КонецПроцедуры`, `Функция`, `КонецФункции`, `Возврат`, `Экспорт`, `Знач` |
| Обработка исключений | `Попытка`, `Исключение`, `ВызватьИсключение`, `КонецПопытки` |
| Объявление переменных | `Перем` |
| Операторы | `Новый`, `Выполнить`, `Перейти`, `Метка` |
| Асинхронность | `Асинх`, `Ждать` |
| Литералы | `Истина`, `Ложь`, `Неопределено`, `Null` |

```bsl
// Плохо:
И = Истина;
НЕ = Ложь;
Перем Если;

// Хорошо:
ЭтоАктивный = Истина;
ЕстьДанные = Ложь;
```

Не использовать имена реквизитов, табличных частей и методов **текущего объекта или
формы**: локальная переменная перекрывает их в пределах метода, и обращение к реквизиту
из этого метода становится невозможным. Ошибка тихая - код компилируется, а тип
подменяется.

```bsl
// Плохо: у обработки есть ТЧ Сообщения - внутри метода она больше недоступна
Сообщения = РегистрыСведений.prj_ИсторияПереписки.ПрочитатьСообщения(КлючСессии);

// Хорошо:
СообщенияСессии = РегистрыСведений.prj_ИсторияПереписки.ПрочитатьСообщения(КлючСессии);
```

**Имя - предмет, а не его характеристика.** Одинокое прилагательное (`Сырой`,
`Актуальный`, `Временный`) не отвечает на вопрос «что это»: в строке `Сырой.БазовыйURL`
непонятно, откуда значение и что в нём лежит. Характеристика - уточнение к предмету,
а не замена ему.

```bsl
// Плохо:
Функция НормализованныйПрофиль(знач Сырой)

// Хорошо:
Функция НормализованныйПрофиль(знач ЭлементМакета)
```

**Без отрицаний в именах.** `БезОтключенияX`, `НеИспользоватьY` дают двойное отрицание
на месте чтения (`Если НЕ БезОтключенияX Тогда`). Называть состояние прямо, инвертируя
смысл: `РазмышленияОтключены`, `ОткатВыполнен`.

**Булев реквизит - утверждение о состоянии, не команда.** `ВключитьДиагностику` читается
как вызов процедуры; типовая для 1С форма - `ИспользоватьДиагностику`,
`ВестиУчетПоСериям`, `ЕстьОшибки`.

### Буква «ё» - только в текстах, не в идентификаторах

Имена переменных, параметров, процедур, функций, полей структур, реквизитов и
метаданных пишутся через «е»: `СвернутоСообщений`, `ОбновитьУчетКонтекста`,
`Сохраненные`. Идентификатор с «ё» ломает поиск по коду (`Свернуто` не находит
`Свёрнуто`) и расходится с остальной кодовой базой, где «ё» никто не набирает.

В текстах «ё» уместна и приветствуется: комментарии, doc-блоки, строки `НСтр`,
заголовки элементов формы, спеки и документация.

```bsl
// Плохо: идентификатор с «ё»
СвёрнутоСообщений = 0;

// Хорошо: идентификатор через «е», текст - с «ё»
СвернутоСообщений = 0; // сколько сообщений свёрнуто в конспект
```

### Длина имени - от 3 символов

Имена локальных переменных и параметров - 3+ символов. Короткие аббревиатуры (`ТЗ`, `Н`, `Кл`, `Стр`) недопустимы: через несколько строк от объявления теряется смысл (`ТЗ` - таблица значений? тип запроса?).

```bsl
// Плохо:
ТЗ = Новый ТаблицаЗначений;
Функция ИзвлечьИзКэша(знач ТЗ)

// Хорошо:
ТаблицаКэша = Новый ТаблицаЗначений;
Функция ИзвлечьИзКэша(знач ТаблицаКэша)
```

Аббревиатура допустима как часть составного имени (`ВидТЗ`, `ОтложенныеДействияТаблица`). Счётчик цикла - `Индекс`, не `И`. Правило - для нового кода; существующий не переписывать ради него.

### Без транслита англицизмов

Не транслитерировать английские термины кириллицей (`Капабилити`, `Фича`, `Воркер`, `Лоадер`, `Пресет`) - и не русский, и не английский. Искать русский синоним, в первую очередь среди уже принятых терминов проекта (`КапабилитиПровайдера` → `ВозможностиПровайдера`, `ПресетыНастроек` → `ПрофилиНастроек`).

Латиница допустима там, где это установленный контракт: имена внешних API, общепринятые термины предметной области, имена типов и свойств XDTO-пакетов сериализации.

### Процедуры и функции

**Имя функции - существительное** (что возвращается), **имя процедуры - глагол** (что
делает). Совпадение имени с типом операции делает интерфейс самоописательным:
`Если КоличествоНенайденных() > 0` читается естественно, `Если ПодсчитатьНенайденных() > 0` - нет.

- Процедуры (действие): `ЗаполнитьТаблицу()`, `ОбновитьДанные()`
- Функции-предикаты: `ЭтоНовый()`, `ЕстьОшибки()`, `МожноИзменить()`
- Функции (получение): `ПолучитьДанные()`, `НайтиКлиента()`, `ВычислитьСумму()`, `КоличествоСтрок()`

Глагол совершенного вида в имени функции допустим (`Сформировать…НаСервере`,
`Получить…`) - подразумевает «возврат уже сформированного результата», устоявшийся
стиль 1С.

**CQS - запрос не мутирует состояние.** Функция-геттер (`Получить…`, `Прочитать…`,
имя-существительное) только возвращает, не меняя персистентное состояние. Если чтение
безопасно лишь после записи - синхронизацию сводит **вызывающий** (его граница
ответственности), а не прячет запись в читателе. Красный флаг - прилагательное-действие
в геттере (`Актуальный`, `Обеспечить…`, `…СПодготовкой`): в нём спрятана команда.

```bsl
// Плохо: команда спрятана в запросе (нарушение CQS + ложь в имени)
Функция ПолучитьАктуальныйPDF(знач Макет)
	ЗаписатьВКэш(Макет);          // мутация под именем "Получить"
	Возврат ПрочитатьКэш(Макет);
КонецФункции
```

**`знач` - строчными.** Модификатор параметра пишется в нижнем регистре:
`Функция НайтиОрганизацию(знач ИНН)`. Разнобой в регистре - лишний шум в diff.

**Валидаторы** (`Проверить*`) - функция, не процедура; параметр `ВыдатьИсключение = Ложь`;
возврат Булево (Истина = проверка пройдена). При неуспехе и `ВыдатьИсключение = Истина` -
исключение с понятным текстом, иначе тихо Ложь. Вызывающий выбирает:
`Если НЕ ПроверитьЯдро() Тогда …` (мягко) либо `ПроверитьЯдро(Истина);` (жёстко на входной точке).

### Форматирование запроса

Текст запроса без отступа на новой строке после `=`:

```bsl
Запрос.Текст =
"ВЫБРАТЬ
|	Таблица.Поле  КАК Поле,
|	Таблица.Поле2 КАК Поле2
|ИЗ
|	Справочник.Таблица КАК Таблица
|ГДЕ
|	Таблица.Поле = &Параметр";
```

### Редактирование чужих запросов

При доработке существующего кода - сохранять стиль оригинала:

1. **Не вводить конкатенацию строк** - если оригинальный запрос записан единым литералом, добавляемые строки вписываются внутрь, а не через `+ "..."`.
2. **Сохранять выравнивание** - отступы `|`, позиции ключевых слов.

```bsl
// Плохо: внесена конкатенация
Запрос.Текст =
	"ВЫБРАТЬ ...
	|ГДЕ
	|	Таблица.Условие1 = &Параметр1"
	+ "
	|	И Таблица.Условие2 = &Параметр2";

// Хорошо: новые строки вписаны в единый литерал
Запрос.Текст =
	"ВЫБРАТЬ ...
	|ГДЕ
	|	Таблица.Условие1 = &Параметр1
	|	И Таблица.Условие2 = &Параметр2";
```

### Промежуточная переменная для результата

```bsl
// Плохо:
Выборка = Запрос.Выполнить().Выбрать();

// Хорошо:
РезультатЗапроса = Запрос.Выполнить();
Выборка = РезультатЗапроса.Выбрать();
```

### Псевдонимы полей и таблиц

Всегда давать псевдонимы через `КАК`.

Псевдоним таблицы должен быть информативным, не однобуквенным (`Р`, `Т`).
Псевдоним таблицы **не должен совпадать** с именем поля этой таблицы - приводит к конструкции `Алиас.Алиас` и ошибке платформы.

```bsl
// Плохо: алиас "Местонахождение" совпадает с измерением
ВЫБРАТЬ
	Местонахождение.Местонахождение КАК Подразделение
ИЗ
	РегистрСведений.МестонахождениеОС.СрезПоследних КАК Местонахождение

// Хорошо:
ВЫБРАТЬ
	МестонахождениеОС.Местонахождение КАК Подразделение
ИЗ
	РегистрСведений.МестонахождениеОС.СрезПоследних КАК МестонахождениеОС
```

## Пользовательские тексты (НСтр)

Все тексты, видимые пользователю (сообщения, предупреждения, заголовки, тексты вопросов, представления в исключениях), создаются в коде через `НСтр` - не строковым литералом напрямую. Это включает локализацию и единообразие текстов.

**Синтаксис:** `НСтр(<ИсходнаяСтрока>, <КодЯзыка>)`

- `ИсходнаяСтрока` (обязательный) - строки на разных языках через `;` (точка с запятой), формат `код='текст'`. Текст - в одинарных кавычках.
- `КодЯзыка` (необязательный) - код языка; по умолчанию - язык текущего пользователя.

```bsl
// Хорошо:
Текст = НСтр("ru='Документ не проведён.'");
Текст = НСтр("ru='Документ не проведён.';en='Document is not posted.'");

// Плохо - голый литерал:
Текст = "Документ не проведён.";
```

**Пробелов в разметке нет**: ни вокруг `=`, ни после `;` - `ru='Текст';en='Text'`,
не `ru = 'Текст'; en = 'Text'`. В многострочном литерале то же: `|en='Text'`.
Одинарные кавычки внутри текста - удвоением: `'это ''пример'''`.

Нужен ли второй язык - решение проекта (см. [`../CLAUDE.md`](../CLAUDE.md)). Если
решено вести оба, то вариант заводится сразу на обоих языках, перевод осмысленный,
а не машинный, и плейсхолдеры `%1` присутствуют в каждом варианте.

Подстановки - через `СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку` (или `СтрШаблон`), а не конкатенацией внутри `НСтр`:

```bsl
Текст = СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку(
	НСтр("ru='Документ %1 не проведён.'"), Ссылка);
```

**Исключение:** строки технического назначения (имена реквизитов в `СообщитьПользователю`, ключи структур, имена полей запроса, тексты для журнала регистрации без показа пользователю) в `НСтр` не оборачиваются.

## Сообщения и исключения

### Вывод сообщений

Не использовать `Сообщить()`. Использовать БСП-методы; текст - через `НСтр`:

```bsl
// На сервере:
ОбщегоНазначения.СообщитьПользователю(
	НСтр("ru='Ошибка при обработке данных.'"), , "Объект.Реквизит", , Отказ);

// На клиенте:
ОбщегоНазначенияКлиент.СообщитьПользователю(
	НСтр("ru='Ошибка при обработке данных.'"));
```

### Обработка исключений

Не глотать исключения молча. Логировать и пробрасывать:

```bsl
Попытка
	// Опасная операция
Исключение
	ТекстОшибки = ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке());
	ЗаписьЖурналаРегистрации(
		"Модуль.Функция",
		УровеньЖурналаРегистрации.Ошибка, , , ТекстОшибки);
	ВызватьИсключение;
КонецПопытки;
```

Не использовать `Попытка...Исключение` для штатных операций с БД. `Попытка` - для действительно опасных операций (COM, внешние вызовы, файлы).

Представления ошибки получать через `ОбработкаОшибок`: `КраткоеПредставлениеОшибки` -
для показа пользователю, `ПодробноеПредставлениеОшибки` - для журнала и исключений.
Глобальные `ОписаниеОшибки()`, `КраткоеПредставлениеОшибки()`,
`ПодробноеПредставлениеОшибки()` не применять - они не рекомендуются с 8.3.17.

## Транзакции

`НачатьТранзакцию()` - **строго до** `Попытка`, не внутри:

```bsl
НачатьТранзакцию();
Попытка
	// ...
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию();
	ЗаписьЖурналаРегистрации(
		"Модуль.Функция",
		УровеньЖурналаРегистрации.Ошибка, , ,
		ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
	ВызватьИсключение;
КонецПопытки;
```

Правила:
- `ЗафиксироватьТранзакцию()` - последний оператор перед `Исключение`
- `ОтменитьТранзакцию()` - первый оператор в блоке `Исключение`
- Между `НачатьТранзакцию()` и `Попытка` не должно быть другого кода

## Даты

Использовать `ТекущаяДатаСеанса()`, не `ТекущаяДата()`.
`ТекущаяДата()` зависит от часового пояса сервера, `ТекущаяДатаСеанса()` учитывает часовой пояс пользователя.

Блокировки нужны при: изменении данных, чтении с последующей записью, работе с автонумерацией.
Предпочитать управляемые блокировки:

Блокировка = Новый БлокировкаДанных;

## Форматирование

### Отступы и выравнивание - табы

Все отступы и колоночное выравнивание - символом табуляции (`\t`), не пробелами. Ширина таба в проекте - 4 позиции (стандарт 1C:EDT).

- **Отступ строки** - табы по уровню вложенности. Один уровень = один `\t`.
- **Колоночное выравнивание** (`=`, аргументы `Структура.Вставить(...)` и т.п.) - добавляются табы до нужной табопозиции, не пробелы (мелкий добор 1-2 пробела - исключение, см. «Выравнивание в однотипных блоках»).
- **Перенос длинных параметров** метода - отступать табами от уровня вызова.
- **Текст запроса в строковом литерале** - после `|` ставится таб, а не 4 пробела.
- **Псевдонимы `КАК` в тексте запроса** - единственное место, где колонка набирается **пробелами**, а не табами. Отступ после `|` при этом остаётся табом: таб задаёт уровень, пробелы держат колонку внутри строкового литерала.
- **Doc-комментарии параметров** - однострочные; если перенос неизбежен, выравнивание под текстом - исключение, не правило.
- **Отступ в doc-комментариях** - табами в обоих местах: и перед именем параметра или свойства (`//` + таб + имя), и в колонке перед `-` с типом. Пробелы в этих местах в редакторе выглядят так же, поэтому глазом расхождение не видно - проверять `grep -nP '^\s*// {2,}\S'` и `grep -nP '^\s*//.*\S {2,}-'`.
- **Свойства коллекций в doc-комментариях** (`* Поле`, `** Ключ`) - отступ табами по уровню вложенности: `//` + 2 таба + `*`, следующий уровень - `//` + 3 таба + `**`.
- **Смешанный вариант** «отступ табами, колонка типов пробелами» не допускается: пробелы разъезжаются с окружением и дают diff-шум.

В примере ниже каждый `→` обозначает один символ табуляции (в Markdown реальные табы рендерятся по-разному, поэтому показаны маркером):

```bsl
// Отступ - таб по уровню вложенности:
Если Флаг Тогда
→Структура.Вставить("Сумма", 0);
КонецЕсли;

// Текст запроса - таб после "|":
Запрос.Текст =
"ВЫБРАТЬ
|→Таблица.Поле КАК Поле
|ИЗ
|→Справочник.Таблица КАК Таблица";

// Колоночное выравнивание "=" - добиваем табами до одной табопозиции:
Настройка.Наименование→→= "Формирование уведомлений";
Настройка.ИмяДляРазработчика→= "ФормированиеУведомлений";
Настройка.СписокЗначений→→= Ложь;
```

Реальные модули EDT-проекта (`<EDT-проект>/src/CommonModules/**/Module.bsl`, `**/Forms/**/Module.bsl` и т.д.) набраны табами - пробельный отступ в новом коде даст diff-шум и разъедется с окружением.

Перед записью большого блока - посмотреть, как окружающий код использует табы, и зеркалить.

### Ограничение строки - 120 символов

Переносить строки длиннее 120 символов. Строки короче 120 - не переносить без нужды.

```bsl
// Плохо (лишний перенос):
ОбщегоНазначенияКлиент.СообщитьПользователю(
	НСтр("ru='Ошибка'"));

// Хорошо:
ОбщегоНазначенияКлиент.СообщитьПользователю(НСтр("ru='Ошибка'"));
```

### Пустая строка между комментарием и директивой области

`#Область` и `#КонецОбласти` отделяются от соседних комментариев пустой строкой. Иначе в свёрнутом виде комментарий прилипает к заголовку области и читается как её часть.

```bsl
// Плохо: в свёрнутом виде комментарий сливается с заголовком области
// Дальше идёт разбор оглавления.
#Область РазборОглавления

// Хорошо:
// Дальше идёт разбор оглавления.

#Область РазборОглавления
```

### Выравнивание в однотипных блоках - обязательно

В любом блоке из идущих подряд однотипных строк выравнивание не опционально, а **обязательно**. Выравнивать по самому длинному имени:

- присваивания свойств (`=`);
- аргументы `Структура.Вставить` / `Соответствие.Вставить`;
- инлайн-комментарии типов в конце строк (`// Тип -`);
- цепочки `Параметр = ...` в подготовке вызова.

При последовательном заполнении свойств - выравнивать `=` по самому длинному имени:

```bsl
// Плохо:
Настройка.Наименование = "Формирование уведомлений";
Настройка.ИмяДляРазработчика = "ФормированиеУведомлений";
Настройка.СписокЗначений = Ложь;

// Хорошо (→ - символ таба, см. «Отступы и выравнивание - табы»):
Настройка.Наименование→→= "Формирование уведомлений";
Настройка.ИмяДляРазработчика→= "ФормированиеУведомлений";
Настройка.СписокЗначений→→= Ложь;
```

Аналогично для `Структура.Вставить`, `Соответствие.Вставить` и других однотипных блоков.

Выравнивание - для **серий** параллельных установок (и параллельных инициализаций в
начале метода). Одиночное создание объекта рядом с группой и две независимые операции
подряд в столбец не тянутся:

```bsl
// Плохо - одиночное создание втянуто в столбец серии:
СтрокаТЗ           = ТЗ.Добавить();
СтрокаТЗ.Ключ      = Ключ;
СтрокаТЗ.Значение  = Значение;

// Плохо - независимые операции подряд:
Чтение = Новый ЧтениеДанных(Источник);
Части  = Чтение.Разделить(Разделитель);
```

**Чем добирать - табами.** Добор от имени до `=` делается табами до общей табопозиции, не пробелами. Блок выравнивается даже если в исходнике он не выровнен - привести к общей табопозиции при правке (`→` - символ таба):

```bsl
// Было - не выровнено:
КэшИсточников = Новый Структура;
КэшСсылок = Новый Структура;

// Стало - "=" на одной табопозиции, добор табами:
КэшИсточников→= Новый Структура;
КэшСсылок→→= Новый Структура;
```

**Исключение - мелкий добор пробелами.** Если весь блок выравнивается добором не более чем 1-2 пробелов на строку (имена различаются на 1-2 символа и не перескакивают табопозицию), допустимы пробелы - тянуть таб ради одного-двух символов не нужно, это только раздвинет колонку:

```bsl
Сумма = 0;
Итог  = 0;   // один пробел добора - пробел допустим
```

### Логические операторы - верхний регистр

`И`, `ИЛИ`, `НЕ` - только в верхнем регистре, не `и`/`или`/`не`. Выделяет логические соединители на фоне русских имён, читаемее в многострочных `Если … ИЛИ … Тогда`.

### Inline-`Если` запрещён

Конструкция `Если ... Тогда ... КонецЕсли` в одну строку не используется - независимо от того, есть ли `Иначе` / `ИначеЕсли`. `Если` всегда оформляется как многострочный блок с отступом тела.

```bsl
// Плохо:
Если Флаг Тогда Структура.Вставить("Сумма", 0); КонецЕсли;
Если Количество > 0 Тогда Результат = Сумма / Количество; Иначе Результат = 0; КонецЕсли;

// Хорошо:
Если Флаг Тогда
	Структура.Вставить("Сумма", 0);
КонецЕсли;

Если Количество > 0 Тогда
	Результат = Сумма / Количество;
Иначе
	Результат = 0;
КонецЕсли;
```

Тернарный оператор `?(Условие, Значение1, Значение2)` разрешён и применим для выражений-значений в одну строку.

## Проверка пустоты коллекций

Использовать `ЗначениеЗаполнено()` вместо `.Количество() = 0`:

```bsl
// Плохо:
Если МассивДанных.Количество() = 0 Тогда ...
Если МассивДанных.Количество() > 0 Тогда ...

// Хорошо:
Если НЕ ЗначениеЗаполнено(МассивДанных) Тогда ...
Если ЗначениеЗаполнено(МассивДанных) Тогда ...
```

Тем же правилом проверяется «значение пустое» вообще. Сравнение с одним конкретным
литералом ловит только его: `= Неопределено` пропустит пустую строку, `= ""` пропустит
`Неопределено`. У данных из внешнего JSON приходят оба варианта.

```bsl
// Плохо: Null и "" пройдут дальше как заполненные
Ответ.Текст = ?(ТекстОтвета = Неопределено, "", ТекстОтвета);

// Хорошо:
Ответ.Текст = ?(НЕ ЗначениеЗаполнено(ТекстОтвета), "", ТекстОтвета);
```

## Структуры и коллекции передаются по ссылке

`знач` у параметра запрещает переприсваивать саму переменную, но **не защищает
содержимое**: структура, массив, соответствие приходят по ссылке, и правка поля
внутри метода видна вызывающему. Присваивание переменной тоже ссылку не разрывает -
`Копия = Настройки` даёт второе имя тому же объекту.

Чтобы изменить настройки только для себя - возвращать **новую** структуру, а не
править параметр:

```bsl
// Плохо: правка протечёт к вызывающему, хотя параметр объявлен «знач»
Процедура ОтключитьРазмышления(знач Настройки)
	Настройки.РежимРазмышлений = "БезИзменений";
КонецПроцедуры

// Хорошо: конструктор контракта + копирование значений
Функция НастройкиСРежимомРазмышлений(знач Настройки, знач Режим)
	Копия = prj_НастройкиКлиентСервер.НастройкиПровайдера();
	ЗаполнитьЗначенияСвойств(Копия, Настройки);
	Копия.РежимРазмышлений = Режим;
	Возврат Копия;
КонецФункции
```

`ЗаполнитьЗначенияСвойств` копирует **поверхностно**: вложенные структуры (у примера
выше - вложенная `Прокси`) у копии и оригинала остаются общими, и правка их полей снова
протечёт. Либо не трогать вложенное, либо заводить новую вложенную структуру, либо
брать `ОбщегоНазначения.СкопироватьРекурсивно` (только серверный контекст).

Локальная переменная-алиас (`НастройкиЗапроса = Настройки`) допустима, когда по ходу
метода она **переприсваивается** другим объектом (шаг цикла, откат к другим
параметрам). Читатель по строке `X = Y` не отличит алиас от копии - в таком месте
нужен комментарий о намерении.

## Привилегированный режим

Использовать минимально и всегда выключать:

```bsl
УстановитьПривилегированныйРежим(Истина);
// Операция, требующая полных прав
УстановитьПривилегированныйРежим(Ложь);
```

## Чистота diff

При редактировании существующего кода каждая строка в diff должна быть обоснована задачей. Запрещено:

- Добавлять комментарии к коду, который не менялся функционально
- Добавлять `Попытка/Исключение` там, где нет нового риска
- Переименовывать переменные/функции в неизменённом коде
- Добавлять логирование без необходимости по задаче
- Переформатировать строки, которые не менялись функционально

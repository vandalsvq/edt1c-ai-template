# Стандарты кода BSL

Стандарты написания кода на платформе 1С:Предприятие. Префикс объектов и название проекта - см. [`../CLAUDE.md`](../CLAUDE.md).

## Комментарии

**Не добавлять комментарии по умолчанию.** Код должен быть понятен без них. Комментарий уместен, когда добавляет то, чего кодом не выразить:

- мотивация неочевидного решения (почему именно так);
- суть нетривиального алгоритма, а не пересказ кода;
- ограничения и граничные случаи;
- технический долг (TODO, FIXME).

**Запрещено:** `// Получаем данные` и другие дубли кода; комментарий к каждой строке; комментарий, повторяющий имя функции; разделители (`// ---`) **вместо** `#Область` (вложенные `#Область` внутри процедуры - нормальное средство структурирования).

**Одна строка о сути.** Сначала вопрос «нужен ли вообще»: поведение видно из кода и имён - комментария нет. Поясняющий комментарий в коде и описание метода в докблоке - одна строка, две - предел. Рассуждение (рассмотренные варианты, что сломается иначе) - в спеке и плане: длинный комментарий к очевидному прячет те, что действительно нужны.

```bsl
// Плохо: пересказ решения спеки
// Событие старта пишется в журнал с той же секундой, что и последнее событие
// прошлого запуска, поэтому без вычитания оно попадёт в обе выборки; вариант
// со строгим неравенством в отборе журнала отклонён - отбор его не поддерживает.
КонецОкна = НачалоЗапуска - 1;

// Хорошо:
// Секунда старта - уже события нового запуска
КонецОкна = НачалоЗапуска - 1;
```

> **Doc-блоки - отдельная история.** В модулях с `// @strict-types` doc-блок метода обязателен
> для всех методов, включая неэкспортные и обработчики событий: это типовые аннотации для
> анализатора EDT. Формат, секции, порядок, выравнивание, составные типы и ссылки `см.` -
> [`bsl-strict-types.md`](bsl-strict-types.md) §2.

### В комментарии - причина, а не история

Комментарий отвечает, **почему код такой**. Даты проверок, номера задач, имена моделей и провайдеров, цифры замеров, ссылки на прогоны живут в спеке (`specs/<prefix>-<N>/plan.md`), не в модуле: в коде они устаревают и раздувают то, что читают на бегу.

```bsl
// Плохо: причина утонула в отчёте о замере
// Отбор по дате - параметром виртуальной таблицы. Замер 2026-08-05 на базе
// клиента: в ГДЕ запрос отрабатывал 12 секунд на 400 тыс. движений, с параметром - 0.3 с.

// Хорошо: осталась причина
// Отбор по дате - параметром виртуальной таблицы, а не в ГДЕ: иначе платформа
// сначала разворачивает весь период и фильтрует уже готовый результат.
```

Дата или номер задачи уместны там, где без них не разобраться: ссылка на внешний баг-трекер, срок обходного решения, привязка к версии платформы. Исключение - шапка тестового модуля: задача и параграфы спеки там говорят, какой контракт защищает тест, это адрес, а не история. В комментариях к самим тестам правило действует.

Предметные сокращения в комментарии расшифровываются («ДУЛ» → «документ, удостоверяющий личность»): читатель модуля не обязан знать предметную область, а непонятное сокращение прячет причину.

### Тире - только дефис-минус, длинное и среднее запрещены

**Везде**: код, строковые литералы и `НСтр`, комментарии и шапки методов, макеты и тексты форм, спеки (`specs/`, `planning/`), документация, сообщения коммитов, комментарии к задачам, текст ответов агента. Разрешён только дефис-минус `-` (U+002D); запрещены U+2014, U+2013, U+2212, U+2011 - здесь они названы кодами намеренно, чтобы начертание нельзя было скопировать в код. Причина одна на всех: в docblock дефис - разделитель парсера EDT (`Параметр - Тип - описание`), в коде и ключах длинное тире неотличимо от дефиса и ломает молча, в текстах - единообразие.

```bsl
// Хорошо:
//	АдресХранилища - Строка - адрес временного хранилища
// Ключ хранится по провайдеру: при смене - плейсхолдер либо пусто.
Сообщение = НСтр("ru='Шаблон не найден - выберите другой макет'");
```

Не считаются нарушением и не правятся **записанные артефакты**: трассировки внешних ответов, артефакты закрытых задач в `specs/done/` (прототипы, скрипты-генераторы), входные исследования и вендоренные копии сторонних проектов - это зафиксированные как есть записи, а не текст, который мы ведём. Если в проекте есть код, где другое тире требует сама платформа или внешний контракт, путь к нему заносится в исключение скрипта проверки (`ИСКЛЮЧЕНИЕ_ТИРЕ`).

Проверка - [`tools/diff-check/diff-check.py`](../tools/diff-check/diff-check.py) (добавленные строки диффа); вручную - Perl-ом, одинаково на macOS и в Git for Windows (`grep -P` там может отказать по локали):

```bash
git diff --cached -U0 | perl -CSD -ne 'print if /^\+/ && /[\x{2010}-\x{2015}\x{2212}]/'
```

## Структура модулей

Порядок областей в общем модуле:

1. `#Область ПрограммныйИнтерфейс` - экспортные, доступны всем, документированы
2. `#Область СлужебныйПрограммныйИнтерфейс` - экспортные, доступны внутри подсистемы
3. `#Область СлужебныеПроцедурыИФункции` - неэкспортные

Состав и порядок областей первого уровня закреплены. **Больше 10 методов в области - дробить на подобласти второго уровня** по назначению или связанности; меньше - по усмотрению автора. Имя подобласти - существительное в именительном падеже (`РазборОглавления`, `ЗагрузкаПакета`); имена-заглушки (`Прочее`, `Вспомогательные`, `Общее`) запрещены.

Внутри области, при прочих равных, процедуры выше функций; связность важнее порядка - методы, вызывающие друг друга, стоят рядом. Дополнительный порядок по директиве компиляции есть в модулях форм и команд - [`bsl-form-module-rules.md`](bsl-form-module-rules.md). В существующих модулях порядок наводится при значимой переработке области, а не отдельной правкой.

### Метод одного объекта - в модулях этого объекта

Метод, который нужен одному объекту (обработке, справочнику), живёт в модулях этого объекта: чтение его макета, справочные данные, расчёт без состояния - **модуль менеджера** (макет читается там же, прямым `ПолучитьМакет(...)`); работа с данными экземпляра - модуль объекта; интерфейс и данные формы - модуль формы.

В общий модуль метод выносится по поводу: его вызывают несколько объектов; он нужен на клиенте или из `&НаКлиентеНаСервереБезКонтекста` (модули менеджера и объекта есть только на сервере); его должен достать тест, а живёт он в модуле формы (серверный метод модуля менеджера тест достаёт и так). Повод перепроверяется, когда меняется устройство. Признак ошибки: общий модуль обращается по имени к макету, форме или реквизиту конкретного объекта (`Обработки.X.ПолучитьМакет("...")`) и вызывается только из этого объекта.

### Динамический доступ через `Вычислить` - в модуле объекта, не в форме

Обращение к тому, чего в базе может не оказаться (общий модуль БСП, объект другого расширения, механизм свежей платформы), пишется через `Вычислить` **в модуле объекта**: прямая ссылка не даёт модулю скомпилироваться целиком, а `Вычислить` превращает отсутствие в обычное исключение. Образец - `ОбщегоНазначения.ОбщийМодуль(Имя)` в БСП.

**В модуле формы динамики нет.** Прямые вызовы сохраняют типизацию и диагностики на коде, который правится чаще всего. Пригодность базы проверяется раньше: у внешней обработки - при регистрации (`СведенияОВнешнейОбработке()` отказывает с текстом администратору), у прочих объектов - при старте. Падение формы на компиляции в заведомо непригодной базе приемлемо: случай редкий, а цена динамики платится каждый день.

### Модуль объекта с вызовами серверных модулей - в обёртке `#Если Сервер`

Модуль объекта обработки компилируется и для толстого клиента управляемого приложения, где серверные общие модули (`ОбщегоНазначения`, серверные модули проекта) не видны: прямой вызов даёт ошибку EDT «Переменная X не определена [Толстый клиент (управляемое приложение)]». Тело модуля объекта оборачивается целиком, сразу после `// @strict-types`:

```bsl
// @strict-types

#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда

...

#КонецЕсли
```

Клиенту обёртка не мешает, если он работает с данными объекта через клиент-серверные модули, а не через методы объекта. Ставить обёртку сразу с первым вызовом серверного общего модуля, а не по факту диагностик.

## Обращение к контексту через `ЭтотОбъект`

В модулях с собственным контекстом (объект, набор записей, форма) к **данным** контекста и **методам платформы** обращаться через `ЭтотОбъект.`: в большом модуле короткая форма неотличима от локальной переменной.

```bsl
// Плохо: табличная часть выглядит как локальная переменная, метод платформы - как глобальный
Для Каждого СтрокаТовара Из Товары Цикл
ТекстовыйДокумент = ПолучитьМакет(ИмяМакета);

// Хорошо
Для Каждого СтрокаТовара Из ЭтотОбъект.Товары Цикл
ТекстовыйДокумент = ЭтотОбъект.ПолучитьМакет(ИмяМакета);
```

Под правило попадают реквизиты, стандартные реквизиты (`ЭтотОбъект.Ссылка`), табличные части, движения и методы платформы (`Метаданные()`, `ПолучитьМакет()`, `ПроверитьЗаполнение()`, `Закрыть()`). **Процедуры и функции самого модуля вызываются без префикса**, экспортные или нет: граница - по происхождению метода, а не по видимости. Исключения модулей форм (`Объект`, `Элементы`, `Команды`, `Параметры`, параметр `Форма` в хелперах) - [`bsl-form-module-rules.md`](bsl-form-module-rules.md), «Обращение через ЭтотОбъект».

Правило для нового кода; существующие модули массово не переписываются, строку, которую правка всё равно меняет, приводят к правилу.

## Именование

### Переменные

Не использовать венгерскую нотацию: `МассивКонтрагентов` → `Контрагенты`. Префикс типа коллекции (`ТаблицаКлиентов`, `МассивСообщений`) уместен только там, где различает проекции одного предмета: массив сообщений против табличной части `Объект.Сообщения`.

Именем переменной не бывают:

- имена глобального контекста: `Документы`, `Справочники`, `РегистрыСведений`, `Метаданные`, `Константы`, `ПараметрыСеанса`;
- методы глобального контекста и системные перечисления: не `ТекущаяДата`, `НачалоДня`, `ЧастиДаты`, а `ДатаСеанса`, `СоставДаты` - `Возврат ТекущаяДата;` читается как вызов платформы без скобок. Занято ли имя, показывает `/bsl-check <Имя>`: совпадение `Глобальный контекст.<Имя>`;
- имена примитивных типов и одноимённых функций (`Строка`, `Число`, `Дата`, `Булево`), конструируемых типов (`Массив`, `Структура`, `Соответствие`, `Тип`) и типов платформы с одноимённым конструктором (`Шрифт`, `Цвет`, `Картинка`): переменная занимает имя функции в пределах метода. Строка табличной части зовётся по коллекции: `СтрокаТовара`, `СтрокаСообщения`;
- ключевые слова языка (`И`, `Если`, `Для`, `Перем`, `Новый`, `Асинх` и остальные);
- имена реквизитов, табличных частей и методов **текущего объекта или формы**: локальная переменная перекрывает их в пределах метода, код компилируется, а тип подменяется (`Сообщения` при табличной части `Сообщения` → `СообщенияСессии`).

```bsl
// Плохо: в этом методе больше не написать Строка(Дата)
Для Каждого Строка Из Объект.Сообщения Цикл

// Хорошо:
Для Каждого СтрокаСообщения Из Объект.Сообщения Цикл
```

Правило - для нового кода. Существующий чистить отдельной правкой: в модуле соседствуют вызовы `Строка(...)` и переменные с этим именем, механическая замена ломает первые.

**Имя - предмет, а не его характеристика.** Одинокое прилагательное (`Сырой`, `Актуальный`, `Временный`) не отвечает на «что это»: `НормализованныйПрофиль(знач Сырой)` → `(знач ЭлементМакета)`.

**Без отрицаний в именах.** `БезОтключенияX` даёт двойное отрицание на месте чтения; называть состояние прямо: `РазмышленияОтключены`.

**Булев реквизит - утверждение о состоянии, не команда.** Не `ВключитьДиагностику`, а `ИспользоватьДиагностику`, `ЕстьОшибки`.

**Имя-заглушка роли не называет.** `Значение`, `Данные`, `Параметр`, `Объект` не говорят ничего; имя по типу значения (`ДвоичныеДанные`, `Текст`) - тоже, когда у типа в модуле одна роль (`ДвоичныеДанные` пакета документации - это `ПакетДокументации`). Исключение - метод работает с любым значением типа, и это сказано в докблоке (`Данные - Произвольный`). У полиморфа с закрытым перечнем форм имя даётся по сущности (`Сессия`), перечень форм - в докблоке.

**Имя-команда - у действия, не у значения.** Параметр, который метод куда-то записывает, называется по предмету: `Модифицированность`, не `УстановитьМодифицированность`. Флагу-переключателю ветки исполнения (`ОбновитьСвязь`) имя-команда допустимо.

### Длина имени - от 3 символов

Имена локальных переменных и параметров - 3+ символов; `ТЗ`, `Н`, `Кл`, `Стр` недопустимы: через несколько строк от объявления смысл теряется. Аббревиатура допустима как часть составного имени (`ВидТЗ`). Счётчик цикла - `Индекс`, не `И`. Правило для нового кода.

### Буква «ё» - только в текстах, не в идентификаторах

Идентификаторы (переменные, методы, поля структур, реквизиты, метаданные) пишутся через «е»: `СвернутоСообщений`, `Сохраненные`. «Ё» ломает поиск по коду и расходится с остальной базой. В текстах (комментарии, docblock, `НСтр`, заголовки, спеки) «ё» уместна и приветствуется.

### Без транслита англицизмов

Не транслитерировать английские термины кириллицей (`Капабилити`, `Фича`, `Воркер`, `Пресет`). Искать русский синоним, в первую очередь среди принятых терминов проекта (`КапабилитиПровайдера` → `ВозможностиПровайдера`). Латиница допустима там, где это установленный контракт: имена внешних API, общепринятые термины предметной области, имена типов и свойств XDTO-пакетов сериализации.

### Прямой смысл, а не метафора и не жаргон

Имя в коде говорит, что это, а не на что похоже. Метафоры и жаргон из обсуждений в код не переносятся - ни в идентификаторы, ни в области, ни в синонимы метаданных, ни в комментарии: читатель кода не был в беседе, где придумали метафору, а слово, занятое платформой или проектом, путает («примитив» в 1С - примитивные типы).

```bsl
// Плохо                    // Хорошо
ОписанияРук()               ОписанияИнструментовИзменения()
НовыйКонвертОтвета()        НовыйОтветИнструмента()
КлиентскийПримитив          ПоручениеКаналу
```

В документах (спеки, планы, `docs/`) метафора уместна как название слоя, если рядом стоит имя в коде: «руки (`prj_АссистентИнструментыИзменения`)». Новое понятие проверяется двумя вопросами: понятно ли имя без беседы и не занято ли слово. Термин выбирает владелец: сомнение - вопрос до правки; новые слова спека выносит в раздел «Термины» ([шаблон](../specs/_template/spec.md)).

Слова из обсуждений, которые уже приходили в код жаргоном, проект держит стоп-листом в [`tools/diff-check/diff-check.py`](../tools/diff-check/diff-check.py) (`ЖАРГОН_СЛОВА`): скрипт ловит их во всех формах и на стыке составного имени (`ТактАгента`). Слово в прямом смысле («пачка документов») - не нарушение: исполнитель оставляет его и называет в отчёте. Новое слово такого рода - дописать сюда и в стоп-лист скрипта.

### Процедуры и функции

**Имя функции - существительное** (что возвращается), **имя процедуры - глагол** (что делает): `Если КоличествоНенайденных() > 0` читается естественно, `Если ПодсчитатьНенайденных() > 0` - нет. Предикаты - `ЭтоНовый()`, `ЕстьОшибки()`, `МожноИзменить()`. Глагол совершенного вида в имени функции допустим (`Сформировать…НаСервере`, `Получить…`) - устоявшийся стиль 1С.

**CQS - запрос не мутирует состояние.** Геттер (`Получить…`, `Прочитать…`, имя-существительное) только возвращает. Если чтение безопасно лишь после записи, синхронизацию делает **вызывающий**, а не читатель. Красный флаг - прилагательное-действие в геттере (`Актуальный`, `Обеспечить…`, `…СПодготовкой`): в нём спрятана команда.

```bsl
// Плохо: команда спрятана в запросе
Функция ПолучитьАктуальныйPDF(знач Макет)
	ЗаписатьВКэш(Макет);
	Возврат ПрочитатьКэш(Макет);
КонецФункции
```

**`знач` - строчными.** Заглавное `Знач` в новом коде не появляется: разнобой в регистре - лишний шум в diff. Когда `знач` ставится и когда нет - [`bsl-strict-types.md`](bsl-strict-types.md) §3.

**Валидаторы** (`Проверить*`) - функция с параметром `ВыдатьИсключение = Ложь`, возврат Булево (Истина = проверка пройдена). При неуспехе и `ВыдатьИсключение = Истина` - исключение с понятным текстом, иначе тихо Ложь. Вызывающий выбирает: `Если НЕ ПроверитьЯдро() Тогда …` либо `ПроверитьЯдро(Истина);` на входной точке.

### Имя параметра - роль в методе, а не контекст вызова

Имя параметра отвечает на вопрос «чем это значение является для метода», а не «откуда вызывающий его взял». Метод читают отдельно от вызовов: имя, понятное только вместе с вызывающим, заставляет восстанавливать чужой контекст, а со вторым вызывающим становится ложью.

```bsl
// Плохо: имена с кухни вызывающего - кем обработан, чьё окно
Функция ПрочитатьЗаписиЖурнала(знач ОбработанДо, знач КонецОкна)

// Хорошо: для метода это границы периода
Функция ПрочитатьЗаписиЖурнала(знач НачалоПериода, знач КонецПериода)
```

**Проверка:** закрыть все вызовы и прочитать тело. Признаки контекстного имени:

- имя требует знания вызывающего (`ОбработанДо` - кем?; `ФормаОкна` в методе, где окна нет);
- имя скопировано у соседа (переменная вызывающего, реквизит формы), где оно отличало значение от соседнего, а у метода этой разницы нет; хвост признака - тот же предмет в соседнем методе зовётся иначе;
- имя занято в модуле другим предметом (`Записи` - и записи дельты, и записи диагностики). Проверяется `Grep` по модулю. Одно имя с одной ролью в разных охватах - не нарушение; дефект - разные предметы под одним именем;
- докблок параметра объясняет смысл через вызывающего или через другой метод вместо того, чтобы назвать предмет: «см. `ДругойМетод`» у типизированного скаляра; ссылка «см. X», которая не разрешается в метод (ловит [`diff-check.py`](../tools/diff-check/diff-check.py)). Законно: происхождение, достоверность и предусловие **после** роли; «Структура: см. `НоваяПравка`» вместо состава; набор значений словами, без `см.` («из набора prj_Перечисления.ТипПоля»: `см.` EDT читает как тип - SU24, [`bsl-strict-types.md`](bsl-strict-types.md) §2).

**Провенанс в имени** (`Объявленный…`, `Прочитанный…`, `Проверенный…`) законен, когда метод опирается на него как на предусловие и сам не проверяет. Если тело признака не использует, имя взято у вызывающего.

Правилу не противоречат:

- имя типа контракта, его конструктора или поля (`ОтветИнструмента`, `Код`, `Текст`), в том числе усечённое (`Охват` от `ОхватПравки`), если метод читает значение так же, как вызывающий, а не видит в нём другую сущность;
- имена, заданные платформой и БСП (`Команда`, `Элемент`, `СтандартнаяОбработка`, `Отказ`, `ДанныеСобытия`, `ДлительнаяОперация`);
- параметр, предмет которого и есть вызывающий (`Форма`, `АдресСтека`);
- сокращение, вынужденное пространством имён модуля: роль-точное имя закрыло бы вызов одноимённой функции в теле (параметр `КлючЦепочки` против функции `КлючЦепочки()`) - тогда берётся имя поля контракта или предмет из докблока конструктора. Коллизия с реквизитом или свойством хозяина модуля решается уточнением: в форме со свойством `Заголовок` параметр зовётся `ЗаголовокОкна`.

**Исключение не отменяет коллизию.** Усечение не берётся, если усечённое слово уже занято другим контрактом, конвенцией модуля (`Результат`, `Ответ`, `Описание`) или локальной переменной возврата (`Результат.Результат`). Имя поля контракта не оправдывает себя, если само нарушает «Имя-заглушка роли не называет»: тогда находка - на контракт целиком.

**Границы правки.** Правило - для нового кода и метода, который и так переписывается. Переименование в существующем методе - отдельная правка: вызовы позиционные, но правятся докблоки, тексты исключений с именем параметра, справочник модулей проекта и тесты. Термин семейства методов и имя, которое тянется через цепочку обёрток, правятся целиком или не правятся вовсе; разнобой по семейству (`Состояние`, `Тема`, `Объект` в методах одной подсистемы) - решение о словаре, а не находка в отдельном звене; находка - звено, выбивающееся из словаря. У обёртки с докблоком «см. исполнитель» без блока «Параметры:» имя параметра обязано различать контракт.

## Запросы

### Русскоязычный синтаксис запросов

В коде и документах - только русскоязычные ключевые слова языка запросов (`ВЫБРАТЬ`, `ЛЕВОЕ СОЕДИНЕНИЕ`, `СГРУППИРОВАТЬ ПО`, `ЕСТЬNULL`, `ВЫБОР КОГДА`); английские (`SELECT`, `JOIN`, `CASE`) не используются. Справочник языка - [`bsl-query-reference.md`](bsl-query-reference.md).

### Форматирование запроса

Текст запроса без отступа на новой строке после `=`; после `|` - таб; псевдонимы `КАК` не выравниваются - между выражением и `КАК` ровно один пробел (колонка разъезжается при каждом новом поле и даёт diff на весь список):

```bsl
Запрос.Текст =
"ВЫБРАТЬ
|	Таблица.Поле КАК Поле,
|	Таблица.Поле2 КАК Поле2
|ИЗ
|	Справочник.Таблица КАК Таблица
|ГДЕ
|	Таблица.Поле = &Параметр";
```

### Редактирование чужих запросов

Сохранять стиль оригинала: не вводить конкатенацию строк (добавляемые строки вписываются внутрь единого литерала, а не через `+ "..."`), сохранять выравнивание `|` и ключевых слов.

### Промежуточная переменная для результата

```bsl
// Плохо:
Выборка = Запрос.Выполнить().Выбрать();

// Хорошо:
РезультатЗапроса = Запрос.Выполнить();
Выборка = РезультатЗапроса.Выбрать();
```

Частный случай общего правила - «Точка после вызова - результат в переменную» (раздел «Форматирование»).

### Псевдонимы полей и таблиц

Всегда через `КАК`. Псевдоним таблицы информативный, не однобуквенный, и **не совпадает с именем поля** этой таблицы: `Местонахождение.Местонахождение` даёт ошибку платформы - псевдоним `МестонахождениеОС`.

## Сообщения и исключения

### Вывод сообщений

Не `Сообщить()`. Текст - через `НСтр` (см. «Пользовательские тексты (НСтр)»):

```bsl
// На сервере:
ОбщегоНазначения.СообщитьПользователю(
	НСтр("ru='Ошибка при обработке данных.'"), , "Объект.Реквизит", , Отказ);

// На клиенте:
ОбщегоНазначенияКлиент.СообщитьПользователю(НСтр("ru='Ошибка при обработке данных.'"));
```

### Обработка исключений

Не глотать исключения молча. Логировать и пробрасывать:

```bsl
Попытка
	// Опасная операция
Исключение
	ТекстОшибки = ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке());
	ЗаписьЖурналаРегистрации(
		"Модуль.Функция",
		УровеньЖурналаРегистрации.Ошибка, , , ТекстОшибки);
	ВызватьИсключение;
КонецПопытки;
```

`Попытка` - для действительно опасных операций (COM, внешние вызовы, файлы), не для штатных операций с БД.

Представления ошибки - через `ОбработкаОшибок` (`КраткоеПредставлениеОшибки` для показа пользователю, `ПодробноеПредставлениеОшибки` для журнала и исключений). Глобальные `ОписаниеОшибки()`, `КраткоеПредставлениеОшибки()`, `ПодробноеПредставлениеОшибки()` не применять: не рекомендуются с 8.3.17.

## Пользовательские тексты (НСтр)

Все тексты, видимые пользователю (сообщения, предупреждения, заголовки, вопросы, представления в исключениях), - через `НСтр`, не голым строковым литералом.

**Синтаксис:** `НСтр(<ИсходнаяСтрока>, <КодЯзыка>)`. `ИсходнаяСтрока` - варианты на разных языках через `;` в формате `код='текст'`; `КодЯзыка` (необязательный) - по умолчанию язык текущего пользователя.

```bsl
// Хорошо:
Текст = НСтр("ru='Документ не проведён.'");

// Плохо - голый литерал:
Текст = "Документ не проведён.";
```

- Пробелов в разметке нет: ни вокруг `=`, ни после `;` - `ru='Текст';en='Text'`, в многострочном литерале то же: `|en='Text'`.
- Одинарные кавычки внутри - удвоением: `'это ''пример'''`.
- Нужен ли второй язык - решение проекта ([`../CLAUDE.md`](../CLAUDE.md)); проект может сделать его обязательным. Если вариантов несколько, они заводятся сразу все, перевод осмысленный, а не машинный, плейсхолдеры `%1` присутствуют в каждом.
- Подстановки - платформенным `СтрШаблон` (до 10 параметров), не конкатенацией внутри `НСтр` и не устаревшим `СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку`. Параметры в массиве или больше десяти - `ПодставитьПараметрыВСтрокуИзМассива`.

```bsl
Текст = СтрШаблон(НСтр("ru='Документ %1 не проведён.'"), Ссылка);
```

**Исключение:** строки технического назначения в `НСтр` не оборачиваются - имена реквизитов в `СообщитьПользователю`, ключи структур, имена полей запроса, тексты для журнала регистрации без показа пользователю.

## Транзакции

`НачатьТранзакцию()` - **строго до** `Попытка`, не внутри (иначе `ОтменитьТранзакцию()` вызовется и там, где транзакция не начиналась):

```bsl
НачатьТранзакцию();
Попытка
	// ...
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию();
	ЗаписьЖурналаРегистрации(
		"Модуль.Функция",
		УровеньЖурналаРегистрации.Ошибка, , ,
		ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
	ВызватьИсключение;
КонецПопытки;
```

`ЗафиксироватьТранзакцию()` - последний оператор перед `Исключение`; `ОтменитьТранзакцию()` - первый в `Исключение`; между `НачатьТранзакцию()` и `Попытка` кода нет.

## Даты

`ТекущаяДатаСеанса()`, не `ТекущаяДата()`: первая учитывает часовой пояс пользователя, вторая зависит от машины. На клиенте - `ОбщегоНазначенияКлиент.ДатаСеанса()` ([`bsl-anti-patterns.md`](bsl-anti-patterns.md) №13).

## Конкурентность и блокировки

Блокировки нужны при изменении данных, чтении с последующей записью, работе с автонумерацией. Предпочитать управляемые:

```bsl
Блокировка = Новый БлокировкаДанных;
ЭлементБлокировки = Блокировка.Добавить("Справочник.Клиенты");
ЭлементБлокировки.УстановитьЗначение("Ссылка", СсылкаКлиента);
Блокировка.Заблокировать();
```

Обработчики событий объектов (`ПередЗаписью`, `ПриЗаписи`) выполняются в транзакции записи - дополнительные блокировки не нужны.

## Форматирование

### Отступы и выравнивание - табы

Все отступы и колоночное выравнивание - табом (`\t`), ширина 4. Отступ строки - по уровню вложенности; колоночное выравнивание (`=`, аргументы `Вставить`) - табами до общей табопозиции (мелкий добор 1-2 пробела - исключение, см. «Выравнивание в однотипных блоках»); перенос длинных параметров - табами от уровня вызова; текст запроса - таб после `|`; в doc-комментариях - табами и перед именем, и в колонке перед `-` (подробности и проверка - [`bsl-strict-types.md`](bsl-strict-types.md) §2). Смешанный вариант «отступ табами, колонка пробелами» не допускается: разъезжается с окружением и даёт diff-шум.

В примерах ниже `→` - символ табуляции (в Markdown реальные табы рендерятся по-разному):

```bsl
Если Флаг Тогда
→Структура.Вставить("Сумма", 0);
КонецЕсли;

Настройка.Наименование→→= "Формирование уведомлений";
Настройка.ИмяДляРазработчика→= "ФормированиеУведомлений";
```

Перед записью большого блока - посмотреть, как окружающий код использует табы, и зеркалить.

### Ограничение строки - 120 символов

Переносить строки длиннее 120 символов (считать символы, не байты); короче - не переносить без нужды. Не умещается из-за вложенного вызова - сначала вынести его в переменную, переносить уже остаток.

### Вложенные вызовы - всегда в переменную

Вызов с параметрами в аргументе другого вызова выносится в локальную переменную с говорящим именем - и тогда, когда внешний вызов помещается в одну строку ([ИТС 640](https://its.1c.ru/db/v8std#content:640:hdoc)): у промежуточного значения появляется имя, его видно в отладчике, вызов не приходится разбирать по скобкам.

```bsl
// Плохо: строка короткая, но в аргументе вызов с параметрами
РазобратьРеестр(ПолныйРеестр(Окружение), Корректные, Нарушения);

// Хорошо:
Реестр = ПолныйРеестр(Окружение);
РазобратьРеестр(Реестр, Корректные, Нарушения);
```

Не считаются нарушением (точный перечень - в скрипте [`nested-calls.pl`](../tools/nested-calls/nested-calls.pl), запуск - через [`diff-check.py`](../tools/diff-check/diff-check.py) или по чек-листу [`bsl-code-review.md`](bsl-code-review.md)):

- `НСтр`, `ПредопределенноеЗначение`, `Тип`, `ТипЗнч`, `ОбработкаОшибок.*ПредставлениеОшибки` в аргументе; их собственные аргументы подчиняются правилу;
- вызов без параметров - читается как значение: `ИмяНастройки()`, `ТекущаяДатаСеанса()`;
- простые методы платформы над строками, числами, датами, булевыми и УИД (`Стр...`, `СокрЛП`, `Лев`, `Формат`, `Строка`, `Число`, `НРег`, `Окр`, функции дат, `ЗначениеЗаполнено`, `Новый УникальныйИдентификатор`) - в аргументе любого вызова и друг в друге на любую глубину: `НачалоДня(КонецМесяца(ДобавитьМесяц(Дата, 1)))`;
- метод модуля или объекта в аргументе **одного** простого метода: `Окр(РассчитатьСумму(Строка), 2)`, `СтрШаблон(НСтр(...), ПредставлениеЗаявки(Заявка))`. Внутри двух простых подряд (`СокрЛП(Лев(ИмяФайла(Путь), 10))`) и в аргументе метода модуля - нарушение;
- конструктор `Новый <Тип>(...)` в аргументе любого вызова и в другом конструкторе; его собственные аргументы подчиняются правилу; `Новый Структура` в аргументе - не больше чем с тремя ключами;
- метод модуля или объекта в аргументе `Вставить` и `Добавить` - на один уровень: `Результат.Вставить("Поле", ДоступноеПоле(ИмяПоля(Строка)))` - нарушение.

Глазом вложенность пропускается - проверка отдельным проходом скриптом. После правки перечня в скрипте - самопроверка по `cases.bsl`, команда - в шапке скрипта.

Правило - для нового и переписываемого кода; строку, которую правка всё равно меняет, приводят к правилу (см. «Чистота diff»). В модулях тестов (проект тестов) правило не действует - как и «Коллекция цикла»: в проверках вида `ЮТест.ОжидаетЧто(ЕстьВСписке(Список, Значение))` промежуточная переменная только удлиняет тест.

Несколько вынесенных аргументов одного вызова - «цепочка `Параметр = ...` в подготовке вызова», выравнивается по правилу однотипных блоков. Шаги, где результат одного идёт аргументом в следующий, серией не считаются и не выравниваются; такие выровненные пары находит [`diff-check.py`](../tools/diff-check/diff-check.py) (кроме модулей тестов), старый соседний код с ними - не образец. Для цепочек через точку (`Запрос.Выполнить().Выбрать()`) та же мысль - «Точка после вызова - результат в переменную».

### Коллекция цикла - в переменной

Вызов с параметрами и цепочка вызовов не ставятся в заголовок `Для Каждого`: коллекция сначала в локальную переменную, цикл по ней - у коллекции появляется имя, её видно в отладчике до входа в цикл.

```bsl
// Плохо:
Для Каждого СтрокаПоля Из СтрокиДоступныхПолейНабора(ДоступныеПоля, КлючНабора) Цикл
Для Каждого СтрокаТаблицы Из Запрос.Выполнить().Выгрузить() Цикл

// Хорошо:
МассивСтрок = СтрокиДоступныхПолейНабора(ДоступныеПоля, КлючНабора);
Для Каждого СтрокаПоля Из МассивСтрок Цикл
```

В заголовке допустимы: переменная, параметр или реквизит (`Из ЭтотОбъект.Товары`); один вызов без параметров, не цепочка (`Из ОписаниеТипов.Типы()`); простой метод платформы на всё выражение (`Из СтрРазделить(Имя, ",", Ложь)`), его аргументы подчиняются правилу вложенных вызовов. Область применения - та же, что у вложенных вызовов.

### Точка после вызова - результат в переменную

К свойству или методу прямо на результате **любого** вызова не обращаются - ни у запроса, ни у своей функции, ни у метода платформы: `СтрокиДокумента(Документ).Количество()`, `Кэш.Получить(Ключ).Наименование`. Результат - в переменную с именем «что вернулось». Три довода: имя читается быстрее цепочки; на `Неопределено` цепочка падает «Поле объекта не обнаружено» без указания, на каком вызове, а у переменной есть место для проверки и её видно в отладчике; второе обращение к результату не повторяет вызов.

```bsl
// Плохо: ключа нет в кэше - «Поле объекта не обнаружено»
Наименование = КэшПартнеров.Получить(Партнер).Наименование;

// Хорошо:
ДанныеПартнера = КэшПартнеров.Получить(Партнер);
Если ДанныеПартнера <> Неопределено Тогда
	Наименование = ДанныеПартнера.Наименование;
КонецЕсли;
```

Не нарушение: точка после переменной, параметра или реквизита (`Объект.Товары.Количество()`) и точка перед вызовом метода модуля или менеджера (`Справочники.prj_Макеты.НайтиПоКоду(Код)`, `ОбщегоНазначения.ЗначениеРеквизитаОбъекта(...)`). Область применения - та же, что у вложенных вызовов.

### Пустая строка между комментарием и директивой области

`#Область` и `#КонецОбласти` отделяются от соседних комментариев пустой строкой, иначе в свёрнутом виде комментарий прилипает к заголовку области.

### Выравнивание в однотипных блоках - обязательно

В блоке из идущих подряд однотипных строк выравнивание **обязательно**, по самому длинному имени: присваивания свойств (`=`), аргументы `Вставить` / `УстановитьПараметр` / `Колонки.Добавить`, инлайн-комментарии типов, цепочки `Параметр = ...` в подготовке вызова. Блок выравнивается и тогда, когда в исходнике не выровнен. `→` - таб:

```bsl
Настройка.Наименование→→= "Формирование уведомлений";
Настройка.ИмяДляРазработчика→= "ФормированиеУведомлений";
Настройка.СписокЗначений→→= Ложь;
```

**Добор - до запятой, не после:** запятая - часть первого аргумента, после неё ровно один пробел:

```bsl
// Плохо: запятые в разных колонках
ПараметрыФормы.Вставить("ОписаниеТипов",→→ТипСвойства());
ПараметрыФормы.Вставить("БыстрыйВыбор",→→→Ложь);

// Хорошо:
ПараметрыФормы.Вставить("ОписаниеТипов"→→, ТипСвойства());
ПараметрыФормы.Вставить("БыстрыйВыбор"→→, Ложь);
```

**Только серии.** Одиночное создание объекта рядом с группой (`СтрокаТаблицы = Таблица.Добавить();` перед заполнением её полей) и две независимые операции подряд в столбец не тянутся.

**Чем добирать - табами.** Исключение - мелкий добор: если весь блок выравнивается не более чем 1-2 пробелами на строку (имена не перескакивают табопозицию), допустимы пробелы: `Сумма = 0;` / `Итог  = 0;`.

### Логические операторы - верхний регистр

`И`, `ИЛИ`, `НЕ` - только в верхнем регистре: выделяет соединители на фоне русских имён.

### Присваивание результата условия - условие в скобках

В BSL `=` - и присваивание, и сравнение: `Результат.Выполнено = КодВозврата = 0` читается как цепочка присваиваний. Пишется `Результат.Выполнено = (КодВозврата = 0);`. Условие-аргумент тернарного оператора и условие после `Если` скобок не требуют.

### Inline-`Если` запрещён

`Если ... Тогда ... КонецЕсли` в одну строку не используется, с `Иначе` или без: всегда многострочный блок с отступом тела. Тернарный оператор `?(Условие, Значение1, Значение2)` разрешён для выражений-значений.

**Простое присваивание по условию - тернарным оператором.** Если обе ветки `Если ... Иначе` только присваивают одной переменной простое значение, пишется `?()` одной строкой: пять строк на одно присваивание читаются дольше одной. Условия: в ветках нет ничего, кроме присваивания; значения - переменная, литерал, арифметика или простой метод платформы (вызов с параметрами - заранее в переменную, «Вложенные вызовы»); строка укладывается в 120 символов; `?()` в `?()` не вкладывается. Не выполнено хоть одно - многострочный `Если`.

```bsl
// Плохо:
Если ЭтоВозврат Тогда
	Множитель = -1;
Иначе
	Множитель = 1;
КонецЕсли;

// Хорошо:
Множитель = ?(ЭтоВозврат, -1, 1);
```

## Проверка пустоты коллекций

`ЗначениеЗаполнено()` вместо `.Количество() = 0` / `> 0`. Тем же правилом проверяется «значение пустое» вообще: сравнение с одним литералом ловит только его (`= Неопределено` пропустит пустую строку, у данных из внешнего JSON приходят оба варианта):

```bsl
// Плохо: Null и "" пройдут дальше как заполненные
Ответ.Текст = ?(ТекстОтвета = Неопределено, "", ТекстОтвета);

// Хорошо:
Ответ.Текст = ?(НЕ ЗначениеЗаполнено(ТекстОтвета), "", ТекстОтвета);
```

## Структуры и коллекции передаются по ссылке

`знач` запрещает переприсвоить переменную параметра, но **не защищает содержимое**: структура, массив, соответствие приходят по ссылке, правка поля внутри метода видна вызывающему; `Копия = Настройки` даёт второе имя тому же объекту. Это не довод против `знач` по умолчанию ([`bsl-strict-types.md`](bsl-strict-types.md) §3, там же - граница клиент → сервер, где поведение обратное), а довод против расчёта на приватную копию. Метод, который по контракту заполняет переданную таблицу, объявляет её `знач` и заполняет; ошибка - когда правку задумывали приватной.

Изменить настройки только для себя - вернуть **новую** структуру: конструктор контракта плюс `ЗаполнитьЗначенияСвойств(Копия, Настройки)`. Копирование **поверхностное**: вложенные структуры остаются общими - либо не трогать вложенное, либо заводить новую вложенную, либо `ОбщегоНазначения.СкопироватьРекурсивно` (только сервер). Локальный алиас (`НастройкиЗапроса = Настройки`) допустим, когда по ходу метода он переприсваивается другим объектом, - с комментарием о намерении.

## Привилегированный режим

Использовать минимально, по месту и только для технического обхода проверки прав платформы; право пользователя на функцию проверять ролью отдельно. Случаи, где он обязателен, - [`bsl-anti-patterns.md`](bsl-anti-patterns.md) №9.

Режим действует до выхода из метода, где включён, и платформа снимает его сама: `УстановитьПривилегированныйРежим(Ложь)` в конце не нужен. Явно выключать - только если после привилегированной операции в том же методе идёт код, которому полные права не нужны (вызовов с `Ложь` в методе не больше, чем с `Истина`, иначе исключение). Поэтому операция выносится в отдельный небольшой метод, а у включения - комментарий, какую проверку прав он обходит: по нему ревьюер видит, что обходится техническая проверка платформы, а не право пользователя на функцию.

```bsl
// Возвращает события журнала регистрации по отбору.
//
// Параметры:
//	Отбор - Структура - отбор журнала регистрации.
//
// Возвращаемое значение:
//	ТаблицаЗначений - события журнала.
//
Функция СобытияЖурнала(знач Отбор)
	
	События = Новый ТаблицаЗначений;
	// Право «Журнал регистрации» - только у администратора; право на историю проверено ролью prj_ПросмотрИстории
	УстановитьПривилегированныйРежим(Истина);
	ВыгрузитьЖурналРегистрации(События, Отбор);
	
	Возврат События;
	
КонецФункции
```

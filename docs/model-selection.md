# Стратегия выбора модели

Руководство по выбору модели Claude при работе над задачами проекта.

---

## Принцип

**Opus — основная рабочая модель. Sonnet — только для независимого кросс-ревью.**

Весь основной объём работы выполняется на Opus. Sonnet применяется исключительно для независимой проверки плана или готового кода другой моделью.

---

## Распределение задач

### Opus — все задачи

- **Архитектура:** проектирование, выбор решений, breaking changes, миграция
- **Безопасность:** ревью кода, аудит RLS, поиск уязвимостей
- **Сложные баги:** порча данных, race conditions, регрессии
- **Кодогенерация:** формы, тесты, запросы, скрипты, модули
- **Рефакторинг:** упрощение, извлечение методов, консолидация
- **Исследование:** навигация по коду, поиск, документация
- **Итеративная работа:** баг-фиксы, реализация фич, тестирование

### Sonnet — только кросс-ревью

- **После завершения кода** — ревью изменённых файлов независимым взглядом
- **После составления плана** — ревью плана на полноту, порядок шагов и риски

---

## Экономия контекста

- **Инкрементальная загрузка:** читать нужный фрагмент, а не весь файл
- **Изоляция через субагентов:** параллельные независимые задачи — в отдельных агентах
- **Батчинг операций:** одна сводная задача вместо множества мелких вопросов
- **Переиспользование результатов:** сохранять найденные решения и паттерны

---

## Антипаттерны

- Использовать Sonnet для основной работы (экономия не стоит потери качества)
- Использовать Opus для ревью собственного кода (нет независимости)
- Читать модуль целиком при поиске одного метода (использовать Grep)
- Запускать субагентов последовательно там, где они независимы (использовать параллельный запуск)
- Продолжать чат при огромном контексте — лучше начать новый с нужными фактами

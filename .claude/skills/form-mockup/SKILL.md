# Макет формы 1С для ТЗ

Инструмент - `tools/form-mockup/formmockup.py` (Python 3, только стандартная библиотека; PNG -
через Google Chrome или Chromium без окна). Форма описывается **моделью** - JSON-деревом
элементов, как в конфигураторе: группы, поля, таблицы, командные панели, без координат.
Раскладку считает рендерер, как платформа. Все пути ниже - от корня репозитория.

| Что | Где |
| --- | --- |
| Справочник видов и свойств модели, правила `check` | `tools/form-mockup/schema/model.md` |
| Схема модели | `tools/form-mockup/schema/form-model.schema.json` |
| Примеры: форма документа, форма списка, пара «было / стало» | `tools/form-mockup/examples/` |
| Стандарты вёрстки форм 1С (источник правил ниже) | `docs/bsl-form-design-8.3.md` |

Перед первой моделью в сессии прочитать `model.md` целиком: в модели только его имена видов и
свойств. Имя не помнится - `formmockup.py ru <слово>` переводит в обе стороны («Поле ввода»
→ `InputField`, `titleLocation` → «Положение заголовка», `titleLocation=None`).

## Команды

```text
F=tools/form-mockup/formmockup.py
python3 $F import <Form.form|Form.xml> -o <каталог>/model.json   модель по XML формы + отчет импорта
python3 $F check  <каталог>/model.json                           проверка модели
python3 $F render <каталог>/model.json -o <каталог>/out --png    HTML, PNG, замечания раскладки
python3 $F render <каталог>/model.json --before <каталог>/before.json -o <каталог>/out --png
                                                                 то же с правками против прежней версии
python3 $F table  <каталог>/model.json [--before <каталог>/before.json]
                                                                 таблица элементов или изменений, Markdown
python3 $F compare <макет.json> <Form.form|Form.xml|модель.json>  сверка собранной формы с макетом, Markdown
python3 $F ru     <слово> [<слово> ...]                          перевод имен по словарю
python3 $F serve  <каталог>/model.json [--src <исходники>] [--before <каталог>/before.json]
                                                                 конструктор в браузере - раздел «Конструктор»
python3 $F serve  <папка макетов>                                 список макетов папки, новая форма, импорт
```

**Windows.** Вместо `python3` - `python` (или `py -3`): `python3` на Windows бывает заглушкой Microsoft
Store - отвечает «Python was not found» и ничего не запускает. Claude Code работает в Git Bash: команды
как выше, кодировка не настраивается. Codex - в PowerShell: перед командами один раз
`[Console]::OutputEncoding = [Text.Encoding]::UTF8`, иначе PowerShell прочтет вывод инструмента
(UTF-8) в кодировке консоли, и кириллица придет кракозябрами. Chrome находится сам (установка для
всех и для пользователя), без него снимки и сценарии страницы идут через Edge.

Выход `render`: `out/<имя модели>.html` - одна самодостаточная страница (открывается без
сети, прикладывается к ТЗ); `out/<имя>.png` и `out/<имя>__<панель>_<закладка>.png` на каждую
закладку не по умолчанию; с `--before` - `<имя>__правки.png`, `<имя>__стало.png` и
`<имя>__правки__<панель>_<закладка>.png` по закладкам с правками. В модели есть `note` - еще
`<имя>__примечания.png` (номера примечаний в кружках, как колонка «№» таблицы) и
`<имя>__примечания__<панель>_<закладка>.png` по закладкам с примечаниями; основной снимок -
без номеров. `--state Панель:Закладка` открывает на снимке другую закладку.

**Каталог работы** - где скажет пользователь (обычно рядом с ТЗ); не сказал - отдельный
каталог задачи вне `tools/form-mockup/`. Имя файла модели = имя файлов HTML и PNG: называть
по форме (`zayavka.json`), а не `model.json`, если файлы пойдут в ТЗ.

## Сценарий 1. Форма по описанию задачи

1. **Состав.** Выписать из задачи вид формы (документ, элемент справочника, список, обработка),
   реквизиты шапки, табличные части с колонками, команды. Чего в задаче нет, а без него
   форма не строится, - **один** короткий вопрос пользователю, не серия. Элемент, который
   агент добавил от себя (стандартный «Комментарий», «Ответственный», итог под таблицей), -
   `"note": "предложение"`: в таблице ТЗ он помечен, пользователь решает, оставить ли.
2. **Модель.** Написать JSON по `model.md` и правилам вёрстки ниже. Образец -
   `examples/zakaz-pokupatelya.json` (документ), `examples/spisok-zakazov.json` (список).
3. **`check`** - исправлять, пока не «Замечаний нет».
4. **`render --png`** - и **открыть каждый PNG и посмотреть глазами**: обрезанные заголовки,
   поля разной ширины в одной колонке, пустые места, не та закладка. Нашелся изъян - правка
   модели, шаг 3. Замечания раскладки разобрать по таблице ниже.
5. **`table`** - таблица элементов для ТЗ.
6. **Отдать** - по разделу «Что отдать пользователю».

## Сценарий 2. Форма по XML

1. Найти XML формы. EDT: `<проект>/src/<Вид>/<Объект>/Forms/<Форма>/Form.form`; выгрузка
   конфигуратора: `<Вид>/<Объект>/Forms/<Форма>/Ext/Form.xml`. Файл брать **на месте** в
   дереве исходников, не копию: заголовки и типы полей импорт ищет в метаданных объекта по
   пути вверх от файла.
2. **`import ... -o <каталог>/<имя>.json`** и прочитать отчет импорта (таблица ниже).
3. **`render --png`**, посмотреть PNG. Замечания правил `check` у импортированной формы
   («больше 25 элементов» и т.п.) - свойство самой формы: не чинить, рисовать как есть.
4. Правка импортированной модели - только по просьбе пользователя (показать другую закладку -
   `--state`; убрать скрытое - не нужно, оно и так скрыто). Ограничения, которые сказать
   пользователю один раз: макет показывает форму «как в XML» - видимость, заголовки и тексты
   ссылок, которые ставит код формы при открытии, на макете не отражены; условного
   оформления и данных списка нет.
5. **`table`**, отдать.

Форма в режиме («вид операции Покупка», «для роли Кладовщик»): отдельный файл модели рядом с
базовой - копия, в которой агент по просьбе пользователя и по коду формы скрывает и
показывает элементы; разница с базовой - сценарием 3.

## Сценарий 3. Доработка с показом изменений

1. Исходная модель (нарисованная в сценарии 1 или импортированная в сценарии 2) - **копия**
   `<имя>-было.json`; ее не правят.
2. Править `<имя>.json` обычной правкой JSON по описанию доработки. Новые элементы - с новыми
   уникальными `name`; переименованный элемент - новое `name` и `"renamedFrom": "<старое>"`,
   иначе сравнение покажет «удален + добавлен». Перенос - просто переложить элемент в
   другое место дерева. Сравнение считает перенесенным то, что сменило родителя или
   нарушило порядок соседей, а не то, что назвала задача: «поле X - под флажки» при
   флажках, ушедших в новую группу, покажет перенос флажков, а X - на прежнем месте.
   Новая группа - одна правка с составом, ее новые элементы отдельно не нумеруются.
3. `check <имя>.json`.
4. **`render <имя>.json --before <имя>-было.json --png`** - проверить число «Правок» в выводе
   против числа доработок в задаче и открыть `__правки.png`: каждая доработка отмечена
   рамкой и номером; лишней правки нет (лишняя - случайно тронутое свойство: вернуть).
5. **`table <имя>.json --before <имя>-было.json`** - таблица изменений; номера в ней - как на
   рисунке правок.
6. Отдать: PNG «Правки» и «Стало», таблицу изменений, HTML (в нем режимы «Было / Стало /
   Правки» и список правок со щелчком к элементу).

## Сценарий 4. Сверка собранной формы с макетом

Форма собрана в конфигураторе или EDT по согласованному макету; сверка показывает, где собранная
форма отошла от макета.

1. **Отметить места кода в макете** - при согласовании или перед первой сверкой. Свойство
   `generated`: `"element"` - элемент целиком создает код или выводит платформа (колонки, которые
   строит код; поля отбора динамического списка): сверка не ищет его в форме; `"title"` - заголовок в
   макете - пример текста, который подменит код (надпись с примером, заголовок формы по режиму):
   заголовок не сравнивается. Без отметок сверка работает, но места кода попадают в отличия.
2. **`compare <макет.json> <Form.form>`** - XML формы брать на месте в дереве исходников, как в
   сценарии 2: заголовки и подсказки импорт берет из метаданных, у копии без исходников их нет, и
   выйдут ложные отличия. Вторым аргументом годится и модель JSON.
3. **Разобрать вывод** - три раздела:
   - **Отличия** - таблица изменений «макет → форма», как у `table --before`. Каждое отличие -
     либо ошибка сборки (исправить форму), либо решение, принятое при доводке (шаг 4);
   - **Заполняется кодом** - что сверка пропустила по отметке и что в форме на этом месте:
     глазами, на месте ли элемент;
   - **Уточнения** - свойства формы, которых нет у элемента в макете (подсказка, длина, цвет,
     отображение таблицы): отличием не считаются, просмотреть глазами.

   Не сравниваются `note` и `sample`; список выбора - по представлениям; состав команд - без
   порядка; заголовок - как его видит пользователь (свой, по пути к данным, по команде, по имени);
   явное умолчание платформы (`group: Vertical` обычной группы, `autoFill: true` командной
   панели) равно незаданному свойству - таблица `defaults` в `schema/property-groups.json`.
4. **Форма отошла от макета по решению** - обновить макет тем же изменением, что и форму:
   `import` формы в файл макета, примечания и примеры, нужные ТЗ, перенести из прежней версии,
   отметки `generated` поставить заново. Повторная сверка - код 0.

## Конструктор: доводка руками в браузере

`serve` открывает модель в конструкторе: дерево элементов, макет, панель свойств, как редактор
формы конфигуратора. Пользователь правит сам, кнопка «Сохранить» пишет тот же файл модели.
Режима без сервера нет: страница работает только с запущенным `serve`. Страница открывается
отдельным окном без вкладок (Chrome, без него Edge); «К списку» - все макеты папки файла.

**Человеку без терминала** (аналитик, владелец ТЗ) - не команда, а ярлык: в `tools/form-mockup/`
лежат `Открыть макеты.cmd` (Windows) и `Открыть макеты.command` (Mac). Двойной щелчок - последняя
папка макетов, перетащить на ярлык папку или модель - эту папку; окно закрыл - сервис через минуту
остановился сам. Подробно - `tools/form-mockup/README.md`, «Как открыть макет»: дать ссылку на
раздел одной строкой, когда пользователь хочет править макеты сам, без агента.

**Когда предложить** - одной строкой, не навязывая:

- мелкие правки положения, заголовков, группировки, порядка («это поле - выше», «эти три - в
  одну строку», «заголовок короче»): руками быстрее, чем пересказом;
- второй круг пересказа одной и той же правки - пересказ не доходит, пусть покажет;
- пользователь сам просит открыть форму, «дай я поправлю».

Форму с нуля по описанию и массовые правки (переименовать все колонки, добавить двадцать полей)
агент делает сам - конструктор не предлагать.

**Как открыть**

1. Сценарий 3: копия `<имя>-было.json` - **до** открытия, если ее еще нет (конструктор пишет в
   `<имя>.json`).
2. Поднять сервер **в фоне** (команда не завершается, пока сервер работает):

   ```text
   python3 $F serve <каталог>/<имя>.json [--src <исходники>] [--before <каталог>/<имя>-было.json]
   ```

   - `--src` - если исходники конфигурации известны (сценарий 2: каталог `src` проекта EDT или
     каталог выгрузки конфигуратора): окна выбора типа, картинки и цвета стиля показывают всю
     конфигурацию;
   - `--before` - в сценарии 3: конструктор отмечает правки против «было» с теми же номерами,
     что `render --before` и `table --before`;
   - окно на машине пользователя открывается само; `--no-browser` - если агент работает не на
     ней.
3. Первая строка вывода - `Конструктор: http://127.0.0.1:<порт>/edit?file=... - файл ...`: дать
   адрес пользователю и сказать, что после правок нужно нажать «Сохранить» (Ctrl+S / Cmd+S) и
   написать в чат. `Сервис на эту папку уже запущен: <адрес>` (код 0, команда сразу завершилась) -
   макет открыт в уже работающем сервисе папки: адрес - пользователю, второй сервер не нужен.

**Пока пользователь правит**

- Файл модели **не писать**: у пользователя могут быть несохраненные правки - запись агента
  покажет ему баннер «Файл изменён на диске» и заставит выбирать. Нужно поправить модель самому -
  сначала попросить сохранить в конструкторе.
- После «сохранил» - **перечитать файл** с диска, а не продолжать с моделью из памяти: в нем
  правки пользователя. Затем `check`, `render`, дальше по сценарию.
- Агент записал файл, пока страница открыта без несохраненных правок, - конструктор перечитает
  его сам; это нормально.
- Сервер останавливается сам: окно закрыто - через минуту без открытых страниц; не открыли за
  30 минут - тоже; «Завершить» на странице списка - сразу. Фоновая команда при этом завершается с
  кодом 0 - это не сбой. Новый `serve` на тот же файл - можно в любой момент.
- «порты 8190-8210 заняты» (код 2) - их держат чужие программы: свой первый порт - `serve --port N`
  на этот запуск или навсегда `{"port": N}` в `~/.form-mockup/config.json` (Windows -
  `%USERPROFILE%\.form-mockup\config.json`), переменная `FORMMOCKUP_PORT` важнее файла; ярлык
  пользователя берет тот же файл - предложить его создать, а не просить запускать из терминала.

**Codex.** Песочница `workspace-write` по умолчанию без сети: `serve` не может открыть порт и
отвечает кодом 2 «нет доступа к сети (песочница агента?)». Тогда - или пользователь разрешает
агенту сеть (`sandbox_workspace_write.network_access = true` в `~/.codex/config.toml`), или
`serve` запускает сам пользователь в своем терминале: агент дает ему готовую команду целиком и
дальше работает с файлом так же - не писать, пока правит, перечитать после «сохранил». Так же,
если фоновая команда не переживает конец хода (сервер пропадает между ответами). Вместо команды
человеку можно предложить ярлык (выше): он не требует терминала.

**Codex на Windows.** Настройки и скиллы - в `%USERPROFILE%\.codex\` (`config.toml`, `skills\`).
Сервер в фоне из PowerShell - отдельным процессом, который переживает конец хода:
`Start-Process python -ArgumentList 'tools/form-mockup/formmockup.py','serve','<каталог>/<имя>.json' -WindowStyle Hidden`.
Окно конструктора у пользователя откроется само; вывода сервера агент не видит, но адрес и не
нужен: сервер остановится сам, когда окно закроют. Песочница не дает открыть порт - ярлык (выше).

## Правила вёрстки

Сокращение `docs/bsl-form-design-8.3.md` для макета; спорный случай - там же, разделом.

**Модель**

- Писать только то, что отличается от умолчания платформы (`model.md`, «Принципы»).
  Заголовок не писать, если он равен имени, разбитому по словам (`ДатаОтгрузки` → «Дата
  отгрузки»).
- `name` - идентификатор 1С по-русски, уникален по всей форме, включая кнопки и колонки.
  Колонки таблицы - с префиксом таблицы (`ТоварыКоличество`), группы - `Группа<Смысл>`.
- `dataPath` у полей (`Объект.Контрагент`, `Объект.Товары.Количество`) - по нему таблица ТЗ
  говорит, какой реквизит нужен. Реквизиты формы и состав их типов (`attributes`, `types` -
  `model.md`, «Реквизиты формы») заполняет импорт и конструктор; в своей модели их можно не
  писать, а записанные - не терять при правке: по ним `check` сверяет пути.
- `dataType` у каждого поля ввода: от него выравнивание, ширина и кнопки (дата - календарь,
  ссылка - «▾» и «⧉», дробное число - калькулятор).
- `sample` - правдоподобные значения в полях и 2-3 строки таблицы: картинка без данных
  читается хуже. Обязательное поле, которое на картинке должно быть отмечено, - без
  `sample` и с `markIncomplete`.
- Ширина - в символах и только у полей с известным содержимым (числовые колонки, код);
  остальное считает рендерер.

**Раскладка**

- Командная панель формы по `formKind` заполняется сама («Провести и закрыть», «Записать»...);
  в `commandBar` - только свои команды: печать - подменю `Popup` «Печать» с картинкой
  `StdPicture.Print`, создание на основании - подменю «Создать на основании».
- Шапка документа: номер и дата - одной строкой сверху (горизонтальная группа); дальше две
  колонки - горизонтальная группа без отображения с двумя вертикальными: слева важные и
  вводимые вручную, справа автозаполняемые. Влияющее поле - выше или левее зависимого
  (организация до договора, контрагент до договора).
- Заголовки полей - слева, у флажков - справа (`"titleLocation": "Right"`); заголовки в
  одной колонке выравниваются сами (сквозное выравнивание).
- **Длинный заголовок среди коротких** (раза в 2,3 длиннее остальных в колонке) 1С переносит
  на две строки, а с ним - заголовки соседей и подписи флажков справа; рендерер делает так
  же. В своей форме такой заголовок сократить (std722 п.1.1.1); переносы на PNG - повод
  проверить заголовки, а не дефект рисунка.
- Табличная часть - на закладке, если закладок больше одной или таблица не главная;
  закладку из одного-двух полей не заводить, закладки - по содержимому. Одна закладка в
  панели - не закладка (правило `check`).
- Итоги - под таблицей, полями только просмотра, справа (группа с
  `childItemsHorizontalAlign: Right`), или подвалом таблицы (`footer` + `footerText`), если
  итоговых колонок больше четырех.
- Второстепенное - на закладку «Дополнительно» или в свертываемую группу (`behavior:
  Collapsible`); не больше ~25 видимых полей на закладке.
- «Комментарий» - внизу формы, многострочное поле на всю ширину (`multiLine`, `height: 2-3`,
  `horizontalStretch`).
- Группы - по смыслу, отображение - нет, слабое или обычное выделение; сильное
  (`StrongSeparation`) не использовать. Вложенность групп - не глубже 4.
- **Группа-обертка** (строка «номер и дата», колонки шапки, итоги) - `"showTitle": false`: в
  1С «Отображать заголовок» по умолчанию включено, и заголовок обертки встанет на форму
  зеленой строкой. Заголовок у нее все равно пишется - его видит «Изменить форму».
- Кнопки у правого края - группа с `childItemsHorizontalAlign: Right` и
  `horizontalStretch: true`. Связанные команды таблицы - `ButtonGroup` с `representation:
  Compact`.
- Форма списка - `formKind: ListForm`, таблица `Список` с `dataPath: "Список"`, отбор - поля
  над таблицей в горизонтальной группе.

## Ответ инструмента → действие

Коды возврата: 0 - чисто; 1 - есть замечания (модели или раскладки), у `compare` - отличия; 2 - файл не читается
(не JSON, не XML формы, нет файла, ошибка Chrome); 3 - нужен PNG, а Chrome нет.

| Ответ | Действие |
| --- | --- |
| `check`: `[schema]` | путь в скобках указывает элемент; имя вида или свойства - по `model.md` или `ru`; значение - из перечня `model.md` |
| `[foreign-property]` | свойство другого вида: убрать или сменить вид элемента (`ru <свойство>` покажет, чье оно) |
| `[duplicate-name]` | переименовать один из элементов: имена уникальны по всей форме |
| `[empty-container]`, `[table-no-columns]` | наполнить или удалить группу, закладку, подменю, таблицу |
| `[single-page]` | одна закладка - убрать панель закладок, содержимое поднять на уровень выше |
| `[current-page]` | `currentPage` - `name` существующей закладки этой панели |
| `[too-many-items]` | своя форма: разнести по закладкам или в свертываемую группу; импортированная - оставить |
| `[group-depth]` | убрать лишние группы-обертки без отображения |
| `[data-path]` | путь не проходится по `attributes` и `types`: исправить путь или добавить реквизит в `attributes`; колонка - только внутри пути своей таблицы |
| `[style-color]` | цвет `style:<Имя>` без значения в `styles`: элемент стиля платформы - имя из `schema/colors-1c.json` (`style:FormTextColor`), своей конфигурации - добавить `"Имя": "#RRGGBB"` в `styles`; без значения элемент рисуется без цвета |
| `render`: «рисую после исправления» | модель не нарисована (схема или повтор имени): `check`, исправить, повторить |
| `render`: «рисую как есть» | нарисовано; замечания правил разобрать по строкам выше |
| `«…» не помещается [layout]` | своя форма: короче заголовок, `titleHeight: 2` или шире поле; импортированная - так в XML, сказать пользователю |

| `в «Еще» ушли: … [layout]` | важная команда в «Еще» - короче текст, `representation: Picture` у частых кнопок или шире форма; для импортированной - как в 1С при этой ширине |
| `картинка … нарисована заглушкой [layout]` | своя форма: имя `StdPicture.*` из платформы или без картинки; импортированная - своя выгрузка картинок `--std-pictures` |

| код 2 «не XML» / «не форма 1С» | не тот файл: нужен `Form.form` или `Ext/Form.xml` самой формы |

| импорт: `Не на своем месте: …` | элемент в XML там, где инструмент его не ждет; заглушка - как выше |

## Что отдать пользователю

Фрагмент ТЗ в Markdown (в ответе или файлом рядом с моделью, если пользователь ведет ТЗ
файлом):

```markdown
### Форма «<заголовок>»

![<заголовок>](out/<имя>.png)

<таблица из formmockup.py table>

Интерактивный макет: out/<имя>.html
```

- Картинки - все PNG из вывода `render` (закладки - отдельными рисунками с подписью).
- Таблица - вывод `table` без правки; колонку «Комментарий» (из `note` модели) агент не
  заполняет от себя. С примечаниями в таблице есть колонка «№» - номер как на снимке
  `<имя>__примечания.png`: отдать этот снимок рядом с таблицей.
- Элементы с `note: "предложение"` перечислить отдельной строкой: «предложено без задачи:
  …» - пользователь решает.
- Что макет не показывает (видимость от кода, условное оформление), - одной строкой, если
  форма импортирована.

name: push-to-template
description: Отправить правки переносимых файлов (docs со стандартами BSL, скиллы, шаблоны спек) из текущего проекта обратно в репозиторий-шаблон edt1c-ai-template — с обратной генерализацией: префикс проекта заменяется на prj_, имя EDT-проекта на плейсхолдер, проектная специфика вычищается. Использовать когда пользователь просит поднять правку в шаблон, вернуть изменения в шаблон, поделиться доработкой стандарта. Обратная операция к sync-template. В самом репозитории шаблона не применять.
---

Подними правки переносимых файлов из текущего проекта в репозиторий-шаблон. Если в `$ARGUMENTS` переданы пути — ограничься ими, иначе проверяй весь переносимый набор.

Правки стандартов рождаются в проекте — там реальный код. Без обратного подъёма шаблон отстаёт, а проекты расходятся между собой. Этот скилл — вторая половина пары к `/sync-template`.

## Шаги

1. **Проверка контекста.** Если текущий репозиторий — сам шаблон (`edt1c-ai-template`), остановиться: подниматься некуда.

2. **Рабочая копия шаблона.** Спроси у пользователя путь к локальному клону шаблона; если его нет — склонируй `git@github.com:vandalsvq/edt1c-ai-template.git` во временный каталог. В клоне: `git fetch origin && git switch -c sync/<кратко-о-правке> origin/main`. Работать **только** в этом клоне, не в каталоге проекта.

3. **Переносимый набор** (только эти пути, остальное не поднимать):
   - `docs/bsl-*.md`, `docs/bsp-common-modules.md`, `docs/mdo-integrity.md`, `docs/testability.md`
   - `docs/codepilot1c-reference.md`, `docs/model-selection.md`, `docs/bsl-check-setup.md`, `docs/yaxunit-bootstrap.md`
   - `docs/skd-mxl-toolkit.md`
   - `.claude/skills/` — **кроме** `skd-*` и `mxl-*`
   - `licenses/cc-1c-skills-LICENSE`
   - `specs/_template/`, `specs/README.md`, `planning/README.md`
   - `.gitattributes`, `.mcp.json.example`

   **Не поднимать никогда:** `CLAUDE.md`, `README.md`, `.claude/settings*`, `.gitignore`, `planning/examples/`, `specs/<prefix>-*/`, `docs/project-init.md`, любые проектные docs (справочники модулей проекта, памятки стенда) — это проектное или одноразовое. Навыки `skd-*` и `mxl-*` — вендоренная копия стороннего проекта: правки в них поднимаются не в шаблон, а в апстрим [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills); в шаблон возвращается только адаптация под EDT (шапка `SKILL.md`, `docs/skd-mxl-toolkit.md`).

4. **Обратная генерализация.** Прочитай из `CLAUDE.md` проекта префикс объектов и имя EDT-проекта. Перед сравнением и копированием в каждом файле замени:
   - префикс проекта → `prj_`
   - имя EDT-проекта → `<Каталог.Имя>`, имя хост-проекта → `<ХостПроект>`

   Это механика. Дальше — **смысловая чистка, её делать глазами, а не sed**:
   - имена объектов проекта в примерах (`prj_Исполнитель`, `prj_Схема`) — оставлять можно, если пример читается без знания проекта; иначе заменить на нейтральные;
   - номера и URL задач (`#123`, ссылки на issue) — убрать или заменить на «проверено ДД.ММ.ГГГГ»;
   - абсолютные пути стенда (`/Users/...`, `C:\...`), имена баз, порты, версии плагинов конкретной машины — на плейсхолдеры;
   - имена ролей, подсистем, XDTO-пакетов проекта — на плейсхолдеры или нейтральные примеры;
   - названия продукта и компании — убрать.

5. **Diff по каждому файлу.** Сравни генерализованную версию из проекта с версией в шаблоне. Правки текут в обе стороны, поэтому:
   - изменения, которых нет в шаблоне, — кандидаты на подъём;
   - изменения, которые в шаблоне уже есть в лучшем виде, — **не затирать**; показать расхождение и спросить, в какую сторону синхронизировать;
   - если файл в шаблоне ушёл вперёд по другим разделам — поднимать **точечно** (только свои правки), а не заменять файл целиком.

   Покажи пользователю сводку: файл → что поднимается → что в шаблоне остаётся своим. Спроси подтверждение по каждому файлу с неочевидным решением.

6. **Коммит в клоне шаблона.** Применить одобренное, показать `git diff --stat`, закоммитить одним коммитом с описанием сути правки на русском (например, `поднять из проекта: правило о выравнивании однотипных блоков`). **Без `Co-Authored-By`.**

7. **Push и PR — только по явной просьбе.** По умолчанию остановиться на локальном коммите в ветке `sync/<...>` и сообщить пользователю путь к клону и имя ветки.

8. **После подъёма** напомнить: чтобы правка вернулась в другие проекты, в них запускается `/sync-template`.

## Usage examples

| Command | What it does |
|---|---|
| `/push-to-template` | Сверить весь переносимый набор и поднять правки в шаблон |
| `/push-to-template docs/bsl-anti-patterns.md` | Поднять только один файл |
| `/push-to-template .claude/skills/` | Поднять только скиллы |
